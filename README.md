# 肥鱼抓兔-改（fat-fish-grabber）

> Chrome 扩展（Manifest V3）：网页图片抓取、多页图站批量采集、聚合搜索、imgbb 相册管理与标星。
> 当前版本 **v0.2.42** ｜ 技术栈：TypeScript + esbuild（无框架、无远程代码）

---

## 一、这是什么

一个本地运行的图片抓取工具。核心能力：

- **抓当前网页的图片**：解析 → 网格预览 → 尺寸筛选/去重 → 勾选 → 下载或打包为 ZIP
- **多页图站批量采集**：对 11 个已适配的图站，一次抓完一个相册的全部子页（含原图）
- **聚合搜索**：一个关键词，同时在多个站点搜索（站内接口 / Google 站内搜索两条通道）
- **imgbb 管理**：相册解析、关注链扩散、标签云、手动星级评定
- **日志面板**：所有关键路径都有日志，问题定位靠它（见第六节）

## 二、安装与加载

`dist/` **不入版本库**（避免构建产物污染 diff），所以先构建再加载：

```bash
npm install          # 安装依赖
npm run build        # 构建到 dist/，输出当前版本号
```

然后在 Chrome 中加载：

1. 打开 `chrome://extensions`
2. 右上角开启 **开发者模式**
3. 点 **加载已解压的扩展程序** → 选择本项目的 **`dist/`** 目录
4. 在任意网页点插件图标即可打开抓取页

> 更新代码后：先 `npm run build`，再到 `chrome://extensions` 点该扩展的**刷新按钮**。
> 改了 `background` 相关代码时**必须刷新扩展**，否则旧逻辑仍在运行（这是最常见的"改了没生效"原因）。

### 权限说明

| 权限 | 用途 |
|------|------|
| `storage` | 保存设置（下载并发、翻译开关、去重/小图过滤状态等） |
| `downloads` | 保存图片与打包文件 |
| `activeTab` / `scripting` | 在页面上下文中提取图片地址 |
| `<all_urls>`（**按需申请**） | 抓取与搜索时访问目标站点；首次使用某功能时弹窗询问 |

## 三、界面总览（5 个页签）

| 页签 | 用途 |
|------|------|
| **抓取** | 解析当前页图片，网格预览、尺寸筛选、去重、小图过滤、全选/反选、下载选中、打包下载 |
| **日志** | 运行日志面板（可清空/复制/导出）—— 反馈问题时请从这里复制 |
| **imgbb** | imgbb 相册/用户解析、关注链扩散检索、标签云、批量星级评定 |
| **多页图站** | 10 个图站的全子页抓取、批量抓取推荐/其他链接、**聚合搜索**、**站内列表浏览** |
| **站点适配模板** | 新站适配用的模板与探测入口 |

另有 **标星悬浮窗**：在 imgbb 页面按需授权后注入，用于快速评星。

## 四、快速上手

### 场景 A：抓当前网页的图片

1. 在目标网页点插件图标 → 停在「抓取」页签
2. 图片自动解析并铺入网格；用工具栏做尺寸筛选、去重、小图过滤
3. 勾选想要的图 → **下载选中**（逐张）或 **打包下载**（ZIP）

### 场景 B：抓一个多页图站相册的全部子页

1. 打开该相册页 → 点插件图标 → 切到「**多页图站**」页签
2. URL 输入框会**自动填入**当前页地址（该站已被适配时）
3. 点「**抓取全部子页**」→ 自动翻页抓取全部原图
4. 抓完后在网格里 **下载选中** 或 **打包下载**

> 站点列表与各自特性见 [`设计文档/站点适配总览.md`](设计文档/站点适配总览.md)。

### 场景 C：一次搜多个站

1. 「多页图站」→「**聚合搜索**」子页签
2. 输入关键词，勾选站点（分「站内搜索」与「Google 通道」两组）
3. 结果以卡片网格呈现，点卡片可打开相册页

> **Google 通道有严格限频**（见第五节），密集搜索会触发冷却，请优先用站内搜索与列表浏览。

## 五、已知限制（重要）

| 限制 | 说明 |
|------|------|
| **8se.me 的打包与缩略图不可用** | 该站图床的跨域策略（CORS）导致「读取图片字节」的三条通道全部失败。**请用「下载选中」**（走浏览器原生下载，实测可用），不要用打包 |
| **Google 通道限频** | 相邻请求至少 4 秒、单轮最多 8 次页面请求、被拒后冷却 15 分钟。这是为规避 Google 反爬而设的硬约束，**不要尝试绕过** |
| **jrants 走 Google 搜索** | 该站站内搜索曾被反爬拒绝，因此改用 Google 站内搜索；相册抓取页间有 2 秒节流 |
| **rrwsh 域名已被他人站占用** | 该域现为视频站，已取消默认勾选，站点列表中仍可手动选择 |
| **部分图床需二次取字节** | 图片在扩展页加载失败时，会经源页面注入取字节——表现为先显示「兜底加载中…」再出图，比普通站点慢 |
| **小图过滤默认开启** | 剔除小于 100×100 的图；多页图站的尺寸是图片加载后才补齐的，因此该过滤对「已显示的小图」不追溯 |
| **打包大相册耗时较长** | ZIP 在本地生成，数百张图需要等待；期间请勿关闭抓取页 |

## 六、遇到问题怎么办（问题定位流程）

本项目的排障方式固定为「**实测 + 日志**」，不靠猜：

1. 打开插件 →「**日志**」页签 → 复现问题 → 复制日志
2. 把日志发给维护者（或自己对照日志中的 `[模块] 消息 { 字段 }` 定位）
3. 关键日志字段速查：

| 日志出现 | 含义 |
|----------|------|
| `启用顺序翻页（分页总数不可测）` | 该站总页数无法预先得知，按上限逐页抓、遇空页/重复页停止 |
| `第一页地址抓取失败，回退基址重试` | 该站第 1 页地址形态与预期不同（已自动兼容） |
| `图片兜底取字节成功（改用 blob 显示）` | 扩展页加载失败，已改由后台取字节显示 |
| `图片加载失败（重试与兜底均失败）` | 该图片三条通道都取不到（多见于反爬图床） |
| `HTTP 429 被限流，等待 2500ms 后重试` | 站点限流，插件已自动退避 |
| 版本徽标 `vX.Y.Z · 时间戳` | 确认当前实际运行的构建（右下角），排除"改了没生效" |

## 七、项目结构

```
src/
  background/   后台 Service Worker：会话、消息路由、抓取编排、Google 通道、下载管理
  content/      内容脚本：页面图片扫描、imgbb 标星悬浮窗
  grabber/      抓取页 UI：5 个页签视图、图片网格组件、滚轮转发
  lib/          共享库：消息协议、存储 schema、下载队列、日志、imgbb/站点专用解析
  sites/         图站引擎（FP-018 核心）
    schema.ts      站点定义的类型（纯数据契约）
    engine.ts      定义 → 运行期对象（URL 构造、容器提取、图片解析）
    parsers.ts     链接/图片解析器注册表
    registry.ts    站点注册与匹配
    defs/*.ts      每个站点一份定义（新增站点 = 新增一个文件）
  assets/       图标等静态资源

scripts/build.mjs        esbuild 多入口打包 + 静态资源复制
scripts/bump-version.mjs 版本递增（同步 manifest.json / package.json）

设计文档/                开发记录（见下节）
dist/                    构建产物（Chrome 加载此目录；不入库）
归档/                    已废弃功能的代码与说明（保留历史）
```

## 九、开发与构建

```bash
npm run dev         # 开发构建（watch，改代码自动重建）
npm run build       # 生产构建（输出当前版本）
npm run typecheck   # 类型检查
npm run bump        # 版本 +1（同步 manifest.json 与 package.json）
```

**约定**：

- 代码与工程文件用英文命名（铁律 2）
- 每次改动都要写变更日志（`设计文档/变更日志/YYYY-MM-DD-NNN-简述.md`）
- 新增站点只需在 `src/sites/defs/` 加一个定义文件并在 `defs/index.ts` 注册，无需改 UI
- 修改模块前先看 [`模块边界.md`](设计文档/模块边界.md)：标 **FROZEN** 的模块需明确解冻才能改
- 版本号规则：`v0.2.N`，每次功能更新 `npm run bump`（Chrome 版本号禁止前导零）
