## 二、各站要点与已知限制

### buondua（唯一默认勾选）
- 站内搜索：`/?search={q}`，分页为**偏移量** `&start=20,40,…`（引擎 `pageStep: 20`，`pageBase: 0`）
- 图站引擎的"基准站点"，多数解析器与容错机制以它为原型

### rrwsh
- **域名已被他人视频站占用**（现为"豆豆"视频站），已取消默认勾选；站点列表中仍可手动选
- 定义了三个镜像域（rrwsh.uuss.uk / 4khd.com / iftye.uuss.uk）

### hitxhot / kaizty / phimvuspot / ilovexs / pixibb / jrants
- 走 **Google 站内搜索**通道（`site:{主域}`），受 Google 限频约束（见第四节）
- **hitxhot**：后台 fetch 响应较慢（实测 >20s），抓取超时设为 40s
- **kaizty**：图床为 WordPress Photon（`i0.wp.com`），**突发并发会被限流** → 缩略图采用「按需加载 + 错峰 + 失败重试 + blob 兜底 + 图床熔断」五级容错
- **phimvuspot**：图床 `wp.com` / `thismore.fun`，`imageQueryFix` 把 `w=640` 放大到 `1920`
- **ilovexs**：容器是 **`<section class="image-gallery">`**（不是 div —— 2026-10-11 修复：此前定义写成 `div`，导致抓取恒为 0 张）
- **pixibb**：站内搜索为 WP 标准 `?s=` + `/page/N/`；命名规则 `pixibb`（`folderNameRule`）

### jrants
- **相册页无分页**（实测：单页给全部图片），但**列表页**分页为 `/page/N`（无尾斜杠）
- 站内搜索曾被反爬拒绝，改走 Google；相册抓取**页间 2 秒节流**
- 命名规则 `jrants`（剥离站名「青年美圖」，简繁兼容）

### knitbid
- 部署在 **`xx.` 子域**，`primary` 必须写 `xx.knit.bid`（搜索 URL 由 primary 生成）
- 图片为 **root-relative 路径**（`/static/images/...`）
- **分页总数不可测**（分页链接不在 `<a>` 中）→ 启用 `followPagesUntilEmpty` 顺序翻页
- **实测触发过站点 429** → 页间 1.2 秒节流 + 首屏复用（不重复请求第 1 页）
- 列表浏览：分类页 `/ja/type/N/`，分页 `pageKind: path-slash`

### se8（最"硬"的一个站）
- 有**两种等价 URL 入口**：`/photo/id-xxx.html`（无斜杠）与 `/photo/id-xxx/2.html` → 引擎统一规范化为 `/photo/id-xxx/`
- **正文图用 CSS `background-image` 渲染**，`<img>` 里只有站点 logo → 依赖引擎的 `style url(...)` 扫描
- 缩略图 `…/00019_600x0.webp` → 原图 `…/00019.jpg`（`imageThumbFix`）
- 推荐位在 `upload.xchina.io` / `xchina.click` → 用 `imageOnlyHosts: ['img.xchina.io']` 排除
- **报告与打包不可用**：图床对三条取字节通道全拒（扩展页 img 被拒 / 页面内 fetch 被 **CORS** 拦 / 后台 fetch 403）
  → **请用「下载选中」**（`chrome.downloads.download` 为浏览器一级请求，不受 CORS 且带 Cookie，实测可用）
- 列表浏览未配；站内搜索：`/search.html?keyword={q}`，分页 `&page=N`（页码式，`pageBase: 1`）

### jliji（聚丽集，与 8se.me 同源内容）
- 相册 `/set/{id}`，**单页无分页**（`?lang=zh` 只是语言参数，可省略）
- 图床 `cdn.jliji.com/galleries/8se/{hash}/…`
- **缩略图在 `<img src>`（`…/thumbs/N.webp`），原图在 `<img data-full>`** → 用 `imageAttr: 'data-full'` 取原图
- 正文容器 `div.gallery-grid`；标题 `{相册名} - {模特} - 聚丽集`（剥站名）
- `primary` 必须是 **`www.jliji.com`**（实际入口），否则搜索 URL 会指向裸域
- 站内搜索：`/images/search?q={q}`（无分页）

### ~~xiuzhai5（秀宅，XiuRen 秀人网系）~~ 已废弃（2026-10-15）

该站**大部分链接会跳转到付费**，用户决定放弃适配；定义已归档至 `归档/xiuzhai5-2026-10-15-废弃归档/`。

原适配要点（仅存档参考）：相册 `/{id}` + `?page=N`（7 页 × 每页正文 20 张）、正文容器 `div.article-fulltext`（与 buondua 同模板）、图床 `img.xiuzhai5.com`、懒加载 `data-src`。

> **注意**：该站适配过程中发现的「懒加载 `data-src` 支持 + 占位图过滤」（v0.2.46，见坑清单第 13 条）是**通用能力，已保留在引擎中**，不随站点废弃而回滚。

### xchina（小黄书 xChina，与 se8.me / jliji.com 同源）
- 相册 `/photo/{id}`（第 1 页）与 `/photo/{id}/{N}`（路径式）；**总页数写在标题**：`潼潼 (2/34)`
- 容器用 Tailwind 类名（长且易变）→ **整页容器 + `imageOnlyHosts: ['img.xchina.io']`**
- 图床 `img.xchina.io/photos/{id}/000NN.jpg`；正文渲染 `…_600x0.webp` → `imageThumbFix` 还原原图
- 广告位背景图（`*.bkcdn.net`，ExoClick）由图床白名单排除
- ⚠️ **取图限制同 se8.me**：图床对服务端 403 且页面内 fetch 受 CORS 限制 → 网格缩略图与打包不可用，**请用「下载选中」**

## 三、引擎能力速查（写定义时可用的字段）

`src/sites/schema.ts` 是契约，以下为常用项：

| 字段 | 取值 | 说明 |
|------|------|------|
| `container` | `{ tag, className }` | `className` 留空 = 匹配该标签任意出现（配 `imageOnlyHosts` 可做整页容器） |
| `pagination.kind` | `query` / `path` / `path-from-2` / `path-slash-from-2` / `page-path-slash` / `html-from-1` / `html-from-2` / `html-auto` / `single` | URL 形态 |
| `baseUrl.stripPagePath` | `none` / `suffix` / `trailing-slash` / `page-segment` / `html` | 从相册 URL 提取基址（`html` 会把 `/N.html` 与 `/xxx.html` 统一为目录） |
| `titleStrip` | `RegexSpec[]` | 按序 replace；**引擎会先解码 HTML 实体**（`&amp;` → `&`） |
| `search` | `query`（可配 `path`/`param`/`pageParam`/`pageStep`/`pageBase`）/ `path-template` / `wp-query-path-page` / `google-sitesearch` | 搜索 URL 构造 |
| `searchAlbumPath` / `searchAlbumPattern` | 字符串 / 正则 | 搜索结果只保留相册页（两者同时配置为「且」） |
| `imageHosts` | `string[]` | **仅**用于「无扩展名图片」的 hostname 白名单 |
| `imageOnlyHosts` | `string[]` | **只保留**这些图床的图（用于正文图床与站点/推荐位不同的站） |
| `imageQueryFix` | `{ param, value }[]` | 改写 query 参数（如把 `w=640` 放大到 1920） |
| `imageThumbFix` | `{ source, flags?, replace }` | 缩略图 → 原图（正则替换，如 `_600x0.webp` → `.jpg`） |
| `throttle` | `{ fromPage, delayMs }` | 页间节流（**相册顺序翻页与站内搜索共用**） |
| `followPagesUntilEmpty` | `boolean` | 分页总数不可测时顺序翻页（上限 40 页，遇连续 3 页无新图停止） |
| `listPages` | `{ label, path, pageKind?, param?, albumPath? }[]` | 站内列表浏览（`pageKind`: `query` / `path` / `path-slash`） |
| `folderNameRule` / `imageCountRule` / `linkParser` / `scan` | 注册表键名 | 视图侧路由，禁止在代码里判断 `site.id` |

## 四、Google 通道限频纪律（硬约束）

| 限制 | 值 |
|------|-----|
| 相邻 Google 页面请求最小间隔 | **4 秒**（含跨站） |
| 单轮聚合搜索 Google 请求上限 | **8 次** |
| 被拒后冷却 | **15 分钟**（冷却期内不发任何 Google 请求） |

**不要放宽或绕过这三个值** —— 密集请求会触发 Google 反爬（历史上导致过整轮搜索失败）。优先用站内搜索与列表浏览。

## 五、适配新站的流程

1. **探测**：打开目标相册 → 插件 →「多页图站」→ 粘贴 URL → 点「**探测结构**」
   输出包含：标题、og:image、**按图床分组**（数量 + 样本 + 代表图向上 6 层的 `tag.class` 链）、
   **疑似分页链接**（任意形态）、`img` 上的 `src`/`data-*` 属性名、内联 `background-image`、`iframe`
   > 探测会先在后台标签页**滚动到底**以触发懒加载，因此多等 2 秒是正常的。
2. **写定义**：新建 `src/sites/defs/<id>.ts`（纯数据），按第三节字段填。
   - 容器取「图床分组」里正文图床那组的**父级链**中最贴近图片的一层
   - 若正文图床与站点自身不同域，优先考虑 `imageOnlyHosts` + 宽容器
3. **离线验证**（强烈建议，能提前抓出大部分坑）：
   编译 `src/sites/registry.ts` + `parsers.ts`，用**真实 HTML** 跑 `parseGalleryImages` /
   `pageUrl` / `cleanTitle`，核对张数与 URL 是否符合预期
4. **注册**：`defs/index.ts` 加 import 与数组项；在 `src/grabber/view-buondua.ts` 把它加入
   站内组（`bd-search-sites-site`）或 Google 组（`googleGroupIds`）——**两处必须一致**，
   否则会渲染出无定义的站点项
5. **实测**：构建 → 刷新扩展 → 从**该站页面**打开插件 → 抓取 → 看日志 → 下载验证

## 六、适配路上踩过的通用坑（按发现顺序）

| # | 坑 | 现象 | 修复版本 |
|---|----|------|----------|
| 1 | 图片是 **root-relative 路径** | 解析恒为 0 张（静默） | v0.2.22 支持相对路径 |
| 2 | **正文图用 CSS `background-image`** | `<img>` 里只有 logo，解析 0 张 | v0.2.33 扫描 `style="…url(…)"` |
| 3 | **容器不是 `<div>`** | 深度匹配只数 `div` → 截取到 HTML 末尾，混入推荐图 | v0.2.32 按容器实际标签匹配 |
| 4 | **「尾部数字 = 分页」误杀相册 ID** | ID 结尾的相册 URL 被排除，搜索结果 0 条 | v0.2.23 配了精确规则时跳过该启发式 |
| 5 | **越界页返回首页内容** | 顺序翻页停不下来，白跑 31 页 | v0.2.26 连续 3 页无新图即停止 |
| 6 | **顺序翻页触发站点 429** | 抓取报 `HTTP 429` | v0.2.24 页间节流 + 退避 + 可读提示 |
| 7 | **首屏抓基址而非第 1 页** | 分页为 `{N}.html` 的站首屏 404 | v0.2.35 / v0.2.38 首屏改用第 1 页 URL 并容错回退 |
| 8 | **同一相册多个 URL 入口** | `/id-xxx.html` 被当成单页 → 只抓到第 1 页 | v0.2.39 统一规范化为目录 |
| 9 | **标题 HTML 实体未解码** | 文件夹名出现 `&amp;` | v0.2.39 清理前先解码实体 |
| 10 | **CORS 阻止读取图片字节** | 页面内 fetch 报 `TypeError: Failed to fetch` | v0.2.41 改用浏览器原生下载（「下载选中」） |
| 11 | **取图失败导致大相册卡死** | 720 张 × 约 4 次失败请求 ≈ 3000 次 | v0.2.40 按图床熔断（连续失败 8 张后快速失败） |
| 12 | **真图不在 `src` 而在 `data-*`** | 只扫 `src` 会抓到缩略图（如 jliji 的 `data-full`） | v0.2.44 新增 `imageAttr` 声明真图属性 |
| 13 | **懒加载 `src=占位图 + data-src=真图`** | 只扫 `src` 会收到占位图并漏掉真图（xiuzhai5） | v0.2.46 扫描加入 `data-src` + 过滤占位图 |
