# 2026-08-14-004 聚合搜索 Google 通道预研

> 预研背景：hitxhot/kaizty 无站内搜索（官方搜索表单即 Google sitesearch）；jrants/pixibb/rrwsh 存在站点搜索限制（限流/懒加载）。
> 用户需求：直接使用 Google 对站点做限定搜索（sitesearch），结果统一呈现。
> 关键环境事实（用户提供）：**使用这些功能时基本都会开启代理**。

## 一、可行性结论（先行版）

**可行，且实现成本低**。核心依据：

| 事实 | 证据 |
|------|------|
| 用户环境 Google 可达 | 用户开代理（本沙箱无代理，curl 直连 Google 000，无法本地复现验证） |
| 扩展 fetch 走用户代理 | 扩展 fetch 使用 Chrome 网络栈 → 跟随系统代理/代理插件 |
| **fetch 已带 cookie** | `buondua-service.ts fetchOnce()` 已用 `credentials: 'include'` + Chrome UA + Referer（第 51-58 行）→ 用户授权 `<all_urls>` 后，Google 请求携带用户 Google cookie，被 sorry 拦截概率大降 |
| 复用现有链路 | searchUrl + parseLinksForSite + enrichSearchItem 均已就位，仅需新增 Google 解析器 |

**最大不确定点**：Google 反爬（sorry 页）在"代理 + 带 cookie"组合下的实际表现——**必须用户环境实测**（这是唯一无法在本沙箱验证的环节）。

## 二、方案设计

### 1. 站点配置（gallery-sites.ts）

| 站点 | searchUrl（Google sitesearch） | 分页 |
|------|-------------------------------|------|
| hitxhot | `https://www.google.com/search?q={q}&sitesearch=www.hitxhot.org` | `&start={N}`（每页 10 条） |
| kaizty | `https://www.google.com/search?q={q}&sitesearch=www.kaizty.com` | 同上 |

- 新增站点字段 `searchMode: 'google'`（区分站内搜索与 Google 通道，供解析路由与 UI 提示）
- Google 域名过滤：解析时仅保留目标域（hitxhot.org/kaizty.com）的相册链接

### 2. Google 结果解析（buondua-service.ts 新增 parseGoogleResults）

基于 Google 网页搜索已知结构（用户环境实测 HTML 后校准）：

| 元素 | 选择器/模式 |
|------|------------|
| 结果链接 | `<a href="/url?q={真实URL}&sa=...">` → URLSearchParams 解码 `q`；现代 Google 有时直接给真实 URL（双模式兼容） |
| 标题 | `<h3 class="LC20lb...">标题</h3>` |
| 域过滤 | 解码后 URL 仅保留目标域（hitxhot `/gallerys/{b64}.html`、kaizty `/photos/{b64}.html`） |
| 封面 | Google 网页搜索无缩略图 → 站点占位图（后续可选 tbm=isch 图片搜索增强，本期范围外） |
| 张数 | 无 → 显示「张数未知」（现有 UI 已支持） |

### 3. 反爬兜底（isBlockedPage 增强）

现有正则缺 Google 特征，需补充：`unusual traffic|sorry/index|recaptcha|为什么会出现这种情况|验证您`。
命中 → 该站报「Google 验证页拦截（反爬），请稍后重试或手动搜索」，不产出垃圾结果。

### 4. UI（view-buondua.ts）

- hitxhot/kaizty 从灰显（disabledNotes）**解除为可选**，默认不勾选（Google 通道请求较慢，用户按需勾选）
- 结果卡片徽标照常显示站点名；封面占位样式已有（no-cover）

### 5. 复用点

- `searchSites` 逐站逐页循环、去重、onSite 增量推送：零改动
- 批量抓取（勾选 → BD_FETCH_ALBUMS）：零改动

## 三、实施步骤（用户确认后执行）

1. `gallery-sites.ts`：hitxhot/kaizty 配置 searchUrl + searchMode
2. `buondua-service.ts`：parseGoogleResults + isBlockedPage 补充 + parseLinksForSite 路由
3. `view-buondua.ts`：解除 hitxhot/kaizty 灰显（默认不勾选）
4. **用户环境抓一次 Google 结果页 HTML 给我**（或我提供调试入口），解析级实测校准
5. 构建交付（版本 bump）+ 用户实测

## 四、风险与对策

| 风险 | 对策 |
|------|------|
| Google sorry 拦截（即使代理+cookie） | 补充检测 → 明确提示；后续迭代可加"自动开 Google 标签手动过验证"降级 |
| Google 结果页结构变化 | 解析双模式容错（/url?q= 与直链）；解析级实测校准 |
| 无封面体验差 | 站点占位图；后续 tbm=isch 封面增强（范围外） |
| 代理模式未覆盖扩展 fetch | 失败提示检查代理模式（系统代理/TUN 模式可覆盖扩展；仅浏览器插件代理也覆盖） |
| Google 限频（sitesearch 请求频繁） | 每站请求间隔 2s（复用 jrants 间隔机制），页数上限 2 页 |

## 五、关联议题（本次预研附带确认）

- **pixibb 懒加载**（每页初始 7 条 vs 渲染 28 条）：后台 fetch 无法绕过；可选"页面降级通道"（自动开搜索页滚动加载 + content script 提取，同 Google 通道交互家族）——**建议后续迭代**，本期不做
- jrants/pixibb/rrwsh 的限流是站点行为，现有间隔机制已缓解

## 六、验证方式（用户实测）

2. 预期：Google 结果（每页约 10 条）统一展示（徽标/标题/占位封面），点卡片打开相册页正常
3. 若提示「Google 验证页拦截」→ 提供当时的 Google 页面截图/日志，评估降级方案
