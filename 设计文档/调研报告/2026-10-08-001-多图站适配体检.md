## 二、P0 确定缺陷（**已于 v0.2.13 修复**，见 `变更日志/2026-10-08-002`）

### P0-1 `google-sitesearch` 的 `site:www.{域名}` 过窄（本次重构引入）✅ 已修 v0.2.13

`src/sites/engine.ts`：

```ts
const siteHost = `www.${primaryHostOf(def)}`          // → www.hitxhot.org
const siteQuery = encodeURIComponent(`${q} site:${siteHost}`)
```

- 影响 **hitxhot / kaizty**（唯二使用 `google-sitesearch` 的定义）：查询被限定在 **www 子域**
- 若相册页位于裸域或其它子域 → **Google 结果为空**（表现为"搜不到"，且不报错）
- 内部不一致：`googleSearchConfig`（Google 全站模式/Google 组）用的是**不带 www** 的 host → 同一站点两条路径查询目标不同
- 历史渊源：旧代码用 `sitesearch=www.hitxhot.org`（该参数语义宽于 `site:` 操作符），FP-022 换成 `site:` 语法时保留了 www 前缀 → 语义被无意收窄

**修复**：改为 `site:${primaryHostOf(def)}`（与 `googleSearchConfig` 一致）。

### P0-2 文件夹名路由仍有 `site.id` 硬编码（违反模块边界第 6 条）✅ 已修 v0.2.13

`src/grabber/view-buondua.ts:43-44`：

```ts
if (site?.id === 'jrants') return extractJrantsFolderName(title)
if (site?.id === 'pixibb') return extractPixibbFolderName(title)
```

- FP-018 阶段 1 已把 service 侧的 id 分支全部收拢到定义字段，但**视图侧漏了这两处**
- 与 `设计文档/模块边界.md` 禁止事项第 6 条（"图站适配禁止在业务代码中出现 `site.id === 'xxx'` 分支"）**直接冲突**
- 后果：将来若新增站点需要专属命名规则，必须改视图代码；且 id 改名会静默失效

**修复**：新增定义字段（如 `folderNameRule: 'jrants' | 'pixibb' | 'default'`），或直接把命名函数注册进解析器注册表（与其他规则一致）。

### P0-3 列表浏览的分页方式无法在界面调整（FP-023 的能力缺口）✅ 已修 v0.2.13

- `listPageUrl` 的分页方式来自 `listPages[0].pageKind`，缺省按站点 `pagination.kind` 派生
- 而列表浏览界面**只提供路径输入框**，没有分页方式选择
- 若派生结果与站点实际不符（很可能，见 P1-1），用户**无法自助修正**，与 FP-023 文档中"路径与页数都可在界面调整，无需等改代码发版"的设计承诺不符

**修复**：界面新增「分页方式」下拉（`?page=N` / `/page/N/` / `/page/N`）。

## 三、P1 改进项

### P1-1 多个站的列表页分页方式存疑

`deriveListPageKind` 的派生规则：`query → 'query'`、`path-slash-from-2 → 'path-slash'`、**其余 → 'path'（`/page/N`）**

| 站点 | 派生结果 | 疑虑 |
|------|---------|------|
| jrants | `/page/N` | jrants 是 WordPress，列表分页标准为 `/page/N/`（带尾斜杠）→ 可能错 |
| cangcuc | `/page/N` | 其站内搜索分页实为 `/page/N/?s=`（带尾斜杠）→ 列表页大概率也是 `/page/N/` |
| pixibb | `/page/N/` | 与站内搜索一致，应正确 |
| hitxhot / kaizty | `?page=N` | 与相册页分页方式一致，待实测 |
| phimvuspot | `?page=N` | 同上 |
| ilovexs | `/page/N` | 该站容器无分页，列表页分页方式未知 |

**建议**：给 jrants、cangcuc 显式配 `listPages`（含 `pageKind: 'path-slash'`），其余待实测后再定。

### P1-2 四个站缺 `searchAlbumPath`，搜索/Google 结果过滤弱

jrants、phimvuspot、ilovexs、cangcuc 未配 `searchAlbumPath` → `cleanGoogleResult` 只按域名过滤 → **结果可能混入分类页/标签页/视频页**。

jrants 尤其明显：相册 URL 形如 `/20260101.html`（根路径下），无法用路径前缀表达。
**建议**：新增可选字段 `searchAlbumPattern`（正则，如 `^/\d{8}\.html$`），与 `searchAlbumPath` 二选一或并用。

### P1-3 站点列表界面显示 `id` 而非定义里的 `label`

`view-buondua.ts:624` 的站点复选框文案直接用 `id`（显示 `ilovexs`），而定义里已提供 `label`（`iLoveXS`）。
`label` / `uiOrder` / `hint` 三个字段目前**定义了但未被任何 UI 消费**（FP-018 阶段 1 只落数据，未改 UI 渲染）。

**建议**：随 FP-018 阶段 1B（UI 由定义派生）一并处理。

### P1-4 `hint` 文案过时

hitxhot / kaizty / pixibb 的 `hint` 仍写「Google 站内搜索（sitesearch）」——`sitesearch` 参数已在 FP-022 废弃并改用 `site:` 语法。
当前 UI 未消费 `hint`，无实际影响；做 P1-3 时应一并更新文案。
