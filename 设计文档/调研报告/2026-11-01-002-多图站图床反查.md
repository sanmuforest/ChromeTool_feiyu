# 调研报告 002（2026-11-01）— 从多图站反查图床及嗅探分析

> 日期：2026-11-01
> 思路：不再直接找"imgbb 式图床"，改为**从项目已适配的多图站出发，反查它们实际使用的图床域名**，再评估这些图床是否具备可复用的浏览/社交结构
> 数据来源：`src/sites/defs/*.ts`（14 个站点定义）+ curl 实测（完整权限网络）
> 关联：`2026-11-01-001-imgbb同构图床站点调研.md`（前一条链路，已终止）

## 一、方法

1. 从 `src/sites/defs/` 取 14 个站的 `endpoints.host` 与 `listPages.path`
2. 抓列表页 → 提取相册链接 → 抓相册页 → 从图片 URL 提取 **host**（图床域名）并统计
3. 对每个图床域名单独抓首页，判断类型（纯图床 / 图站 / CDN / WP）与是否有 `explore / album / following` 结构
4. 验证图片直链是否可匿名下载

**限制**：多数站点在本机网络下不可达（000/403），能拿到实测数据的是 rrwsh(4khd)、pixibb、ilovexs、jliji 四个；其余站的图床来自代码 `imageHosts` 与历史实测记录（标注为"代码/历史"）。

## 四、结论

1. **多图站使用的图床分两类**：
   - **自建/CDN 集群**（buondua、pixibb、jliji、jrants、hitxhot、kaizty、knitbid、se8、xchina、xiuren、misskon）→ 仅存图，无任何用户/相册/关注生态
   - **第三方图床**（ilovexs 的 `reiobox/karubox/fujibox` 集群、`wp.com` Photon、`thismore.fun`）→ 同样**无浏览/社交结构**，首页只有 WP 基础端点
2. **没有任何图床具备「用户主页 + 关注关系」** → 图床**不能作为扩散检索入口**；它们的价值只在「图片直链可下载」（对打包下载有用）
3. **ilovexs 的图床是多域名轮换集群**（reiobox / karubox / fujibox / nekobox / quenbox / rakuda），镜像站内容完全相同 → 适配时**不能只写死一个域名**，需要"图床域名白名单 + 多域名容错"（这正好对应项目 `imageHosts` 机制，但 ilovexs 当前只配了单一域名，需扩展）
4. **pixibb 是自建 WP 多子域矩阵**（hub / sexy / cosplay / pixieugirls / wpmedia001）→ 同站点不同子域承担不同栏目，图片 CDN 有防盗链（403）
5. **reiobox 首页无内容导航**说明它只是"上传-外链"型图床；ilovexs 的相册页才是内容组织者 → **内容组织的价值在站点层，不在图床层**

## 五、对项目的直接建议

| 建议 | 依据 |
|------|------|
| **扩展 `imageHosts` 多域名白名单**：为 ilovexs 增加 `karubox.top / fujibox.top / nekobox.top / quenbox.top / rakuda.my.id` | 实测同一相册 170 张图分布在 6 个域名，单域名会导致部分图片判定/抓取失败 |
| **图床域名失效容错**：`nekobox/rakuda` 已不可达，抓取时应允许"同一图片有镜像域名时降级" | 实测 000 |
| 下载/打包走**图床直链**（已可行，reiobox 200）而非站点页 | 直链无防盗链 |
| **放弃"从图床做扩散检索"** | 所有图床均无用户/关注结构 |
| 若仍要扩散检索，回到站点层（多图站的"模特/分类/相关推荐"），而非图床层 | 图床层无生态 |

### 8.1 代理补测的新发现

1. **se8 与 xchina 共用 `upload.xchina.io` 同一图床**，且 se8 页面直接链接到 `xchina.co` 的 photos/models/videos 等栏目 → **两站属同一运营方**（xchina 系），可视为同一生态的两个入口。
2. **buondua 使用 4 个自建子域做 CDN 轮换**（`i2 / cdn / i / i0.buondua.com`），并夹杂 `2.bp.blogspot.com` 外链（历史遗留的 Google 图床）→ 图片域名是**多域名混布**，单域名白名单思路不适用。
3. **hitxhot / phimvuspot 都走 WordPress Photon（`i0/i1/i2.wp.com`）** → 与 rrwsh 同类（`wp.com`），三站共用同一 CDN 体系。
4. **misskon 用 `kul.misskon.com` 子域 CDN**，与主域混用。
5. **kaizty / xiuren 在代理下依然 000** → 不是网络问题，是站点本身不可用（与 `2026-10-08-001` 体检报告里 cangcuc/rrwsh 的情况类似）。
