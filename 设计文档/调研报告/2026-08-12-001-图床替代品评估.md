# 调研报告 001 — 与 imgbb 相当的图床替代品评估

> 日期：2026-08-12
> 调研方式：curl / 浏览器自动化实测（全部结论基于实际抓取，非猜测）
> 背景：用户询问 postimg（postimg.cc）能否实现插件内 imgbb 适配器（FP-003）的类似功能，实测否定后，进一步调研「结构、功能、可获取性与 imgbb 相当的网站」

## 一、评估标准（imgbb 适配器的 4 大特征）

对照模块边界 FP-003，imgbb 适配器可用性的前提：

1. **用户主页公开可枚举**：`{username}.imgbb.com`，无需登录
2. **相册生态**：`/albums` 列表 + `ibb.co/album/{ID}` 详情，公开可抓
3. **关注体系**：`/following`、`/followers` 公开页（支撑扩散检索 FP-005）
4. **可获取性**：静态 HTML + 结构化数据（`data-object` JSON 含原图 URL），后台 fetch 即可，反爬弱

## 三、关键站点实测细节

### 3.1 postimages（postimg.cc）— 已排除

- postimg.cc 重定向至 postimages.org（同一网站）
- 首页 HTTP 200 静态可抓，但**只有上传功能**，无公开浏览/搜索图库入口
- 图集 URL：`postimg.cc/gallery/{随机hash}`，无用户名成分，hash 无法枚举
- 无 `{username}.postimg.cc` 用户主页子域；无相册列表/关注墙
- 图库仅上传者登录可见或分享链接；「一键下载整个图库」为高级付费功能
- 自动化上传被反爬拦截（服务器返回 0 码）
- 公开 API 需注册 key（免费 1000 次/月），且为上传 API 非浏览 API

### 3.2 freeimage.host（Chevereto 程序）— 最接近 imgbb

**Chevereto 开源图床程序**（自带用户/相册/关注/探索体系），freeimage.host 为其运营实例。

**① 探索页公开可抓 + 分页有效（SSR）**
- `https://freeimage.host/explore` → HTTP 200，单页约 45 图
- `?ajax=1&list=images&sort=date-added-desc&page=2` → 200，返回不同 data-id（分页确认有效）

**② 数据结构与 imgbb 几乎完全同构（探索页 SSR 直接输出）**
```html
<div class="list-item" data-id="CPGiIBS" data-type="image"
     data-object='{"id_encoded":"CPGiIBS",
       "image":{"url":"https://iili.io/CPGiIBS.jpg", "filename":"CPGiIBS.jpg", ...},  ← 原图
       "thumb":{"url":"https://iili.io/CPGiIBS.th.jpg", ...},                        ← 缩略图
       "url_viewer":"https://freeimage.host/i/CPGiIBS",
       "width":"400","height":"400",
       "name":"...","title":"...","display_url":"...","url_short":"...","size_formatted":"..."}'>
```
data-object 顶层字段：`id_encoded / image / thumb / name / title / display_url / extension / filename / height / how_long_ago / size_formatted / url / url_viewer / url_short / width`
- 与 `imgbb-parse.ts` 现有解析器高度一致（差异：无 user 字段，属主需从图片页取）
- 图片 CDN：`iili.io`

**③ 用户主页与关注路由存在**
- `/{username}` → og:type=profile（如 `/test` 标题 "Test (test) — Freeimage.host"）
- `/{username}/albums` → 200
- `/{username}/followers`、`/{username}/following`、`/{username}/liked` → 200

**④ 已验证的局限**
- 用户主页/相册/关注列表的**内容为 JS 动态加载**（HTML 壳 + `data-params` AJAX 端点，如 `list=images&sort=date_desc&page=1`），非纯 SSR——与 imgbb 不同，适配需多一层 AJAX 请求
- 匿名上传（Guest）占主导，关注网络数据价值可能不如 imgbb
- `/json` 端点（Chevereto 标准）实测 500，需用 `?ajax=1` 方式
- Chevereto 实例依赖站长运营，有倒闭/改版风险

### 3.3 lensdump.com（Chevereto 程序）— 同程序但实例不理想

- 用户主页 `/guest`、`/demo` 均 200（og:type=profile）
- 但 `/explore`、`/latest`、`/discover` 均 404（关闭公开探索）
- 公开内容极少（预置测试用户空相册），无搜索索引

## 四、与 imgbb 的差异汇总（影响适配工作量）

| 差异点 | imgbb | freeimage.host |
|--------|-------|----------------|
| 用户主页图片列表 | 纯 SSR（content 注入直接抓） | JS 动态加载（需调用 AJAX 列表端点） |
| 公开探索页 | 无（只走用户网络） | 有（SSR + 分页），反而多一个数据入口 |
| 内容生态 | 用户制为主 | 匿名上传（Guest）占主导 |
| 站点稳定性 | 老牌稳定 | 依赖站长运营 |
| data-object | 含 user 字段 | 无 user 字段（属主从图片页取） |

## 五、结论与建议

- **结论**：与 imgbb 在「结构、功能、可获取性」上最相当的是 **freeimage.host（Chevereto 程序实例）**；imgur/flickr 被墙不可用；postimages/pixhost/imagebam/imgpile 生态不相当
- **建议**：如需落地，可立项 **FP-007-freeimage适配**（功能规划书流程），定位比 imgbb 适配器小一号：
  - 优先：探索页抓取（已验证 SSR 可解析）+ 图片页原图提取 → 复用现有下载队列/打包逻辑
  - 次选：用户主页 AJAX 端点适配、关注墙
  - 现有 `imgbb-parse.ts` 的 data-object 解析可抽取共用（涉及 FROZEN 模块，需先走模块边界变更流程）

## 六、遗留待验证（如立项后补测）

1. 用户主页 AJAX 列表端点的准确请求格式（从页面 `data-params` 构造 + 带 userid）
2. 关注列表页是否有公开内容（实测用户为空状态）
3. 图片页属主提取（Guest 匿名 vs 注册用户）
4. 反爬稳定性（长时间/高频抓取是否触发限流）
5. 站点长期运营稳定性
