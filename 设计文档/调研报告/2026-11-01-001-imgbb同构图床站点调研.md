# 调研报告 001（2026-11-01）— 与 imgbb 同构的开放图床/图站调研

> 日期：2026-11-01
> 调研方式：**网络搜索 API 检索 + 官方文档/第三方工具说明核实**（本机沙箱无出网，curl 实测 baidu/github 均返回 000）
> 前置报告：`2026-08-12-001-图床替代品评估.md`（已有 9 站实测矩阵）、`2026-10-08-001-多图站适配体检.md`（现行 `src/sites` 体系）
> 目标：找「网站结构类似 imgbb、开放、可做类似扩散检索与相册下载」的站

## 一、imgbb 适配器的 4 大结构特征（判定基准）

对照 `设计文档/模块边界.md` imgbb 专规：

1. **用户主页公开可枚举**：`https://{username}.imgbb.com`，无需登录
2. **相册生态**：`/albums` 列表（分页）+ `ibb.co/album/{ID}` 详情
3. **关注体系**：`/following`、`/followers` 公开页（支撑 FP-005 扩散检索的图边）
4. **结构化数据**：`data-object` JSON 内 `image.url` 即原图，后台 fetch 即可解析

> 关键取舍：**「关注关系」是扩散检索的前提**，只有具备它的站才可能替代 imgbb 的扩散能力；只有相册没有关注的站，只能提供「用户级批量下载」。

| `imgstore.io` | 200 | 无社交信息 | 2024 年建站 |
| `imgstock.io` | 200 | 无社交信息 | 2025 年建站 |

#### 2.1.1 2026-11-01 实测结果（对原假设的重要修正）

用 curl（完整权限下；受限模式下外网请求全被拦截，返回 000）逐个实例实测：

| 实例 | 探测路径 | 结果 | 判定 |
|------|---------|------|------|
| **freeimage.host** | `/explore/recent` | 200，**`data-object`=36 / 页**，`list-item`=262 | ✅ **开放可用** |
| freeimage.host | `/test`（用户页）、`/test/albums`、`/test/following`、`/test/followers` | 全部 200，但 `data-object`=0、`data-params`=15~25 | ⚠️ 路由存在，**内容 AJAX/JS 加载** |
| freeimage.host | `/i/{id}`（图片页） | 200，含 `user-link` / `uploader` 关键词 | ✅ 属主可提取 |
| imgstore.io | `/`、`/explore` | 200 但**重定向到 `/login`** | ❌ 需登录，不开放 |
| imgstock.io | `/explore` | 200 → `/login` | ❌ 需登录 |
| fotoku.host | `/` | 200（72KB） | ⚠️ 仅首页可达 |
| fotoku.host | `/explore`、`/explore/recent`、`/test` | **全部 404** | ❌ 公开浏览已关闭 |

**结论修正**：原「4 个实例可复用」不成立 —— **仅 freeimage.host 一个开放可用**；imgstore/imgstock 需登录，fotoku 关闭公开浏览。多域名策略暂不可行。

结构事实（来自前置报告 001 的实测 + 上述实测）：

- 探索页 `https://{host}/explore` 为 **SSR**，约 45 图/页，`?ajax=1&list=images&sort=date-added-desc&page=N` 分页有效
- `data-object` JSON 顶层字段与 imgbb 高度同构：`id_encoded / image / thumb / name / title / display_url / extension / filename / height / width / url_viewer / url_short / url`
- 图片 CDN：`iili.io`
- 用户路由：`/{user}`、`/{user}/albums`、`/{user}/followers`、`/{user}/following`、`/{user}/liked`（均 200，**内容为 JS 动态加载**，需 AJAX 端点）
- 差异：`data-object` **无 user 字段**（属主需从图片页取）；匿名上传（Guest）占主导

**价值**：一个解析器 + 多域名配置即可覆盖 4 个活跃实例；`归档/freeimage-2026-08-13-废弃归档/` 内有完整实现可复用。

### 2.2 Pixelfed 联邦实例群（扩散检索最完整）

数据来源：[Pixelfed API 文档 — Accounts](https://developers.pixelfed.org/api/accounts)

已核实的标准端点（Mastodon 兼容）：

| 端点 | 用途 |
|------|------|
| `GET /api/v1/accounts/{id}/statuses` | 用户全部帖子（图片/视频，分页） |
| `GET /api/v1/accounts/{id}/followers` | 粉丝列表 |
| `GET /api/v1/accounts/{id}/following` | 关注列表 |
| `GET /api/v1/collections` | 相册（Pixelfed 独有） |
| `GET /api/v1/discover/*` | 发现页 |

账号对象含 `followers_count / following_count / statuses_count / note / url`。
用户主页 URL：`https://{instance}/{username}`。

**价值**：唯一「关注关系可编程枚举、无需解析 HTML」的形态，可直接喂给现有扩散引擎（BFS + 入度统计）。

限制：内容以摄影/生活为主，成人内容取决于实例政策；部分端点可能需 access token（待实测）；多实例需要「实例列表」这一新配置概念（现有 `src/sites` 是单域名模型）。

### 6.3 freeimage.host `data-object` 样本（URL 解码后）

```json
{"id_encoded":"nglPcKP",
 "image":{"filename":"nglPcKP.png","name":"nglPcKP","mime":"image/png","extension":"png",
          "url":"https://iili.io/nglPcKP.png","size":"176314"},
 "medium":{"filename":"nglPcKP.md.png","url":"https://iili.io/nglPcKP.md.png"},
 "thumb":{"filename":"nglPcKP.th.png","url":"https://iili.io/nglPcKP.th.png"}}
```

要点：
1. **`data-object` 的值是 URL 编码（`%7B%22...`）的 JSON**，解析前必须 `decodeURIComponent`（imgbb 为未编码 JSON，这是两者关键差异）
2. `image.url` 即原图（CDN `iili.io`）→ 与 imgbb「原图在 `image.url`」的约定一致
3. 无 `user` 字段 → 属主需从图片页 `/i/{id}` 提取（已确认该页有 `user-link`/`uploader`）

#### 6.7.1 e621.net —— 本次最大发现（可编程 tag 扩散 + 相册下载）

三个公开端点实测（**无需 token、无需登录**）：

| 端点 | 结果 | 内容 |
|------|------|------|
| `/posts.json?limit=2` | **200 JSON** | 每个 post 含 `file.url`（**原图直链** `static1.e621.net/data/...png`）、`preview.url`、`tags.general[]`（如 `blonde_hair` / `alternative_fashion`） |
| `/tags.json?search[name_matches]=*&limit=3` | **200 JSON-array** | 标签体系可查询 |
| `/pools.json?limit=3` | **200 JSON-array** | **pool（相册）** 可枚举 |

**为什么重要**：
- 结构上覆盖 imgbb「用户 + 相册 + 关系」中的**「相册（pool）+ 关系（共享 tag）」**，且是**纯 JSON API**（比 HTML 解析稳定）
- **扩散可用 tag 替代关注**：`posts.json?tags=xxx` 可沿标签扩散，与项目已有「标签云」基础设施天然契合
- 原图直链可直接下载，**无 referer 限制**（不同于 imgbb 的 180 降级问题）

**限制**：内容为兽人/动漫向图库（furry/anime），与现有 9 个真人图站的内容生态不同；是否接入取决于内容定位。
