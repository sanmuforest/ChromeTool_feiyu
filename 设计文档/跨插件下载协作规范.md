# 跨插件下载协作规范（自建 Chrome 插件强制遵守）

> 目的：保证**同一开发者创建的所有插件**之间不互相干扰下载路径与命名。
> 机制根源：`chrome.downloads.onDeterminingFilename` 事件可改写任何下载的最终文件名——
> 若多个插件无差别接管，路径/命名会被后响应者覆盖（无法创建预期文件夹）。
> 本规范强制所有自建插件遵守，从机制上杜绝该冲突。

## 一、核心原则

**谁发起下载，谁负责命名；绝不无差别接管所有下载。**

## 二、三条强制约定

### 约定 1：默认不监听 onDeterminingFilename

- 命名一律通过 `chrome.downloads.download({ url, filename })` 指定（filename 支持相对默认下载目录的子文件夹，Chrome 自动创建）
- 不监听 `onDeterminingFilename` 的插件**天然不干扰**其他插件

### 约定 2：必须监听时，用 downloadId 白名单只接管自己的下载

```ts
// 自建插件 X（如未来实现「下载管理」功能时）
const myDownloadIds = new Set<number>()

// 发起下载时记录自己的 downloadId
const downloadId = await chrome.downloads.download({ url, filename: '...' })
myDownloadIds.add(downloadId)

// 监听：只处理自己的下载，其他一律原样放行
chrome.downloads.onDeterminingFilename.addListener((item, suggest) => {
  if (!myDownloadIds.has(item.id)) {
    return // 不是自己的下载，绝不干预（不调用 suggest = 保持原文件名）
  }
  suggest({ filename: `自定义路径/${item.filename}` })
  myDownloadIds.delete(item.id)
})
```

**禁止**：在回调中无条件 `suggest(...)`（即无差别改写所有下载）。

### 约定 3：文件夹名带插件唯一前缀（命名空间隔离）

| 插件 | 前缀 | 示例 |
|------|------|------|
| 图片下载器（ChromeTool） | `ID-`（现有版本为 `{标题}-{域名}-{时间戳}`，后续版本统一加前缀） | `ID-相册-20260810_1234` |
| （未来插件在此登记） | `PREFIX-` | ... |

- 新插件必须使用自己的前缀，并在注册表中登记
- 相同前缀的插件视为同一命名空间，须保证内部唯一

## 三、冲突检测（可选增强）

监听 `chrome.downloads.onChanged`，对比 `item.filename`（实际落盘）与请求的 filename：
- 不一致 → 说明有外部插件改写了路径 → 日志告警（等级 warn）
- 当前插件可据此在日志页暴露冲突证据

## 四、排查流程（冲突发生时）

1. `chrome://extensions` 列出所有插件
2. 逐个禁用下载类插件 → 重测 → 定位冲突源
3. 确认是自建插件 → 按本规范第三条检查其 onDeterminingFilename 实现
4. 确认是第三方插件 → 无法阻止（Chrome 设计），只能引导用户禁用/换用

## 五、适用范围

- 本文件随 `AGENTS.md` 一起复制到每个新插件项目
- 新插件立项时，AGENTS.md 的「AI 宪法」须包含本规范引用
