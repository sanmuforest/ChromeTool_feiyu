# 2026-08-11-058 imgbb 原图 180 降级修复（源页注入方案）

## 背景

打包下载与普通下载 imgbb 相册时，图片全部变成 ~9KB 的 180x180 缩略图（用户实测），部分直连请求被挂起 20+ 秒。

## 根因（多层实测定位）

imgbb 防盗链升级，按**请求上下文**降级（2026-08-11 逐层验证）：

| 请求上下文 | Accept 图片头 | 结果 |
|-----------|--------------|------|
| 扩展 Service Worker fetch | 带/不带 | 一律 180 缩略图 |
| 扩展页（chrome-extension:// origin）fetch / `<img>` | 带 | 一律 180 缩略图 |
| opaque 沙箱 iframe fetch | 带 | 慢速挂起（60s 超时） |
| 源页（imgbb 域页面）MAIN world fetch | 带 | **原图**（Referer = ibb.co 页面 = 用户浏览行为） |
| curl（非浏览器 TLS 指纹） | 任意 | 原图 |

## 本次改动

| 文件 | 改动 |
|------|------|
| `src/lib/downloader.ts` | 新增 `fetchImgbbViaSrcTab()`（`chrome.scripting.executeScript` 向源页 MAIN world 注入 fetch，请求 Referer = 页面 URL 放行原图，返回字节数组）；普通下载 imgbb 分支改为主路径「源页注入 → 降级 background fetch → 直连」 |
| `src/background/background.ts` | `GRAB_FETCH_IMAGE`（打包下载字节）改走「源页注入 → 降级 background fetch」 |

**已移除（无效路径回滚）**：
- `fetchImageBytes` 的图片 Accept 头（SW 上下文无效）
- grabber 页 `imgbb-fetch.ts`（页面 fetch / canvas / opaque 沙箱均无效或挂起）
- `IMG_FETCH_BYTE_REQ/RES` 消息协议、`DownloadJob.grabTabId`、各视图 grabTabId 参数

## 依赖条件

源页注入依赖 **imgbb 源页（srcTab）存活**；源页已关闭或非 imgbb 域时降级 background fetch（可能 180）。

## 验证方式（实测通过）

1. 保持 imgbb 相册源页打开 → 普通下载：日志 `imgbb 源页注入转 data URL` bytes 数百 KB+（实测 805KB）
2. 打包下载：日志 `GRAB_FETCH_IMAGE 源页注入抓取完成` bytes 数百 KB~2MB（实测 732KB~2MB，42/42 成功）

## 回归检查

- 非 imgbb 站点下载路径未改动（buondua / 通用站点）
- 源页注入失败时降级链完整，不影响下载完成
- tsc 类型检查通过
