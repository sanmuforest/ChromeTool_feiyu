# 2026-08-13-068 修复 imgbb 用户主页抓取最多 96 张（无尽滚动 seek 翻页）

## 背景（用户反馈）

imgbb 用户主页抓取，抓取后最多只显示前 96 张；点「下一批」也无法继续追加。

## 日志解读 → 根因 → 改动点

- **日志解读**：`用户主页分页抓取完成` 的 count 不随批次数增长（每批都停在 ~96，即 3 页 × 32 张/页）
- **根因**：`src/background/imgbb-service.ts` 的 `fetchGalleryPages` 用**裸 `?page=N`** 构造翻页 URL。imgbb 用户主页为**无尽滚动**页面，裸 page 参数不可靠且**每页返回累计内容**（page=3 返回前 96 张、page=6 返回前 192 张）。抓 1~3 页的解析结果全是前 96 张的累计重复 → UI 视图去重后只剩前 96 张；「下一批」请求 4~6 页同样只能拿到累计内容 → 永远无新增。`imgbb-parse.ts:188` 注释已记载该结论（「裸 ?page=N 不可靠，必须跟随 ?page=N&seek=游标」），且同文件 `fetchAlbumImages`（相册详情）已用 seek 方案正常，唯独用户主页漏改
- **改动点**：仅改 `fetchGalleryPages`（`src/background/imgbb-service.ts`）：
  - 从首页 URL 开始，**跟随 seek 游标**（`parseAlbumNextPage`）逐页翻
  - **按原图 URL 去重**（对齐 `fetchAlbumImages` 模式）
  - 返回 `pageFrom~pageTo` 区间增量：`page >= pageFrom` 时收集，前导页仅推进游标并记录已见键
  - 终止条件：无图片 / 无下一页链接

## 兼容性自查

- `IMG_FETCH_GALLERY`（抓第一批/下一批/指定页码）：pageFrom=1 返回前 3 页，pageFrom=4 返回第 4~6 页增量 ✅
- `IMG_FETCH_GALLERY_RANGE`（编号范围抓取）：调 `fetchGalleryPages(url, 1, 60)` 取前 60 页全部去重后按编号过滤，语义不变 ✅
- 说明：imgbb seek 为连续游标，无法直接跳到第 N 页，`pageFrom>1` 时需从首页重新跟随翻页（每批最多 6 次请求），正确性优先，可接受

## 验证方式（用户实测，红线 3）

1. 重新加载 `dist/`（chrome://extensions → 刷新扩展，右下角版本徽标确认新构建）
2. imgbb 页签 → 用户主页：输入一个图片量 >100 的用户主页 URL → **抓第一批**（96 张）
3. 点**下一批** → 应追加第 4~6 页新图（合计 ~192 张），不再卡在 96
4. 继续「下一批」应持续追加；指定页码抓取（如 1~10 页）也应全量
5. 编号范围抓取抽查一次（如文件名前缀编号），确认不受影响
