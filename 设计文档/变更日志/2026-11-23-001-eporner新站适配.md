# 2026-11-23-001 新增 eporner 站点 + 引擎新增 imageTagPattern 字段

> 版本：**v0.2.81** ｜ 类型：新站适配 + 引擎能力扩展
> 触发：用户发现新类型图站 `https://www.eporner.com/gallery/OYnlGBsLlxz/...`，反馈「当前页面的直接抓取只能抓到缩略图」

## 一、站点结构实测

| 项 | 结果 |
|----|------|
| 页面 | HTTP 200，536 KB，185 个 `<img>` |
| 正文容器 | `<div id="content" class="gallerypage">` |
| 图片标签 | `<img id="t38093122" src=".../38093122-10001_296x1000.jpg" alt="amateur photo 10001">` |
| 图床 | `static-sg-cdn.eporner.com` |
| 分页 | **无**（页面声明 `145 pics`，HTML 内唯一正文图恰好 145 张，无任何分页链接） |

## 二、核心问题：只抓到缩略图

页面里的 `src` 全是 **`_296x1000`** 缩略图（20 KB）。

**规律实测**（关键）：去掉 `_宽x高` 后缀就是原图。

| URL | 大小 |
|-----|------|
| `.../38093122-10001_296x1000.jpg`（页面实际） | 20,885 字节 |
| **`.../38093122-10001.jpg`**（去掉后缀） | **1,053,502 字节** |
| `_1000x1000` / `_2000x2000` / `_1920x1080` / `_300x0` / `_1000x0` | 全部 **404** |

结论：该站原图地址就是「无尺寸后缀」形态，**不需要猜尺寸**，直接 `imageThumbFix` 去掉后缀即可。

## 三、第二个问题：混入「相关相册」推荐位

加 `imageThumbFix` 后解析出 **165 张**（本相册 145 + 推荐位 20）。

排查过程：

1. **先误写了 `imageHosts: ['eporner.com']`** → 解析出 **199 张**
   - 根因：`imageHosts` 是**全部站点 `imageHosts` 的全局并集**（`engine.ts` 的 `IMAGE_HOSTS`），
     写了之后**所有站点**都会把 eporner 的页面链接（`/profile/`、`/cat/`）当成图片
   - 修复：**删掉该字段**（本站图片都带 `.jpg`，用不到）
2. `imageOnlyHosts` 挡不住推荐位 —— 推荐位图同域同格式、也带 `.jpg`
3. 正文图与推荐位图的 URL **结构完全相同**：
   ```
   正文    /gallery/xz/Ll/OYnlGBsLlxz/38093122-10001_296x1000.jpg
   推荐位  /gallery/YK/06/HTwxifS06YK/38093351-10080_296x1000.jpg
   ```
   路径层级、ID 格式、尺寸后缀全都一样 → **静态 URL 规则无法区分**

**唯一可靠的差别在 `<img>` 标签属性**：

| 类型 | alt |
|------|-----|
| 正文图 | `alt="amateur photo 10001"`（**纯数字**） |
| 推荐位 | `alt="amateur photo The receptionist who was filming"`（文字标题） |

交叉验证（块内 165 个 img）：
```
alt 为纯数字的 145 个 → 全部属于本相册 ✓
其余 20 个            → 全部不属于本相册 ✓
```

## 四、改动

### 1. 引擎新增 `imageTagPattern`（`src/sites/schema.ts` + `src/sites/engine.ts`）

```ts
/** 图片标签过滤：<img> 标签原文必须匹配该正则才收录。
 *  用于「正文图与推荐位图 URL 结构完全相同，只能靠 DOM 属性区分」的站点。 */
imageTagPattern?: RegexSpec
```

采集分支优先级：

```
imageAttr（只扫指定属性）
  > imageTagPattern（按 <img> 标签过滤）
    > 默认（href/src/data-src 全块扫描 + style url()）
```

**不声明时完全走原有路径，对其他 15 个站点零影响**（已核对：全项目只有 eporner 声明）。

### 2. 新增站点定义 `src/sites/defs/eporner.ts`

```ts
container: { tag: 'div', className: 'gallerypage' },
pagination: { kind: 'single' },
titleStrip: [{ source: '\\s*Photo Gallery\\s*-\\s*EPORNER\\s*$', flags: 'i' }],
imagePathPattern: { source: '_\\d+x\\d+\\.jpg$' },          // 只留带尺寸后缀的
imageTagPattern: { source: 'alt="amateur photo \\d+"' },     // 只留纯数字 alt
imageThumbFix: { source: '_\\d+x\\d+(\\.jpg)$', replace: '$1', flags: 'i' },
imageOnlyHosts: ['eporner.com'],
linkParser: 'generic-post-links',
```

### 3. 注册（`src/sites/defs/index.ts`）

数组末尾追加 `eporner`，站点数 **15 → 16**。

## 七、沉淀

- **`imageHosts` 是全局并集**，不是站点私有配置 —— 写错的代价是**污染其他所有站点**。除非图片真的无扩展名，否则不要写。
- **URL 结构相同时，只能靠 DOM 属性区分**；`imageTagPattern` 是为此准备的通用口子。
- 遇到「只抓到缩略图」，先试「去掉尺寸后缀」，再用 HEAD 请求确认原图大小；不要直接猜 `_1000x1000`、`_2000x2000` 这类尺寸（本站在这些值上全是 404）。
