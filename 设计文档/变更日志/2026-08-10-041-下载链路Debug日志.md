# 2026-08-10-041 下载链路 Debug 计时日志（定位 imgbb 慢）

## 需求

imgbb 下载依然慢，需要下载分析 + Debug 日志定位瓶颈。

## 新增日志（downloader.ts，debug 级别）

下载全链路阶段计时，覆盖每个环节耗时：

| 日志 | 信息 |
|------|------|
| 派发下载项 | `queueWaitMs`（入队→派发排队等待） |
| imgbb 字节抓取完成 | `ms`（fetch 网络耗时）、`bytes`（是否原图大小） |
| imgbb 原图转 data URL | `fetchMs`、`b64Ms`（base64 CPU 耗时）、`bytes` |
| downloads.download 已发起 | `setupMs`（API 调用耗时） |
| 单项下载完成 | `ms`（派发→complete 总耗时）、**`fileSize`**（实际落盘大小，判断是否被降级 180） |
| 下载任务完成（info 汇总） | `totalMs`、`avgMsPerItem`、`concurrency` |

## 使用方式

1. 刷新扩展
2. 打开抓取页 → 日志页签 → 切换 Debug 模式（如已有此功能；否则在日志面板选择 debug 等级）
3. 下载少量 imgbb 图片（3~5 张即可）
4. 复制日志贴回，按下列指标分析：

## 分析指南

- **fetch ms 大**（数秒/张）→ 网络瓶颈（代理节点到 imgbb）
- **b64Ms 大** → CPU（一般 <10ms，异常时再查）
- **fileSize 小**（<60KB）→ imgbb 降级 180（需换方案）
- **queueWaitMs 大** → 并发槽不足（调高 header 并发）
- **单项 ms 大但各阶段小** → downloads.download 处理慢（data URL 大文件）
- **avgMsPerItem × 张数 ≈ 总耗时** → 无排队问题，纯网络速度

## 回归检查

- 日志均为 debug 级别，默认 info 不输出，不影响正常使用与性能
- 下载逻辑无改动，仅加计时埋点
