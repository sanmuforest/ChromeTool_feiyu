# 2026-08-10-035 修复 imgbb 相册抓取不完整（seek 游标翻页）+ 下载取消/速度

## 问题（用户反馈）

1. imgbb 相册 `https://ibb.co/album/pvzPkf` 有 580 张，抓取页只抓到 90 多张
2. 下载很慢
3. 下载的取消按钮无效

## 根因（参考项目 DEVLOG 经验证实）

- **imgbb 无尽滚动分页**：裸 `?page=N` 不可靠，每页返回**累计内容**（实测 p1=32、p2=64、p3=96 张），必须跟随 `?page=N&seek=游标` 翻页。原实现只 fetch 单页 → 只拿到约 32~96 张
- 下载慢：并发仅 3 + imgbb 字节抓取无 Referer
- 取消无效：imgbb 下载先 background fetch 字节（40s 内无 downloadId），取消只 cancel 已注册的 downloadId，**fetch 阶段无法中断**

## 修复

1. **全量翻页抓取**（`imgbb-parse.ts` + `imgbb-service.ts`）
   - 新增 `parseAlbumNextPage`：解析 `?page=N&seek=游标` 链接（跳过 peek/排序），取 page 号最大者
   - `fetchAlbumImages` 跟随 seek 游标循环抓取（上限 20 页防反爬），按原图 URL 去重，无新增即停
   - `parseAlbumPageTitle` 兼容 `标题 — ImgBB — Page N` 后缀
2. **下载提速**（`downloader.ts`）：并发 3→4；imgbb 字节抓取加 `Referer: https://imgbb.com/`
3. **取消修复**（`downloader.ts`）：`fetchControllers`（jobId→AbortController），取消时 abort 进行中的字节抓取；抓取完成后再检查 `job.status !== 'running'` 则跳过下载

## 验证（真实相册 pvzPkf，开发侧）

- 逐页跟随 seek：页1=32 → 页2=96 → ... → 页16=580 张（新增 0 停止于页17）✓
- 相册名 `是小桃呀` 正确 ✓
- 类型检查通过、构建零警告 ✓

## 回归检查

- 小相册（单页无 seek）：第一页即全部，循环自然停止 ✓
- 下载 data URL 方案不变（180x180 防护保留）
- 非 imgbb 下载不受影响（并发 4 全局）
