# 2026-10-17-018 缩略图尺寸回填修复 + 打包空包提示

> 版本：**v0.2.52** ｜ 类型：缺陷修复（v0.2.51 引入的回归 + 打包体验）
> 触发：用户实测反馈「抓取的都是 600×800 的图」「打包压缩包只有 1K」

## 一、问题 1：网格尺寸标签显示 600×800

### 现象

抓取 xchina 相册后，网格里每张图的尺寸角标显示 `600×800`，看起来像抓的是预览图。

### 根因

v0.2.51 为性能优化引入 `thumbUrl`（网格加载 `_600x0.webp` 预览），但加载成功的回调仍用缩略图的 `naturalWidth/naturalHeight` 回填 `img.width/height`：

```ts
if ((!img.width || !img.height) && thumb.naturalWidth > 0 ...) {
  img.width = thumb.naturalWidth   // ← 这是 600，不是原图宽度
  img.height = thumb.naturalHeight // ← 这是 800
}
```

多页图站解析本来就不带宽高，所以每张图都会被回填成预览尺寸，尺寸标签与尺寸筛选随之出错。

### 修复

`src/grabber/image-grab-view.ts`：只有**没有 `thumbUrl`**（网格直接加载原图）时才回填尺寸；有 `thumbUrl` 时保持「尺寸未知」，不再把预览尺寸当原图尺寸。

> 实际抓取地址始终是原图：日志中的 `0004.jpg` 等 URL 即原图；网格显示预览、下载/打包用 `img.url`，单张下载已验证正确。

## 二、问题 2：打包下载得到 1K 空压缩包

### 现象

打包 109 张，日志 `打包下载完成 { ok: 0, total: 109 }`，产出的 ZIP 只有 1K。

### 根因

xchina 图床 `img.xchina.io` 对三条取字节通道全部拒绝（与 se8.me 相同，变更日志 014 已记录）：

- 扩展页 `fetch` → CORS 失败
- 源页注入 `fetch` → `TypeError: Failed to fetch`
- 后台 `fetch` → HTTP 403

三条都失败时 `okCount = 0`，但代码仍生成 ZIP 并下载，于是得到空包。

### 修复

`src/grabber/image-grab-view.ts`：全部失败（`okCount === 0`）时不再生成/下载 ZIP，进度条位置显示：

> 打包失败：0/109 张可读取（图床拒绝扩展读取，请改用「下载选中」）

### 结论

**xchina 的打包下载不可用是图床策略导致的硬限制，不是本轮引入的 bug。** 该站请使用「下载选中」（`chrome.downloads` 浏览器原生下载，带 Cookie，实测正确）。这一限制在 `站点适配总览.md` 与变更日志 014 中已有记录。
