# 2026-10-10-003 加载失败角标支持手动重试（缩略图容错第 5 级）

> 版本：**v0.2.18** ｜ 类型：功能增强（延续 v0.2.17 的四级容错链）
> 触发：v0.2.17 实测「大部分加载成功、仅很少几张最终失败」→ 用户选择「加点击失败角标手动重试」

## 背景

v0.2.17 的四级链（错峰加载 → 延迟重试 → blob 兜底 → 标记失败）已把破图压到极少数。剩余失败属"当前网络下持续取不到"，而图床限流的**暂时性**特征意味着"过一会儿再试往往能成"。因此补一个由用户掌控的重试入口。

## 改动（`image-grab-view.ts`，同一解冻授权范围内延续）

| 项 | 实现 |
|----|------|
| 角标文案 | 最终失败时显示「**加载失败（点击重试）**」，并置 `cursor: pointer`（inline 样式，**不改 CSS**） |
| 点击行为 | 重置重试计数 → 角标显示「重试中…」→ 以附加时间戳的 URL 强制重新请求（绕过失败缓存） |
| 误触防护 | **仅当角标处于「加载失败」文案时**才响应点击；成功后 `restoreSizeTag()` 会清掉 pointer 与文案 |
| 事件隔离 | `ev.stopPropagation()` —— 避免点击角标时**同时触发卡片的选中切换** |
| 抽取 | 新增 `loadSrc(force)` 统一生成加载 URL，自动重试与手动重试共用（消除重复逻辑） |
| 日志 | 手动重试记录 `手动重试加载图片 { url }`，便于判断是否有效 |

**未触碰**解析、去重、筛选、选择、下载、打包、命名；下载始终用原图 URL。

## 验证

- `npm run typecheck`：EXIT=0
- `npm run build`：通过，**当前版本 v0.2.18**

## 用户实测清单

1. 重载 `dist/`（确认徽标 **v0.2.18**）→ 抓一个 kaizty 相册
2. 等待自动流程走完（会出现「重试中 N/2…」→ 可能「兜底加载中…」）
3. 对仍显示「**加载失败（点击重试）**」的图**点一下角标** → 应出现「重试中…」并通常能加载出来
4. 确认点击角标**不会**改变该图的选中状态（这是本次特意隔离的行为）
5. 回归：主抓取页、imgbb 相册各抓一次

## 备注

- 这一级是"人工兜底"，不增加自动请求量，也不影响常规路径性能
- 若手动重试仍失败，说明该资源在当前网络下确实不可达（站点网页端同样如此），属环境限制
