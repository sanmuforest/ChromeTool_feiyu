# 2026-10-11-007 探测工具二轮增强（滚动触发懒加载 + 放宽取值属性）

> 版本：**v0.2.32** ｜ 类型：工具增强（延续 v0.2.31，仍属用户批准的 `messages.ts` / `background.ts` 解冻范围）
> 触发：v0.2.31 的探测输出**仍看不到正文图**（用户实测 `tw.8se.me`）

## 一、v0.2.31 输出的问题（用户实测）

按 host 分组只出现三组，**正文图床缺席**：

| 分组 | 父级链 | 判断 |
|------|--------|------|
| `tw.8se.me ×18` | `a < div.logo < div.topMenu < nav.mobile` / `div < a < div.subs < div.menu` | 站点 logo 与菜单 |
| `upload.xchina.io ×15` | `a.z-fixed-zones-content < div.z-fixed-zones.z4 < div.right-5 < div.layout-lr.photo` | 落在**固定层/右栏**（侧栏或放大预览） |
| `xchina.click ×8` | `a.z-fixed-zones-content < div.z-fixed-zones.z8 < div.left-1 < div.layout-lr.photo` | 落在**固定层/左栏** |

而 `og:image` 明确是 **`img.xchina.io/photos/6ab304a17337d/00014.jpg`** —— 正文图床一张都没探测到；分页链接里也只有当前页 `2.html`，没有 `1.html` / `3.html`。

## 二、根因判断

`probePageStructure` 用 `chrome.tabs.create({ url, active: false })` 开**后台标签页**，**从不滚动**。该站正文图是懒加载（进入视口才创建/填充 `img`）→ 正文图从未进入 DOM → 提取不到。

同时，取图 URL 的属性收得过窄（只试 `data-src` / `data-original` / `src`），若该站用别的属性名（`data-lazy-src` / `data-url` / `data-image` / `srcset` …）也会全漏。

## 三、改动

| 项 | 内容 |
|----|------|
| **① 先滚动再提取** | `extractProbeData` 改为 `async`：按 4 段滚到页面底部（每段等 400ms）再回顶，触发懒加载后才开始统计 |
| **② 放宽取值属性** | 新增 `srcOf()`：依次尝试 `data-src` / `data-original` / `data-lazy-src` / `data-lazyload` / `data-url` / `data-image` / `data-echo` → `srcset` 首个 URL → `currentSrc` → `src`；`imgSrcs` 与 `imageGroups` 统一改用它 |
| **③ 新增三条排查线索** | `imgAttrKeys`（img 上实际出现的 `src`/`data-*` 属性名，直接告诉我该站 lazy 用哪个属性）、`bgImages`（内联 `background-image`，正文可能用 CSS 背景）、`iframeSrcs`（正文可能嵌在 iframe 内） |

对应 `PageProbeResult` 新增三个**可选**字段，view 展示追加三段。

预期能看到其中之一（任一都能让我写出定义）：

| 若出现 | 说明 |
|--------|------|
| `img.xchina.io ×N` + 父级链 | 正文图已加载 → 容器定义直接照父级链写 |
| `img 上的 src/data-* 属性名` 里有非常见属性 | 该站用特殊 lazy 属性 → 我把 `srcOf` 与解析器一并支持它 |
| `内联 background-image 样本` 出现 `img.xchina.io` | 正文用 CSS 背景 → 解析器需支持从 style 里取图 |
| `iframe src` 非空 | 正文在 iframe 内 → 抓取流程需先进入 iframe |
