## 二、问题：真实失败原因被吞掉

原 `fetchImgbbViaSrcTab` 在**注入函数内部**抛错：

```ts
if (!resp.ok) throw new Error('HTTP ' + resp.status)
```

而 `chrome.scripting.executeScript` **不会把注入函数的异常回传**（`results[0].result` 变为 `undefined`）→ 调用方只能看到 `页面未返回字节`。

于是「页面内 fetch 也被 403」与「跨域被 CORS 拦截」**在日志里长得一模一样**，两者修法完全不同：

| 真实原因 | 含义 | 对应修法 |
|---------|------|---------|
| `页面内 fetch 失败：HTTP 403` | 图床对该站会话也拒（限流/校验更严） | 降并发 + 退避重试，或改用页面自身加载的 URL（缩略图）/触发预览层 |
| `页面内 fetch 失败：TypeError: Failed to fetch` | **CORS 拦截**（页面 fetch 跨域不可行） | 换通道：让页面自身发起请求（注入 `<img>` 取到 blob，或驱动预览层） |

按红线 3（禁止猜测性修改），**先让日志说真话**，再对症修复。

## 六、关于「默认被过滤了一部分」

已核查 `isSmallImage`（小图过滤）逻辑：**尺寸未知的图直接放行**，不会被过滤。

```ts
if (img.sizeStatus !== 'ok' || !img.width || !img.height) return false   // unknown → 不算小图
```

而多页图站抓来的图初始 `sizeStatus` 均为 `unknown`（后台解析不含宽高）→ 默认**不会**被小图过滤剔除。

所以「被过滤了一部分」更可能是**图片取字节失败导致显示为破图**（即上面那条 403），请确认：

- 若统计栏显示形如「共 66 张（小图剔除 N），显示 M 张」→ 请把该行文字贴我（N/M 的值能直接定位）
- 若只是部分缩略图显示「加载失败（点击重试）」→ 那就是取字节问题，与过滤无关
