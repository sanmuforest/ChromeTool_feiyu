# 2026-11-11-005 SPA 站点浏览器 DOM 通道（rrwsh 可抓了）

> 版本：**v0.2.76** ｜ 类型：新通道（解决 SPA 站点 fetch 拿不到内容）
> 触发：用户指出 rrwsh 仍是 0 张（日志：DOM 有 30 张、后台 fetch 0 张）

## 一、问题本质

rrwsh 改版后服务端 HTML 是空壳：

```
相册全子页抓取完成 { scanned: 0, title: "4KHD - HD Beautiful Girls", unique: 0 }  ← fetch：空壳
解析完成（默认全选） { count: 30 }                                              ← DOM：30 张
```

- 服务端 HTML 约 **1991 字节**、**0 个 `<img>`**、title 是站点默认标题
- 内容全靠 JS 渲染，因此**后台 fetch 与页面内 fetch 都拿不到**
- 只有**真实渲染后的 DOM** 里有图片

## 二、改动

### 新增 `src/background/dom-fetch.ts`

| 函数 | 用途 |
|------|------|
| `extractDomImages(tabId)` | 用 `chrome.scripting.executeScript` 注入，从已渲染页面读取图片绝对 URL（去重、过滤 logo/图标/头像）。优先取正文容器 `.entry-content, .wp-block-post-content, article, main`，找不到退化为整页；兼容 `data-src` / `data-original` / `data-lazy-src` / `currentSrc` / `src` |
| `extractImagesByNavigation(url)` | 开**非激活临时标签页**加载 URL → 等 `status: 'complete'` → 再等 1200ms（hydration）→ 提取 → **关闭标签页**。用临时标签页是为了不打断用户当前浏览 |

### `buondua-service.ts`：`fetchAlbumAllPages` 增加 `domFetchFn`

```ts
async fetchAlbumAllPages(url, fetchHtmlFn?, domFetchFn?): Promise<...>
```

在翻页循环结束后判定：

```ts
if (imagesMap.size === 0 && domFetchFn) {
  logger.warn('buondua', 'HTML 通道 0 张，改走浏览器 DOM 通道（SPA 站点）', {...})
  const domImages = await domFetchFn(url)
  // 应用 site.imageUrlClean（缩略图还原等）后写入 imagesMap
}
```

**只在 HTML 通道解析为 0 张时才启用** —— 正常站点完全不受影响，也不会多开标签页。

### `background.ts`：`BD_FETCH_ALBUM` 注入 `domFetch`

- **当前标签页 URL == 目标 URL** → 直接读它的 DOM（页面已渲染，零成本）
- **否则** → 开临时标签页导航后读取
- 两条路径都只在 SPA 降级时触发

## 五、当前限制

| 项 | 说明 |
|----|------|
| **只有第 1 页** | `fetchAlbumAllPages` 的翻页依赖 `maxPage`，而 SPA 的空壳 HTML 里读不到总页数（`parseGalleryMaxPage` 返回 1）。所以**多页相册目前只抓第 1 页** |
| 多页的解法 | 给该站加 `followPagesUntilEmpty: true`，让流程顺序翻页；每页都会走 DOM 通道。但 SPA 每页要等 ~1.2s 渲染 + 开标签页，11 页估计 20~30 秒 |
| 临时标签页 | 抓取过程中会看到标签页闪动（非激活），抓完自动关闭 |
