# 2026-10-07-002 相册名中文化（FP-019）

> 版本：**v0.2.6** ｜ 范围：多页图站相册的文件夹名与图片名前缀中文化
> 关联：`设计文档/功能规划书/FP-019-相册名中文化.md`

## 需求（用户提出）

多页图站抓取正常，但相册命名是原文（日文/英文/越南文），希望对**文件夹名与图片名**都使用翻译后的中文。

用户确认的方案：翻译用 Google 免费端点；文件夹名 + 图片名都用译文、失败回退原文、加开关（默认开）；**本阶段只做多页图站**。

## 改动

| 文件 | 改动 |
|------|------|
| `src/lib/translate.ts` | **新增**：翻译层（Google `translate_a/single` 端点 + 8s 超时 + storage 缓存 + 译文清洗 + 全失败回退原文 + 已是中文跳过） |
| `src/grabber/view-buondua.ts` | 页签名右侧新增「相册名译成中文」开关（复用既有 `.bd-google-all-check` 样式，**无需改 CSS**）；单相册抓取与两处批量抓取（推荐/其他、聚合搜索）在命名前翻译标题，并显示 `翻译相册名 n/N…` 进度 |
| `设计文档/模块边界.md` | 新增「标题翻译」模块行；登记存储键 `translate_enabled` / `translate_cache` |

**未触碰**：`messages.ts`、`background.ts`、`grabber.html`、`grabber.ts`、`grabber.css`、`manifest.json` 权限、命名规则本身（站点路由与短名清洗逻辑完全沿用）。即 **本次零 FROZEN 解冻**。

## 设计要点

- **同源生效**：图片名前缀 = `getAlbumName()`，与文件夹名同源于「相册标题」，故翻译一次两者同时中文化
- **回退优先**：未授权 / 超时 / 非 200 / 结构异常 / 译文为空 → 返回原文，异常仅记 warn 日志，不阻断抓取
- **缓存**：按原文缓存（上限 500 条，超出丢较早一半），同一相册不重复请求
- **隐私**：标题会发送给 Google 翻译；关闭开关即完全不发请求
