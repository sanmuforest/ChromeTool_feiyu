# 2026-10-08-001 修复：Google 组站点被误判「该站不支持搜索」（FP-025）

> 版本：**v0.2.12** ｜ 类型：Bug 修复（单点根因）

## 现象（用户实测 + 日志）

v0.2.11 聚合搜索，手动勾选 **ilovexs**（Google 组）搜索「无内」：

```
聚合搜索发起 { googleSites: ["ilovexs"], sites: ["ilovexs"], pagesPerSite: 2 }
聚合搜索完成 { merged: 0, perSite: {}, sites: 1 }     ← perSite 为空
grabber 聚合搜索完成 { sites: 0, total: 0 }
```

关键特征：**完全没有 Google 请求日志**（无 `Google 标签页提取`），`perSite` 为空 —— 说明该站在发起任何请求之前就被跳过。

## 根因

`BuonduaService.searchSites` 的早退闸门只认两种「需要站内 searchUrl」的场景，漏了 Google 组：

```ts
// 修复前
if (!site || (!site.searchUrl && !useGoogleAll)) {
  await onSite(siteId, [], '该站不支持搜索')
  continue
}
```

`ilovexs` 与 `phimvuspot` 的站点定义**没有 `search` 字段**（设计上就是只走 Google 通道），因此：

- `site.searchUrl` 为 `undefined`
- 用户未开「Google 全站搜索」→ `useGoogleAll = false`
- → 早退条件成立 → 被判定「该站不支持搜索」并 `continue`，**Google 通道根本没被调用**

`hitxhot` / `kaizty` / `jrants` / `pixibb` 因为定义了 `search` 字段而侥幸正常 —— 这正是用户观察到的「有些网站没有激活搜索」。

## 影响面

| 站点 | 是否有 search 字段 | 修复前 |
|------|------------------|--------|
| hitxhot / kaizty | 有（google-sitesearch） | 正常 |
| jrants | 有（FP-021 起为 google-sitesearch） | 正常 |
| pixibb | 有（wp-query-path-page） | 正常 |
| **ilovexs** | **无** | **被误判跳过** |
| **phimvuspot** | **无** | **被误判跳过** |

## 改动（仅 1 处，只改根因）

`src/background/buondua-service.ts` 的 `searchSites` 早退闸门：

```ts
// 修复后：Google 全站模式 或 Google 组站点 都不要求站内 searchUrl
const useGoogleChannel = useGoogleAll || googleSites.includes(siteId)
if (!site || (!site.searchUrl && !useGoogleChannel)) {
  await onSite(siteId, [], '该站不支持搜索')
  continue
}
```

后续分支无需改动：这两个站 `isGoogleOnly` 为真，会自动走 `googleSearchConfig` 构造 `site:域名` 查询并进入标签页通道。

## 验证

- `npm run typecheck`：EXIT=0
- `npm run build`：通过，**当前版本 v0.2.12**
- 实测：勾选 **ilovexs**（或 phimvuspot）搜索 → 日志应出现 `Google 标签页提取 {... requestsUsed: 1}`，且不再出现「该站不支持搜索」

## 回归检查

| 相邻模块 | 结论 |
|---------|------|
| 站内搜索（buondua 等有 searchUrl 的站） | 逻辑未变（`useGoogleChannel` 为假时行为与修复前一致） |
| Google 组站点（hitxhot/kaizty/jrants/pixibb） | 仍走原分支；仅闸门多认了一种放行条件 |
| Google 通道限频（FP-024） | 未触碰；新放行的站点同样计入 `googleBudget` 预算与 4 秒间隔 |
| 列表浏览（FP-023） | 未触碰 |

## 提醒（沿用 FP-024 纪律）

修复后 ilovexs / phimvuspot 会**真正发起 Google 请求**，因此：

1. 不要短时间反复搜索（每轮之间 ≥1 分钟）—— 用户本次测试的 3 次搜索间隔仅 7~18 秒
2. Google 组多站同时勾选会更快触达单轮 8 次预算上限（这是预期的保护）

## 已知限制（沿用）

- ilovexs / phimvuspot 无 `searchAlbumPath`，Google 结果只按域名过滤 → 可能混入非相册页；实测若噪音明显，再加 `searchAlbumPattern` 正则过滤字段
