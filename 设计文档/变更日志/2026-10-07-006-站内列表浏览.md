# 2026-10-07-006 站内列表浏览（FP-023）

> 版本：**v0.2.10** ｜ 关联：`设计文档/功能规划书/FP-023-站内列表浏览.md`
> 触发：Google 通道在用户网络环境被 403 拒绝；用户选择「直接抓站点分类/列表页」方向

## 定位结论（本轮）

用户实测反馈「DSH 内可以打开 Google，Chrome 浏览器打不开、403」：

| 证据 | 含义 |
|------|------|
| DSH / 系统环境可访问 Google | 代理出口本身可用 → **不是出口被封** |
| Chrome 手动访问 `google.com/search?q=test` → 403 | 问题在 **Chrome 侧网络路径** |
| 系统代理 `127.0.0.1:7897`、`www.google.com` 解析到 `174.132.167.252`（非 Google IP） | 代理工具接管了 DNS；Chrome 的代理扩展规则或「安全 DNS」可能绕过该系统路径 |

→ 已给用户 Chrome 侧排查建议（无痕窗口验证扩展规则 / 关闭安全 DNS / 核对 Chrome 代理设置）。**与插件代码无关**。

## 设计要点

- **复用而非新建**：列表页解析不写新解析器，用通用同域链接提取 + 路径收窄；抓取结果直接进现有链接列表 → 直接复用「抓取选中」批量抓取
- **两段兜底**：后台 fetch 失败或 0 结果 → 自动降级页面内 fetch（带 Cookie，穿透反爬）
- **界面可编辑**：列表路径与页数都由界面控制，实测发现默认路径不对时用户可直接修改，无需等改代码发版

## 用户实测清单

1. 多页图站 → **批量抓取其他链接** → 面板第二行「列表浏览」
2. 选 **hitxhot** → 路径应自动填 `/gallerys/` → 点「抓取列表页」（先 1 页）
3. 观察：链接列表是否出现相册卡片（标题/张数）；若 0 条，把日志贴我（日志含 `列表页抓取完成 unique:N`、`列表页被反爬拦截`、`后台列表抓取失败`）
4. 同法测 **kaizty**（`/photos/`）
5. 对其它站点试根路径 `/`；若某个站有更好的分类路径（如 `/category/xxx`），直接改输入框即可
6. 抓到的链接勾选 → 「抓取选中」→ 验证能批量抓到图
7. 右下角徽标应为 **v0.2.10**
