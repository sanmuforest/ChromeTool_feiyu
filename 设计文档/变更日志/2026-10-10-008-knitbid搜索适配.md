# 2026-10-10-008 knit.bid 站内搜索适配 + 两个通用缺陷修复

> 版本：**v0.2.23** ｜ 类型：新站点能力补全（搜索）+ 通用缺陷修复
> 触发：用户提供搜索页 `https://xx.knit.bid/ja/search/`

## 一、搜索接口探测（真实 HTML）

| 项 | 实测 |
|----|------|
| 表单 | `<form method="get" action="/ja/search/">` + `<input type="search" name="s" placeholder="入力キーワード">` |
| 搜索 URL | `/ja/search/?s={关键词}`（页面上即存在 `?s=JVID`、`?s=AI` 等示例链接） |
| 分页 | `/ja/search/page/N/?s={关键词}`（实测第 2 页 HTTP 200，结果与第 1 页不同） |
| 结果卡片 | 每页 16 个相册链接，形态 `/ja/article/{id}/` |
| 噪音 | 结果页同时含 `/ja/type/1/` 等分类页链接 → 必须按相册形态过滤 |

## 二、修掉的两个通用缺陷（本次适配中发现，均为长期存在）

### 缺陷 A：「尾部数字路径 = 分页」的启发式误杀 ID 结尾的相册 URL ⚠️ 重要

`parseSitePostLinks` 中有一条排除规则，用于剔除 `/slug/2` 这类分页链接：

```ts
if (/\/\d+\/?$/.test(path)) continue // 分页尾部数字
```

但它同时会**误杀「以 ID 结尾」的相册 URL** —— 例如 `/ja/article/27027/`。
后果：**凡是「文章 URL 以数字 ID 结尾」的站点，用通用解析器（`generic-post-links`）做搜索/列表时，结果会被静默清空（0 条，且无任何报错）**。

本次验证时正是这条规则导致解析结果为 0，才被发现。

**修复**：该排除改为**可跳过**，并在站点已配置精确过滤规则（`searchAlbumPath` / `searchAlbumPattern`）时跳过：

```ts
if (!opts?.skipNumericFilter && /\/\d+\/?$/.test(path)) continue
// generic-post-links 与 parseListPageLinks 传入：
skipNumericFilter: !!(site.searchAlbumPath || site.searchAlbumPattern)
```

即「有精确规则时不再用启发式猜测」，避免两者冲突。

### 缺陷 B：`wp-query-path-page` 假定搜索页位于根路径

原实现固定生成 `https://{host}/?s=q` 与 `https://{host}/page/N?s=q`，无法表达搜索页不在根路径的站点（knit.bid 为 `/ja/search/`）。

**修复**：`SiteSearch` 的 `wp-query-path-page` 新增可选 `path`（默认 `/`，对既有站点行为不变）：

```ts
search: { kind: 'wp-query-path-page', param: 's', path: '/ja/search/', trailingSlash: true }
```

### 配置修正：主域应为实际部署的子域

初版定义把 `knit.bid` 设为 primary → 生成的搜索 URL 是 `https://knit.bid/...`（裸域），而该站实际在 **`xx.` 子域**。

**修复**：`endpoints: [{ host: 'xx.knit.bid', role: 'primary' }, { host: 'knit.bid', role: 'mirror' }]` —— 搜索 URL 由 primary 生成，必须指向可用子域。

## 四、用户实测清单

1. 重载 `dist/`（确认徽标 **v0.2.23**）
2. 多页图站 → 聚合搜索 → **knitbid 现在位于「站内搜索」组**（此前在 Google 组）
3. 勾选 knitbid → 搜一个词（如 `JVID`）→ 预期每页约 16 条相册结果
4. 点「下一批（继续检索）」→ 应返回第 2 页的不同结果
5. 抽一条结果抓取 → 应正常抓到图片（顺序翻页 + 相对路径解析均已在 v0.2.22 支持）
6. 回归：buondua 站内搜索、hitxhot/kaizty 的 Google 通道搜索均应不受影响（缺陷 B 对未配 `path` 的站点行为不变；缺陷 A 仅在配置了精确过滤规则时放宽）

## 五、备注

- 缺陷 A 的影响面值得记住：**「搜索/列表结果莫名 0 条」时，先检查相册 URL 是否以数字结尾**，以及该站是否已配 `searchAlbumPath` / `searchAlbumPattern`
- 本次两次「先写定义 → 用真实 HTML 跑验证」的流程各抓出一个隐藏问题（相对路径、尾数字误杀）；建议后续新增站点一律照此验证，别只看代码通过
