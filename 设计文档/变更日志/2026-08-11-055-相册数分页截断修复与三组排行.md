# 2026-08-11-055 相册数分页截断修复 + 三组独立排行 + 重置确认

## 1. 相册数 32 截断修复（用户实测发现）

- **根因**：确认评分只抓 `{user}.imgbb.com/albums` **第一页**，imgbb 用户相册列表按页加载（约 30~32 个/页）→ 相册数被截断为第一页数量，大量用户显示 32
- **修复**：确认评分改为**遍历全部分页**（`?page=N&seek=...`，复用 `parseAlbumNextPage`，上限 20 页，去重）→ 真实相册数
- **已确认数据需重置**：新增「重置确认」按钮（`IMG_DB_RESET_CONFIRM`），清所有用户的 albumsChecked/albumCount/albums（保留入度与来源），之后重新「确认评分」即可拿到全量相册数

## 2. 统计改为三个独立排行分组（用户要求）

| 分组 | 排序 | 内容 |
|------|------|------|
| 得分 Top N | 综合评分降序 | 得分（随权重实时变化）/ 入度 / 相册数 |
| 入度 Top N | 入度降序 | 入度 |
| 相册数 Top N | 相册数降序（仅已确认） | 相册数 / 入度 |

- **排行数量 N 可调**（输入框 10~500，默认 100），变化即刷新
- 权重调整 → 得分组实时刷新排序
- 会话实时列表保留（① 扩散进度观察）

## 3. 其他

## 4. 截断标注 + 单用户彻底遍历（用户反馈：巨量相册用户 20 页仍不够）

- 常规确认页数上限 20 页，未遍历完的用户在相册数位置标注 **`N+`**（橙色点状下划线，可点击）
- **点击 `N+`** → 确认弹窗 → 单用户彻底遍历（上限 300 页）→ 更新相册数与截断状态
- 数据字段：ProducerEntry +albumsTruncated；消息 IMG_SCORE_FULL；公共函数 fetchUserAlbums（常规/彻底共用）
- 彻底遍历结果：相册数更新为全量，若仍超 300 页上限继续标注

## 5. 确认逐个更新 + 停止按钮（用户反馈）

- **确认一个更新一个**：确认评分批内每完成一个用户，通过 `IMG_SCORE_PROGRESS_FWD` 实时推送（当前用户/相册数/失败数），状态文本实时刷新 + 排行每 2s 节流刷新
- **停止按钮**：确认评分运行中「停止」可点 → `IMG_SCORE_STOP` 设取消标志 → worker 中断整批 → 已确认部分保留入库
- IMG_SCORE_BATCH 增加 srcTabId（推送目标）；三组排行改为横向并排（rank-groups flex）
- 「重新确认」按钮：重置确认状态 + 自动开始重新确认第一批
