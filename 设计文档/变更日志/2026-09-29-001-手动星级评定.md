# 2026-09-29-001 手动星级评定（FP-015）

## 需求（用户指示 2026-09-29）

生产者库「入度 Top」列表有两个空闲栏位（第 3 列得分、第 5 列相册数）。用户要求：

1. 第 5 列改为 **5 颗空白星级**，手动点击评星（1~5 星，再点同一颗取消）
2. 星级**计入综合评分，权重占 50%**
3. 剩余 50% 仍按②区「入度权重」输入框的比例分给入度与相册数
4. **未评星（0 星）= 星级项 0 分**

## 评分公式（变更后）

```
score = 0.5 × (stars / 5) + 0.5 × [ w1 × logNorm(入度) + w2 × logNorm(相册数) ]
```

- `w1` = ②区「入度权重」输入框（默认 60%），`w2 = 1 − w1`
- 未评星用户星级项 0 分（按用户确认的口径）

## 边界影响与回归自查（红线 1）

- 涉及 FROZEN 模块：`types.ts` / `producer-db.ts` / `messages.ts` / `background.ts` → 已先更新 `模块边界.md` 再改代码
- **得分 Top**：排序结果随星级变化（预期）；**区间检索**：`confirmedScored` 走同一 `computeScore`，区间选取结果随之变化（预期）
- **相册数 Top**：未改动，不受影响
- **重新确认**（`resetConfirmations`）：只清相册字段，保留 `starRating`（星级与相册确认相互独立）
- **导入导出 / GitHub 合并**：引入路径均经 `loadDb` 容错或 `mergeDb`（本地星级优先），不丢星级
- **未确认相册的用户**：星级照常计分（星级不依赖相册确认）
