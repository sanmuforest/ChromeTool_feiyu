# 2026-10-10-006 多页站视图工具栏新增「重新抓取」按钮

> 版本：**v0.2.21** ｜ 类型：小功能（用户确认）
> 触发：用户反馈「重新抓取按钮消失」→ 确认后决定在多页站视图工具栏补上

## 背景

多页图站创建共享抓取视图时显式传 `showReparse: false`（既有设计：重抓入口是面板上方的「抓取全部子页」）。用户希望在视图工具栏里也能直接重抓。

## 改动

| 文件 | 改动 |
|------|------|
| `src/grabber/image-grab-view.ts` | `GrabViewOptions` 新增可选 `reparseLabel`（默认 `'重新解析'`，不影响既有场景）；工具栏按钮文案改用该变量 |
| `src/grabber/view-buondua.ts` | 抽取 `runAlbumFetch()` 作为唯一抓取实现；`#bd-album-fetch` 按钮与视图工具栏「重新抓取」**共用**它；视图选项改为 `showReparse: true` + `reparseLabel: '重新抓取'` + `onReparse` 回调 |

**要点**：重抓逻辑（读输入框 URL → 申请 `<all_urls>` 授权 → 发 `BD_FETCH_ALBUM` → 命名中文化 → 更新文件夹名/相册名）只有一份实现，面板按钮与工具栏按钮行为完全一致，不会出现两条路径分叉。

## 验证

- `npm run typecheck`：EXIT=0
- `npm run build`：通过，**当前版本 v0.2.21**

## 回归检查

| 相邻模块 | 结论 |
|---------|------|
| 主抓取页 / imgbb 场景 | 未传 `reparseLabel` → 按钮仍显示「重新解析」，行为不变 |
| 多页站面板「抓取全部子页」 | 改为调用 `runAlbumFetch()`，逻辑与之前逐行一致 |
| 共享视图工具栏布局 | 多页站新增一个按钮；「加载下一批」仍隐藏（`showLoadMore: false`） |

## 用户实测清单

1. 重载 `dist/`（确认徽标 **v0.2.21**）
2. 多页图站 → 抓一个相册 → 视图工具栏应出现「**重新抓取**」按钮
3. 点击它 → 应重新抓取输入框里的同一个 URL（与面板「抓取全部子页」效果一致）
4. **同时验证 v0.2.20 的性能修复**（尚未实测）：
   - 抓大相册（几百张）时**滚动应顺畅**、滚轮在留白处有响应
   - 缩略图**滚到哪加载到哪**（不再一次性全 load）
   - 尺寸筛选按钮应在图片加载后**自动出现**
