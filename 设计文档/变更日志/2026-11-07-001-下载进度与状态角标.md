# 2026-11-07-001 下载进度修正 + 缩略图下载状态角标

> 版本：**v0.2.69** ｜ 类型：缺陷修复 + 新功能
> 触发：用户反馈「下载进度条不能正确显示已下载多少成功多少失败」，并要求「给预览小图加右下角标记显示当前下载状态，点击标记重试」

## 一、进度条为什么看起来不准

原实现：

```ts
const doneCount = job.done + job.failed
const pct = Math.round((doneCount / job.total) * 100)
dlText.innerHTML = `${statusText} ${doneCount}/${job.total} 成功 ${job.done} 失败 ${job.failed}`
```

问题：**重试中的项既不算 `done` 也不算 `failed`**。

imgbb 场景下大量项会经历「超时 → 重新入队 → 重试」，这期间进度条会长时间停在某个数字上，看起来像卡死；而用户又看不到「有几张正在重试」，只能看到成功/失败两个数不动。

## 二、改动

### 1. 进度条补上「进行中」（`src/grabber/image-grab-view.ts`）

```ts
const inflight = Math.max(0, job.total - job.done - job.failed)
dlText.innerHTML =
  `${statusText} ${doneCount}/${job.total}（${pct}%）` +
  ` 成功 ${job.done} 失败 ${job.failed}` +
  (job.status === 'running' ? ` 进行中 ${inflight}` : '')
```

现在三个数相加恒等于 `total`，一眼能看出还有几张在跑。

### 2. 新增逐张下载状态角标

**数据结构**（`src/lib/types.ts`）：

```ts
export interface DownloadJob {
  ...
  /** 已完成项的 URL（只有计数无法知道「哪一张」成功） */
  doneUrls: string[]
}
```

**background 侧**（`src/lib/downloader.ts`）：每项下载完成时把 url 追加进 `doneUrls`。

**抓取页侧**（`src/grabber/image-grab-view.ts`）：

- 每张卡片右下角创建 `.dl-badge`，状态由 `job` 推导：
  - `doneUrls` 命中 → **✓ 成功**（绿色）
  - `failedItems` 命中 → **! 失败**（红色，可点击）
  - 其余 → **隐藏（等待中）**
- `renderGrid()` 重建时清空 `dlBadgeMap`，避免累积与更新到已移除节点
- `renderDownload()` 每次刷新都调用 `updateDownloadBadges()`

### 3. 失败角标点击 = 单张重试

```ts
dlBadge.addEventListener('click', (ev) => {
  if (dlBadge.dataset.state !== 'fail') return
  ev.stopPropagation()
  if (job?.status === 'running') return   // 有任务在跑时不打断
  void retrySingleDownload(img)
})
```

`retrySingleDownload()` 走与批量下载相同的通道：

- imgbb 图片 → `GRAB_FETCH_IMAGE` 后台取字节 → blob → `chrome.downloads.download`
- 其它 → 直接 `chrome.downloads.download`
- **文件名与批量下载保持一致**：从 `collectSelectedItems()` 里查该项已有的 `filename`（批量命名用的是「选中序号 + 相册名」，序号不同文件名就不同）
- 成功后角标变 ✓，失败仍为 !（可再次点击）

### 4. 样式（`src/grabber/grabber.css`）

右下角圆形角标，`data-state` 控制显示：`ok` 绿色 ✓ / `fail` 红色 !（hover 加深）/ `pending` 隐藏。

## 三、验证

- `npm run typecheck`：EXIT=0
- 核对点：`dlBadgeMap` 定义在渲染之前（避免 TDZ）、`renderGrid` 中 clear、`doneUrls` 在 types/downloader/grabber 三处贯通
- `npm run build`：通过（v0.2.69）

## 四、用户实测清单

1. **刷新扩展**（确认 v0.2.69）
2. 抓一个 imgbb 相册 → 「下载选中」
3. 观察：
   - 进度条文案应为 `下载中 X/92（Y%）成功 A 失败 B 进行中 C`，且 **A+B+C 恒等于 92**
   - 每张缩略图右下角：下载成功的出现绿色 **✓**
   - 有失败的图出现红色 **!**
   - 点击红色 **!** → 该张单独重试（日志出现「手动重试单张下载」），成功后变 ✓
4. 注意：任务运行中时角标点击不响应（避免打断），需等任务结束后再点

## 五、说明

- 角标只在**下载/打包任务存在时**才有意义；解析后未开始下载时全部隐藏
- 任务结束后角标保留（方便确认哪些失败），直到下次下载重新计算
