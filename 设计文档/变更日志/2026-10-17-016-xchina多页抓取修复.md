# 2026-10-17-016 xchina.co 多页抓取修复（只抓第 1 页 30 张）

> 版本：**v0.2.50** ｜ 类型：抓取缺陷修复
> 触发：用户实测站内搜索可用（v0.2.49），但相册多页抓取只得到第 1 页 30 张

## 一、现象

- 站内搜索：可用（用户确认能搜到）
- 多页抓取：只抓到首页 30 张，后续页没有抓

## 二、根因（用户第 2 页探测输出）

```
标题: 极品小清新 - 第 2 页 - 希威社 - 小黄书 xChina
URL:  https://xchina.co/photo/6ab7845e39edf/2#pics
分页(0): （无）
```

站点改版后，**第 2 页标题不再带 `(N/M)` 总页数**，而是「{相册名} - 第 N 页 - {模特} - 小黄书 xChina」；同时页面探测不到任何分页链接。

抓取流程：

1. `parseGalleryMaxPage` 先用 `maxPagePattern` 匹配标题（原正则 `\((\d+)/(\d+)\)`）→ 新版标题无括号页数 → 不命中
2. 分页链接兜底（`page-numbers` / `?page=N` / `/page/N/`）→ 探测分页 0，也不命中
3. 返回默认值 **1** → `maxPage = 1` → 只抓第 1 页

> 注：`#pics` 锚点不是根因。`buildBaseUrl` 会先清空 hash，再剥 `/2` 后缀，基址仍为 `/photo/{id}`。

## 三、改动

`src/sites/defs/xchina.ts`：

```ts
followPagesUntilEmpty: true,            // 新增：标题与分页链接都拿不到总页数 → 顺序翻页
titleStrip: [                            // 新增一条
  { source: '\\s*-\\s*第\\s*\\d+\\s*页\\s*' },
  ...
]
```

- `followPagesUntilEmpty`：抓取循环上限提升到 40 页，靠「连续 3 页无图」或「连续 3 页无新图」提前停止（与 knit.bid / 8se.me 同一机制）
- `maxPagePattern` 保留，用于兼容旧格式「潼潼 (2/34)」；命中时按旧格式走
- `titleStrip` 增加「- 第 N 页」清理，避免第 2 页标题进入文件夹名

## 四、验证

- `npm run typecheck`：通过
- `npm run build`：通过，当前版本 **v0.2.50**

## 五、用户实测清单

1. `chrome://extensions` 刷新扩展（必须）
2. 抓同一个 xchina 相册（`/photo/6ab7845e39edf`）
3. 看日志面板：
   - 应出现 `启用顺序翻页（分页总数不可测）`，`detected` 可能为 1
   - 结束时 `相册全子页抓取完成` 中 `pages` 应为实际页数（该相册标题显示 34 页），`unique` 明显大于 30
4. 若日志出现 HTTP 404 / 请求失败中断：说明顺序翻页翻过了实际页数（xchina 超出页数会报错而不是返回空页）→ 把日志贴给我，下一步给顺序翻页加「请求失败即停止」容错（属抓取流程改动，需单独确认）

## 六、已知风险

- **超页行为未验证**：顺序翻页最多尝试 40 页。若 xchina 对超出实际页数的 URL 返回 404，`getHtml` 抛错会中断整次抓取。这是本轮最可能出问题的点，要靠实测日志确认。
- 若该相册超过 40 页，会被上限截断（与 knit.bid 一致）。
