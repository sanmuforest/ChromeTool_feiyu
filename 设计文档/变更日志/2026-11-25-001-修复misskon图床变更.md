# 2026-11-25-001 修复 misskon 图床变更导致解析 0 张

> 版本：**v0.2.83** ｜ 类型：站点适配跟进（图床域名变更）
> 触发：用户报告 misskon 相册「多图抓取失败」

## 一、日志解读

```
首页解析 0 张，诊断信息 { hasContainer: true, imgTags: 17, htmlLen: 81610, site: misskon }
相册全子页抓取完成 { maxPage: 40, scanned: 0, unique: 0 }
```

三个数字组合非常说明问题：

| 指标 | 值 | 含义 |
|------|-----|------|
| `hasContainer` | **true** | 正文容器 `article.post-listing` **匹配成功** |
| `imgTags` | **17** | 页面里**确实有图片** |
| `scanned` | **0** | 但一张都没被收录 |

**容器对了、图也存在、结果却是 0** —— 这说明图片在**收录阶段被过滤掉了**。
在引擎的过滤链里，最可能的就是图床白名单 `imageOnlyHosts`。

## 二、根因：图床域名换了

抓取真实页面，统计容器内所有图片 URL 的域名：

```
lux.mrcong.com            : 10   ← 正文图真实所在
vertigovitalitywieldable.com : 1   （广告 js）
a.magsrv.com              : 1      （广告 js）
tez.misskon.com           : 0      ← 原定义的白名单域名，已完全不用
```

而当时的定义是：

```ts
imageOnlyHosts: ['tez.misskon.com'],   // ← 全部正文图都被这行过滤掉了
```

页面 p1 / p2 / p6 三页统计 `tez.misskon.com` 均为 **0 次**，确认该站已把正文图整体迁到
`lux.mrcong.com`（mrcong 系图床）。

图片本体可正常下载：`HTTP 200`，`117.4 KB`，`image/webp`。

## 三、改动（`src/sites/defs/misskon.ts`）

```ts
// 2026-11-25：正文图迁到 lux.mrcong.com，保留旧域名做兼容
imageOnlyHosts: ['lux.mrcong.com', 'tez.misskon.com'],
```

保留 `tez.misskon.com` 是因为老相册可能仍指向旧图床，加上不影响正确性
（容器已限定 `article.post-listing`，广告脚本非图片扩展名会被引擎跳过）。

## 六、沉淀：一个可复用的排查判据

遇到「抓 0 张」时，先看日志里这三个数的组合：

| `hasContainer` | `imgTags` | `scanned` | 结论 |
|---|---|---|---|
| **false** | 任意 | 0 | 容器 class 变了 → 改 `container` |
| **true** | **0** | 0 | 页面真没图（SPA 空壳 / 需登录）→ 考虑 DOM 通道 |
| **true** | **>0** | **0** | **图片被过滤链拦掉** → 优先查 `imageOnlyHosts` / `imagePathPattern` / `imageTagPattern` |

本次就是第三种：容器命中、有图、但白名单过期。

图床域名变更在这类站里很常见（misskon 从 `tez.misskon.com` 换到 `lux.mrcong.com`），
所以 `imageOnlyHosts` 是站点定义里**最容易过期**的字段。
