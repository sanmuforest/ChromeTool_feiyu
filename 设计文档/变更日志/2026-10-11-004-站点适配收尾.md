## 一、ilovexs 抓 0 张的真正根因（一行之差）

| | 内容 |
|---|---|
| 定义 | `container: { tag: 'div', className: 'image-gallery' }` |
| 实测 HTML | `<section class="image-gallery" aria-label="… gallery">` |

**容器标签是 `<section>`，定义写的是 `div`** → 容器匹配失败 → 解析 0 张。

**修复**：`tag: 'section'`。用真实 HTML 复验：**0 → 40 张**（与页面 meta「Includes 40 media items」完全一致）。

> 此前把该站列为「抓 0 张，疑似结果该过滤」的悬案，至此定性为**定义笔误**，与过滤逻辑无关。

## 二、通用缺陷：`extractContainerBlock` 硬编码只数 `<div>`

修复 ilovexs 后解析出 **56 张**，比 meta 声明的 40 张多 16 张 —— 多出的全是 `class="album-card-image"` 的**相关推荐封面**（`reiobox.top` / `karubox.top` / `fujibox.top`）。

根因：

```ts
let depth = 1
const scan = /<div[\s>]|<\/div>/g      // ← 只统计 <div> 的嵌套深度
```

容器是 `<section>` 时，闭合标签 `</section>` **不被识别** → 深度永不归零 → 函数走到 `return html.slice(i)` → **一直截取到 HTML 末尾**，把容器之后的推荐区一并吞入。

**修复**（通用）：深度扫描改为按**容器实际标签**动态构造：

```ts
function extractContainerBlock(html, openTag, tag = 'div') { … }
const closeTag = `</${tag}>`
const scan = new RegExp(`<${tag}[\\s>]|${closeTag}`, 'g')
```

调用处传入 `site.def.container.tag`。对 `<div>` 容器（其余 8 个站）行为完全不变。
