# 2026-10-10-010 通用解析器补封面提取（聚合搜索无预览图）

> 版本：**v0.2.25** ｜ 类型：通用缺口修复
> 触发：用户反馈「knit 的聚合搜索没有抓取到封面图」

## 根因

聚合搜索结果的封面来自解析器返回的 `coverUrl`。各专用解析器（buondua / jrants / pixibb / kaizty / rrwsh）都会提取封面，但**通用解析器 `parseSitePostLinks`（`generic-post-links`）在设计上就不提取** —— 代码注释原文：

> 标题：a title 属性 → a 文本 → 附近文本；**封面不提取（专用解析器负责）**

而下列站点**没有专用解析器**，因此它们的聚合搜索结果**全部没有预览图**：

| 站点 | 状态 |
|------|------|
| knitbid | 本次反馈的站点 |
| phimvuspot | 同样受影响 |
| ilovexs | 同样受影响 |
| cangcuc | 同样受影响（该站域名已失效，暂不体现） |

## 改动（`src/sites/parsers.ts`）

在 `parseSitePostLinks` 内新增封面提取：

1. 卡片常见写法是 `<a href="文章"><img src="封面"></a>` → 取该链接**之后 1500 字符内的首个 `<img>`**（支持 `src` / `data-src` / `data-lazy-src`）
2. **过滤干扰项**：静态资源后缀（`.js/.css/.svg/.ico`）与 `favicon|logo|avatar|sprite|placeholder|blank|loading` 特征
3. 相对路径按页面基址解析为绝对 URL
4. 同 URL 后到者补齐：原逻辑只补标题，现**同时补封面**（同一文章常有「封面 a + 标题 a」两个链接）

## 验证（真实搜索结果 HTML 跑编译后引擎）

```
search-jvid   : 结果 16 | 有封面 16
search-jvid-p2: 结果 16 | 有封面 16
封面形如 https://xx.knit.bid/static/images/2024/07/20/{相册名}/{hash}.jpg
```

- 封面覆盖 **16/16（100%）**，且均为该站同域的真实相册封面 ✓
- `npm run typecheck`：EXIT=0；`npm run build`：通过（v0.2.25）

## 用户实测清单

1. 重载 `dist/`（确认徽标 **v0.2.25**）
2. 多页图站 → 聚合搜索 → 勾 **knitbid** → 搜一个词
3. 预期：结果卡片出现**封面预览图**（此前为空白占位）
4. 顺带验证同批受益的站点：**phimvuspot / ilovexs** 的搜索结果同样应有封面
5. 回归：buondua / hitxhot / kaizty / jrants / pixibb 的封面行为不变（它们走各自的专用解析器）

## 备注

- 该缺口是「通用解析器」的设计取舍（把封面交给专用解析器），但在站点适配变轻量之后（新站普遍直接用通用解析器），这个取舍反而成了默认缺陷 → 现已补齐
- 封面是**启发式提取**（取链接附近首个图片）：极少数卡片可能取到同卡片的其它图，不影响可读性；若某站封面明显不对，可为其写专用解析器或调整该站容器
