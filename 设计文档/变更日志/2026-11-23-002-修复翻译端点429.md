# 2026-11-23-002 修复相册名中文化失效（Google 翻译端点长期 429）

> 版本：**v0.2.82** ｜ 类型：缺陷修复（影响所有英文标题站点）
> 触发：用户反馈 eporner 的多图打包下载「没有使用网页翻译后的命名，而是直接用的原英文名」

## 一、诊断：不是没实现，是端点被限流后静默降级

先说结论：插件**有**「相册名中文化」功能，而且**直接贴 URL 抓取也会调用**它。

链路（`src/grabber/view-buondua.ts`）：

```
BD_FETCH_ALBUM 返回清理后的标题
  → const name = await localizeName(res.name ?? url)      // 第 326 行，确实调用了
  → lastAlbumFolder = buildBuonduaFolderName(name, url)
  → 「打包」/「下载选中」都用 getFolderName() = lastAlbumFolder
```

`#bd-translate` 复选框**默认勾选**，提示语也写明「文件夹名与图片名前缀一起生效」。

**真正的原因**：`src/lib/translate.ts` 用的 Google 免费端点被限流。

实测（间隔 5 秒连试 3 次）：

| 端点 | 结果 |
|------|------|
| `translate.googleapis.com/translate_a/single?client=gtx`（原用） | **HTTP 429** ×3（直连与代理均如此） |
| `translate.googleapis.com/translate_a/t?client=gtx` | **HTTP 429** |
| **`clients5.google.com/translate_a/t?client=dict-chrome-ex`** | **HTTP 200** → `[["穿丝袜的女人拍照---4","en"]]` |
| 对照：`google.com/generate_204` | HTTP 204（网络本身正常） |

而本模块的设计原则是「任何失败一律回退原文，绝不影响抓取主流程」——
所以 429 被静默吞掉，用户侧表现为「翻译功能像是没生效」，日志里也没有可查的线索。

## 二、改动（`src/lib/translate.ts`）

### 1. 多端点回退

```ts
const ENDPOINTS = [
  'https://clients5.google.com/translate_a/t?client=dict-chrome-ex&sl=auto&tl=zh-CN&q=',  // 实测可用
  'https://translate.googleapis.com/translate_a/single?client=gtx&sl=auto&tl=zh-CN&dt=t&q=', // 备用
]
```

`requestTranslate()` 改为**按序尝试**，任一成功即用。单个端点被限流不再导致整体失效。

### 2. 兼容两种响应格式

两个端点的 JSON 结构不同，新增 `parseTranslatePayload()` 统一解析：

| 端点 | 结构 | 判定 |
|------|------|------|
| `clients5…dict-chrome-ex` | `[["译文","en"]]` | `data[0][0]` 是 **string** |
| `translate_a/single?client=gtx` | `[[["译文","原文",null,null,10]],null,"en"]` | `data[0][0]` 是 **array**，需按段拼接 |

### 3. 失败可观测

原来所有端点失败只打 `debug`，用户查不到原因。改为 `warn`：

```
翻译无结果（端点限流/不可用），本次回退原文 { source: "Women in stockings..." }
```

## 五、用户实测清单

1. **刷新扩展**（v0.2.82）
2. 打开 eporner 相册 → 多页图站 → 抓取
3. 预期：
   - 抓取页标题、下载文件夹名、图片名前缀**都是中文**
   - 日志出现 `[translate] 相册标题已翻译 { source, translated }`
4. 若仍为英文，请贴日志里 `[translate]` 开头的行 —— 现在失败会有 `warn` 明示原因

## 六、影响面

**全局修复**：所有「标题为英文」的站点都受益（不止 eporner）。

- 中文标题站点：`HAS_CJK` 判定直接跳过翻译，行为不变
- 翻译开关关闭：行为不变
- 端点全挂：仍回退原文（设计如此），但现在会留下 warn 日志

## 七、沉淀

- **「功能像没生效」先查依赖的外部端点连通性**，不要一上来翻业务代码。
  本次从「用户说没翻译」到「端点 429」只用了两次探测。
- **静默降级必须有可观测痕迹**：把「失败回退原文」的日志从 debug 提到 warn，
  否则同一个问题会被反复报告而每次都查不到根因。
- 免费翻译端点会不定期限流，**多端点回退**是必要的韧性设计。
