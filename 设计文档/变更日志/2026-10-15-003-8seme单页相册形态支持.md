# 2026-10-15-003 8se.me 支持单页相册形态（分页自适应 + 标题规则拆分）

> 版本：**v0.2.37** ｜ 类型：Bug 修复（第二种相册形态）
> 触发：用户 v0.2.36 实测另一个相册，抓取 404

## 一、日志现象

```
会话: folderName "瑄瑄&依依 - 國模套圖 - 各國其他套圖 - 8色人體攝影"     ← 标题结尾是站名，无页码
URL : https://tw.8se.me/photo/id-6ab82e0dab417.html                    ← .html 结尾，无 /2.html
[warn] 页面抓取第 1 次失败 { error: "HTTP 404（…/id-6ab82e0dab417.html/1.html）" }
[info] 全子页抓取结果 { count: 0 }
```

## 二、根因：该站有**两种相册 URL 形态**

| 形态 | 例子 | 分页 |
|------|------|------|
| 多页 | `/photo/id-6ab304a17337d/2.html` | `/1.html`、`/2.html` … |
| **单页** | `/photo/id-6ab82e0dab417.html` | **本身即全部内容**，无分页 |

`html-from-1` 会无条件拼 `{base}1.html` → 单页形态被拼成 `…/id-xxx.html/1.html` → 404。

**同时暴露第二个问题**：标题清理规则要求「`- 8色人體攝影 - 第 N 頁`」整体结尾，而单页相册标题结尾只有站名（无页码段）→ 站名没被剥离（`folderName` 里可见）。

## 三、改动

| # | 改动 | 说明 |
|---|------|------|
| 1 | 新增分页方式 **`html-auto`** | 基址以 `.html` 结尾 = 单页相册 → `pageUrl` 恒返回基址；否则按 `{base}N.html` 分页。**后续页返回同一基址**（而非制造 404），由既有的「连续页无新图」检测自然停止，避免 404 中断整轮抓取 |
| 2 | 首屏 URL 判断同步加入 `html-auto` | `fetchAlbumAllPages` 的 `firstPageUrl` 分支 |
| 3 | `titleStrip` 拆成**两条按序执行** | ① 去尾部 `- 第 N 頁`（多页相册）② 去尾部 `- 8色人體攝影`（两种形态都有）。`buildCleanTitle` 本就是按数组顺序 replace，无需引擎改动 |
| 4 | `defs/se8.ts` | `pagination` 由 `html-from-1` 改为 `html-auto` |
