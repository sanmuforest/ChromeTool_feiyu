# 2026-08-14-100 聚合搜索修复：去除外层多余滚动窗口（嵌套滚动截断）

## 背景（用户反馈）

实测 v0.1.19：各个网站的独立显示窗**外面还套了一层多余的窗口**，导致显示不完全（站点窗口 460px 高，但被外层 340px 视口截断，需要两层滚动才能看到全部内容）。

## 根因

聚合搜索列表元素是 `<div class="bd-link-list bd-search-list">`，**继承了共享类 `.bd-link-list` 的 `max-height: 340px; overflow-y: auto`**（该样式原为推荐/其他面板的链接列表设计，1259-1266 行）。改造为「每站独立窗口」后形成**嵌套滚动**：

```
.bd-link-list（外层：340px 高 + 滚动） ← 多余的窗口
  └─ .bd-search-site-block × N（每站 460px 高 + 独立滚动）← 显示不全
```

## 本次改动

| 文件 | 改动 |
|------|------|
| `src/grabber/grabber.css` | `.bd-search-list` 覆盖共享类限制：`max-height: none; overflow: visible`——外层不再截断/滚动，站点独立窗口完整显示，页面由 `.adapters-view` 自然滚动 |

## 行为说明

- 修复后层级：适配页整体滚动（.adapters-view）+ 每站窗口内部独立滚动，**不再有中间层滚动容器**
- 推荐/其他面板的 `.bd-link-list`（340px 列表）样式不受影响（未改动该规则，仅搜索面板覆盖）

## 验证方式（用户实测，红线 3）

1. 版本徽标核对（**v0.1.20**）后 `chrome://extensions` 重新加载 dist/
2. 聚合搜索 → 关键词 → 各站独立窗口应**完整显示**（无外层截断、无嵌套滚动条）；每个窗口内部独立滚动
3. 推荐链接/其他链接面板回归（其 340px 列表应保持原样）

## 回归检查（红线 1）

- 改动仅 `.bd-search-list` 两条覆盖属性；`.bd-link-list` 原规则未动（推荐/其他面板不受影响）
- 结论：无相邻模块受损
