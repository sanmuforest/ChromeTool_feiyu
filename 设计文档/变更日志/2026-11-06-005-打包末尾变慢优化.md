# 2026-11-06-005 打包末尾变慢：请求去重 + 退避收敛

> 版本：**v0.2.64** ｜ 类型：性能优化（v0.2.63 并发修复后的残余瓶颈）
> 触发：用户反馈「下载内容现在正确了，但打包下载最后几张依然非常慢」

## 一、日志时间线还原（59 张的相册）

```
01:39:42  下载任务启动 total=59
01:39:46 ~ 01:40:16  正常取字节（约 30 秒处理 55 张）✓
01:40:54  4 张 HTTP 503 出现                    ← 开始卡
01:41:15 ~ 01:41:33  大量 AbortError            ← 在途请求被中断
01:41:48  imgbb background 抓取失败，降级直连
01:42:55  打包下载完成 ok=58 / total=59
```

**前 1.5 分钟处理 55 张，后 2 分钟只处理 4 张** —— 时间几乎全耗在少数失败图的重试上。

## 二、三个残余原因

| # | 原因 | 证据 |
|---|------|------|
| 1 | **503 失败图的退避重试过长** | 3 次 × (800+1600+3200) = **5.6 秒/张**，4～10 张就是半分钟以上 |
| 2 | **同一 URL 被重复取字节** | 日志 `01:40:15` 同一 URL 连续出现两条「兜底取字节成功」→ 列表重建时又发了一次请求，白跑一遍 |
| 3 | **Service Worker 生命周期导致 AbortError** | `AbortError: signal is aborted without reason` 集中出现，间隔 18 秒而非 40 秒超时 → MV3 SW 闲置被终止，在途 fetch 全部中断，只能重来 |

## 三、改动

| # | 文件 | 改动 | 期望效果 |
|---|------|------|----------|
| 1 | `image-grab-view.ts` | 新增 `inflightBytes: Map<url, Promise<...>>` + `fetchBytesOnce()`，同一 URL 的并发取字节**共享同一个 Promise** | 消除重复请求（日志中的二连发） |
| 2 | `image-grab-view.ts` | `recoverThumb` 改为走 `fetchBytesOnce`，并复用同一个 object URL | 请求数下降，显示逻辑不变 |
| 3 | `downloader.ts` | 退避基数抽成 `THROTTLE_BACKOFF_BASE_MS = 500`，序列 800/1600/3200 → **500/1000/2000**（累计 5.6s → 3.5s） | 失败图等待时间降 37% |

**未改**：`RETRY_THROTTLE_MAX` 仍为 3 次（保证成功率），`HOST_THROTTLE_GAP_MS` 仍为 500ms。

## 四、验证

- `npm run typecheck`：EXIT=0
- 引用核对：`inflightBytes` 在 100/106/130/131 行正确使用；`THROTTLE_BACKOFF_BASE_MS` 在 25/101 行生效
- 逻辑审阅：
  - `fetchBytesOnce` 先查 `blobCache`，命中直接返回；再查 `inflightBytes`，有在途则复用；`finally` 中清理，避免 Map 增长
  - 失败时返回 `null` 且不写入缓存，下次仍可重试
  - object URL 每个 URL 只创建一次，两个调用方共享

- `npm run build`：通过（v0.2.64）

## 六、仍未处理的两项（需要你决策）

| 项 | 现状 | 取舍 |
|----|------|------|
| `startOne` 对 imgbb 仍先试源页注入 | 每张白跑一次 CORS 失败（日志里 `imgbb 源页注入失败，降级 background fetch`） | 跳过可省一次往返，但 v0.2.11 曾指出源页注入是「防 180 降级」的唯一通道 —— 虽然本次实测 background 已能拿到原图，仍建议单独立项确认 |
| imgbb 用 base64 `data:` URL 交给 downloads | 每张约 133KB 字符串 | 改 blob URL 可降内存，但涉及 SW 生命周期下的 URL 存活，风险较高 |

**建议**：先验证本次效果。若尾部仍慢，下一步优先做「打包前对已知失败 URL 快速跳过、结束后单独重试」的结构调整，而不是继续压退避时间。
