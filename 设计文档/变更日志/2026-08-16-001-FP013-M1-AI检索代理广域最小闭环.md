## 修复记录 2（同日晚，用户实测反馈「下一批死锁 + 无关结果多」）

- **问题 1a**：请求 5 次（第一批）后结果不再增加，点「下一批」报「上一批处理中，请稍后」
  - 根因：view 的 busy 标志只在 done/error 复位，而「批次完成」走 progress 推送 → 死锁（done 需点下一批才到）
  - 改动：`view-ai.ts` progress 到达即 busy=false，状态栏提示「点下一批继续」
- **问题 1b**：取消不及时
  - 根因：cancel 只置 cancelled 标志，在途 fetch 要等 20s 超时
  - 改动：`ai-search-service.ts` 增加 cancelCtrl（AbortController），cancel 时 abort 在途 fetch；AbortError 静默不重试
- **问题 2**：结果大量无关
  - 根因：网页查询「关键词 域名」时 Bing 把域名当普通词，混入其他站结果；过滤只黑名单+加分，无 host 强校验
  - 改动：`ai-filter.ts` 增加 hostMatches（子域/主域双向）限定域名强校验——带 hitDomain 的查询结果 host 不匹配直接丢弃；`ai-strategy.ts` 黑名单扩充（社交/聚合/图库/视频/电商站）
- **验证**：重载扩展后 AI 检索 → 第一批后「下一批」可点；取消立即生效；结果应只剩限定域名站内页

## 修复记录 3（同日晚，用户实测反馈 CSP 违规 + TypeError）

- **问题 1**：CSP 违规（`Executing inline event handler violates... script-src 'self'`）
  - 根因：`view-ai.ts` 封面缩略图用了内联 `onerror="..."` 事件处理器，MV3 扩展页面 CSP 禁止内联脚本
  - 改动：改为 `img.addEventListener('error', ...)`（全量排查无其他内联事件）
- **问题 2**：`Uncaught (in promise) TypeError: Cannot read properties of null (reading 'queryIndex')`
  - 根因：MV3 SW 休眠/重启后 AiSearchService 实例重建，session=null；此时点「取消」→ cancel() → pushProgress() 访问 session.queryIndex 抛错（void 未捕获 → unhandled rejection）
  - 改动：① batch() session 为 null 时推送 error「会话已失效，请重新开始」（防静默）② cancel() 无会话静默忽略 ③ pushProgress() 判空防御
- **验证**：重载扩展 → AI 检索正常；检索完等十几秒（SW 休眠）→ 点下一批应提示「会话已失效」，点取消无报错；封面缩略图加载失败时隐藏无 CSP 报错

## 验证方式（红线 3：用户实测）

1. `chrome://extensions` → 开发者模式 → 加载已解压 → 选 `dist/`（确认徽标 v0.2.0）
2. 打开任意网页 → 插件图标 → 多页图站 → **AI 检索** 子标签
3. 输入关键词（如 `amateur`）→ 「AI 检索」
4. 预期：策略区显示变体与域名候选 → 进度区显示查询/请求/结果计数 → 结果列表出现 Bing 网页结果（点击可打开相册）
5. 勾选「Bing 图片通道」再试：结果应含封面缩略图
6. 点「下一批」继续检索；点「取消」停止
7. 日志面板贴 `[ai-search]` 前缀日志定位问题
