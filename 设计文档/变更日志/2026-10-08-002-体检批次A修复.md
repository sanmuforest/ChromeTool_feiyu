# 2026-10-08-002 多图站适配体检批次 A 修复（P0-1 / P0-2 / P0-3）

> 版本：**v0.2.13** ｜ 来源：`设计文档/调研报告/2026-10-08-001-多图站适配体检.md`

## 修复清单

### P0-1 `google-sitesearch` 的 `site:www.{域名}` 过窄

| 项 | 内容 |
|----|------|
| 文件 | `src/sites/engine.ts`（`buildSearchUrl` 的 `google-sitesearch` 分支） |
| 问题 | FP-022 把 `sitesearch=www.xxx` 换成 `site:` 语法时保留了 `www.` 前缀 → 查询被限死在 www 子域；与 `googleSearchConfig`（用裸主域）自相矛盾；症状是「搜索无结果但不报错」 |
| 修复 | 改为 `site:${primaryHostOf(def)}`（裸主域），与 Google 全站模式一致 |
| 影响 | hitxhot / kaizty（唯二使用该搜索类型的定义）。`site:域` 天然覆盖 www 及所有子域 → 只会**变宽**，不会漏 |
| 行为变更 | 有（有意）：查询目标域名由 `www.hitxhot.org` → `hitxhot.org` |

### P0-2 消除视图侧 `site.id` 硬编码

| 项 | 内容 |
|----|------|
| 文件 | `src/sites/schema.ts`（新增 `FolderNameRuleName` 类型与 `folderNameRule` 字段）、`defs/jrants.ts`、`defs/pixibb.ts`、`src/grabber/view-buondua.ts` |
| 问题 | `buildBuonduaFolderName` 仍用 `site.id === 'jrants' / 'pixibb'` 路由，违反「模块边界」禁止事项第 6 条（FP-018 只收拢了 service 侧） |
| 修复 | 定义新增 `folderNameRule`（缺省 `'buondua'`）；jrants → `'jrants'`、pixibb → `'pixibb'`；视图改为读定义字段 |
| 行为变更 | **无**（字段值与原先的 id 判断一一对应，命名结果逐字一致） |

### P0-3 列表浏览支持手动指定分页方式

| 项 | 内容 |
|----|------|
| 文件 | `src/sites/engine.ts`（`listPageUrl` 增加 `pageKindOverride`）、`src/lib/messages.ts`（`BD_FETCH_LIST` 增加可选 `pageKind`）、`src/background/background.ts`、`src/background/buondua-service.ts`（`fetchSiteList` 增加 `pageKind` 参数）、`src/grabber/view-buondua.ts`（新增下拉） |
| 问题 | 分页方式只能靠派生（`jrants`/`cangcuc` 派生成 `/page/N`，而它们站内搜索实际用 `/page/N/`），用户在界面无法修正 → 与 FP-023「界面可调整、不必等发版」的承诺不符 |
| 修复 | 「列表浏览」行新增「分页」下拉：自动 / `?page=N` / `/page/N/` / `/page/N`；状态栏显示本次使用的分页方式 |
| 行为变更 | 无（默认「自动」＝原逻辑） |
