> 版本：**v0.2.14** ｜ 来源：`设计文档/调研报告/2026-10-08-001-多图站适配体检.md` 的 P1-2
> 触发：v0.2.13 实测日志显示 pixibb / ilovexs 的 Google 结果抓取 **0 张**

## 实测证据（v0.2.13 日志）

```
pixibb : 相册全子页抓取完成 { scanned: 0, unique: 0, maxPage: 1,
          title: "Amau Kisumi (天羽希純) 18+: Complete Video & Photo Sets | PixiBB",
          url: "https://hub.pixibb.com/model/amau-kisumi/" }
ilovexs: 相册全子页抓取完成 { scanned: 0, unique: 0, maxPage: 1,
          title: "Cosplay 日本性感萝莉Byoru – Bremerton Pillowed Counselling",
          url: "https://ilovexs.com/post_id/2034555525838192641/" }
```

两站均**成功抓到页面并解析出标题**，但图片数为 0 —— 说明问题不在网络层，而在「返回的链接不是相册页」或「容器不匹配」。

- **pixibb**：Google 返回的是 `/model/amau-kisumi/`（**模特聚合页**，非单相册）→ 抓取必然 0 张。根因：pixibb 无 `searchAlbumPath`，Google 结果**不做任何路径过滤**
- **ilovexs**：返回 `/post_id/{id}/`，容器 `image-gallery` 未提取到图片。性质待确认（图集页=容器过时；视频/文字帖=应过滤）

## 改动

| 文件 | 改动 |
|------|------|
| `src/sites/schema.ts` | 新增 `SiteDef.searchAlbumPattern`（`RegexSpec`）与编译产物 `GallerySiteConfig.searchAlbumPattern`（`RegExp`）；与 `searchAlbumPath` 同时设置时为**「且」**关系 |
| `src/sites/engine.ts` | `compileSite` 编译该正则 |
| `src/sites/parsers.ts` | `cleanGoogleResult`（Google/搜索通道）与 `parseListPageLinks`（列表浏览）都应用正则过滤 |
| `src/sites/defs/pixibb.ts` | 配 `searchAlbumPattern: { source: '-photos', flags: 'i' }` —— pixibb 相册 URL 形如 `/{slug}-{N}-photos/`，`/model/`、`/tag/` 等会被自动剔除 |
| `src/background/buondua-service.ts` | **诊断增强**：抓取首页解析 0 张时记录 `hasContainer`（容器正则是否命中）/ `htmlLen` / `imgTags`（页面 img 标签数），用于区分「容器 class 已变」与「页面本身无图片」 |

## 设计说明

- **不用 `searchAlbumPath` 的原因**：pixibb / jrants / ilovexs 的相册 URL **无固定路径前缀**（pixibb 在子域根路径、jrants 在根路径 `/20260101.html`），前缀匹配无法表达，必须用正则
- **两字段并存语义**：同时配置时需**都满足**（先前缀收窄、再正则精确），便于将来「路径 + 形态」双重约束
- **列表浏览同样受益**：`listPages[0].albumPath` 优先；未配时退化为站点级 `searchAlbumPath` / `searchAlbumPattern`
