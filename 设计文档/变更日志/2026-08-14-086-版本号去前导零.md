# 2026-08-14-086 版本号格式修正：去除前导零（Chrome 兼容）

## 背景（用户反馈）

加载 dist/ 报错，manifest 版本为 `0.1.004`。

## 根因

**Chrome 扩展版本号禁止前导零**：每段必须是 0-65535 整数，`004` 会被拒绝加载（`Invalid value for 'version'`）。0.1.001/002/003/004 均违反该规则（此前版本未被实际重新加载过，故未暴露）。

## 本次改动（用户确认：彻底放弃补零格式）

| 文件 | 改动 |
|------|------|
| `manifest.json` | version `0.1.004` → **`0.1.4`**（004 的合法形式，Chrome 可加载） |
| `package.json` | 同步 `0.1.4` |
| `AGENTS.md` | 版本规则更新：禁止前导零，格式 v0.1.N，`npm run bump` 末位 +1（4→5→…→10） |
| `scripts/bump-version.mjs` | **无需改动**（padStart 自适应位数：0.1.4→0.1.5，9→10 正常） |

- 徽标显示 `v0.1.4`（读取 manifest 原样显示，无需改代码）

## 验证方式

1. `npm run typecheck` + `npm run build` 通过；dist/manifest.json version = 0.1.4
2. Chrome 加载 dist/ → **不再报错**，扩展列表显示「肥鱼抓兔 - 图片下载器 v0.1.4」

## 回归检查（红线 1）

- 仅版本号字符串改动，无代码逻辑变更；bump 脚本已验算兼容
- 结论：无相邻模块受损
