# 2026-10-11-005 cangcuc 站点废弃归档

> 版本：**v0.2.30** ｜ 类型：站点下线（用户决定）
> 触发：用户决定「cangcuc 放弃」

## 一、决定与背景

`cangcuc.com` 自 2026-10-07 起域名 DNS 失效（`getaddrinfo ENOTFOUND`），多次维护节点均无新域名线索（FP-021、变更日志 2026-10-07-004/005/006/007 均记录「待用户提供新域名」）。本轮用户明确决定**放弃适配**。

## 二、处理方式（沿用 freeimage 废弃先例：代码移除 + 归档留存）

| 项 | 处理 |
|----|------|
| 定义文件 | `src/sites/defs/cangcuc.ts` → 复制到 `归档/cangcuc-2026-10-11-废弃归档/`，并附 `README.md` 记录原定义要点（容器 / 图床形态 / 标题清理 / 站内搜索），供将来若该站以新域名复活时参考；源文件删除 |
| 注册表 | `src/sites/defs/index.ts` 移除 import 与数组项；顶部补充「废弃站点处理约定」 |
| 站点列表 | `src/grabber/view-buondua.ts` 的站内搜索组由 `['buondua','rrwsh','cangcuc','knitbid','imgbb']` 改为 `['buondua','rrwsh','knitbid','imgbb']`（**必须同步**，否则会渲染出无定义的站点项） |
| 注释更正 | `schema.ts`（`single` 分页举例）、`parsers.ts`（通用解析器封面受影响站点列表）、`buondua-service.ts`（Google 组站点举例）三处去掉 cangcuc 提及，避免误导 |

**未改动**：历史文档（FP-014/FP-018/FP-021、体检报告、既有变更日志）**保持原样** —— 它们是当时事实的记录，不做事后改写。
