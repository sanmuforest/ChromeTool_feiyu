# 2026-11-06-001 图床 429 限流：退避重试 + 自适应限速

> 版本：**v0.2.60** ｜ 类型：取字节通道缺陷修复
> 触发：用户反馈「imgbb 出现很多相册抓取失败」，附 500 条日志（v0.2.59）

## 一、日志解读：失败的不是 imgbb

日志里 **imgbb 相册抓取全部成功**：

```
相册全量抓取完成 { count: 53,  name: "anna8kun",   pages: 2 }   ✓
相册全量抓取完成 { count: 134, name: "LuckyQL777", pages: 3 }   ✓
```

真正大量失败的是**打包取字节**，且失败图全部来自 `i0.wp.com/cdn1.thismore.fun/...`（**kaizty 的图床**，WordPress Photon）：

```
GRAB_FETCH_IMAGE 源页注入失败，降级 background  { srcError: "页面内 fetch 失败：TypeError: Failed to fetch" }
GRAB_FETCH_IMAGE 抓取失败                      { error: "Error: HTTP 429" }
打包下载完成 { ok: 40, total: 60 } / { ok: 59, total: 97 } / { ok: 62, total: 106 }
```

## 二、根因

打包时每张图依次走三条通道：

| 通道 | 对 i0.wp.com 的结果 |
|------|---------------------|
| 扩展页 `fetch(url)` | ✗ 无 CORS 头 → `TypeError: Failed to fetch` |
| 源页注入 fetch | ✗ 同上 |
| 后台 `fetchImageBytes` | ✓ 能通，但**默认 12 并发同打一个 CDN → 429** |

即：每张图先撞两次 CORS，第三次才可能成功，而 12 并发一起打同一 CDN 必然被限流。

**已排除 Referer 因素**（先前的怀疑点）：实测对同一张图分别用

```
Referer: https://imgbb.com/   → HTTP 200
不带 Referer                   → HTTP 200
Referer: https://www.kaizty.com/ → HTTP 200
Referer: https://i0.wp.com/    → HTTP 200
```

四种**全部 200**，说明限流与 Referer 无关，是**并发/频率**问题。

## 三、改动（`src/lib/downloader.ts`）

| # | 改动 | 说明 |
|---|------|------|
| 1 | 429 / 503 **退避重试** | 最多 3 次，间隔 800 → 1600 → 3200 ms |
| 2 | **按图床自适应限速** | 某 host 触发过限流后，同 host 取字节加 500 ms 最小间隔（此后该 host 串行化） |
| 3 | 4xx（非 429/503）**不重试** | 确定性失败立即抛出，避免无谓等待 |
| 4 | 日志改为「图片字节抓取完成 / 取字节受限，退避后重试」 | 原日志文案写死 imgbb，与通用用途不符 |

**关键设计**：限速**只在触发过 429 的 host 上生效** —— 正常图床的打包速度完全不受影响。

## 四、验证

- `npm run typecheck`：EXIT=0
- `npm run build`：通过（v0.2.60）
- 逻辑审阅：非限流 4xx 立即失败；限流/网络错误最多重试 3 次；取消信号仍然生效（`signal` 透传）

## 五、用户实测清单

1. 刷新扩展（**改了 background，必须刷新**）
2. 重新抓 kaizty 的相册（如 `[Twitter收集] Ssssss素素`，9 页 106 张）→ 打包
3. 预期：`ok` 接近 `total`（此前是 62/106）；日志里 `HTTP 429` 大幅减少，可能出现「取字节受限，退避后重试」随后成功
4. 若仍有较多失败，请再贴一次日志 —— 重点看 `ok/total` 比例与是否仍集中在同一图床

## 六、顺带说明（不是本次改动范围）

- **se8.me / xchina.co** 仍然只能用「下载选中」：它们的图床是 **403 + CORS** 双重拒绝，与本次的 **429 限流**是不同问题，退避重试解决不了。**未做改动。**
- 每条失败都会先尝试源页注入（每张图一次 CORS 失败）。可以按 host 缓存「该图床不支持源页注入」以减少无效请求，但这属于额外优化，**未在本次实施**，如需要请另行确认。
