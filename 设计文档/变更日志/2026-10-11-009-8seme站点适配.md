# 2026-10-11-009 8se.me 站点适配完成（整页容器 + 图床白名单方案）

> 版本：**v0.2.34** ｜ 类型：新增站点 + 引擎 2 项通用能力 + 打包兜底
> 触发：用户报告「暂不支持该站点」+「页面没有自动填入」

## 一、两个报告的问题，其实是同一个根因

```ts
// view-buondua.ts 现有逻辑（早就实现了自动填入）
if (sourceUrl && matchGallerySite(sourceUrl)) {   // ← 站点未适配 → 返回 null → 不填
  albumUrlInput.value = sourceUrl
```

自动填入**一直存在**，但前提是「该站点已被适配」。8se.me 没有定义 → 于是同时表现为「暂不支持该站点」与「页面没有自动填入」。补上定义即两者同时解决。

## 二、适配方案：不依赖容器 class

三轮探测确认该站**正文图用 CSS `background-image` 渲染**，`<img>` 里只有站点 logo → 探测的容器候选里**根本不存在正文容器**，无法照常写 `container`。

采用组合方案：

| 项 | 值 | 作用 |
|----|----|------|
| `container` | `{ tag: 'body', className: '' }` | 宽容器（整页），不依赖具体 class |
| `imageOnlyHosts` | `['img.xchina.io']` | **只保留正文图床** → 自动排除 logo（tw.8se.me）与推荐位（upload.xchina.io / xchina.click） |
| `imageThumbFix` | `_\\d+x\\d+\\.webp$` → `.jpg` | 正文的 600 宽预览图还原为原图（与 og:image 同形态） |
| `pagination` | `html-from-1` | `/photo/id-{id}/{N}.html` |
| `baseUrl` | `stripPagePath: 'html'` | `…/2.html` → `…/id-xxx/` |
| `titleStrip` | 去尾部 `- 8色人體攝影 - 第 N 頁` | 文件夹名干净 |
| `followPagesUntilEmpty` + `throttle` | — | 总页数不可测 → 顺序翻页；页间 1.2s |

## 三、引擎新增（2 项通用能力）

| # | 能力 | 说明 |
|---|------|------|
| 1 | **`imageOnlyHosts`** | 定义字段：只保留指定图床的图片。用于「正文图床与站点/推荐位不同」的站 —— 配合宽容器即可精确取图 |
| 2 | **容器 `className` 可为空** | `containerOpen` 在 className 为空时匹配该标签的任意出现（`<body …>`）；此前空 className 会生成无法命中的正则 |

## 四、打包下载兜底（必须一起修）

打包流程对**非 imgbb** 图片走扩展页 `fetch` → 对 8se.me 图床必然 403 → 会静默产出 0 字节文件。

**改为**：先试扩展页直连，失败则回退 `GRAB_FETCH_IMAGE`（源页注入取字节，带 Cookie 穿透反爬）。属通用兜底，其它反爬图床同样受益。

## 七、已知风险 / 待实测确认

- **第 1 页是否为 `1.html`**：入口给的是 `2.html`，我按同形态取 `1.html`。若实际第 1 页是不带数字的 `…/id-xxx/`，需把 `pagination.kind` 改为 `html-from-2`（一行改动，日志会显示第 1 页解析 0 张）
- **单页张数**：`og:image` 显示 `00014`、背景图样本 `00019`~`00025`，推测每页十余张；顺序翻页会翻到无新图为止
- **「下载选中」通道**：走 `chrome.downloads.download({url})`（浏览器下载栈，带 Cookie），对该图床是否放行需实测；若失败，需改为经源页取字节转 blob 下载
