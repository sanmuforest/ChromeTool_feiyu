# 2026-10-15-001 修复 {N}.html 分页站点首屏 404（8se.me 抓取失败根因）

> 版本：**v0.2.35** ｜ 类型：Bug 修复（抓取流程首屏 URL）
> 触发：用户 v0.2.34 实测 8se.me 抓取失败日志

## 一、日志现象

```
[warn]  页面抓取第 1 次失败 { error: "Error: HTTP 404（https://tw.8se.me/photo/id-6ab304a17337d/）" }
[warn]  后台抓取失败，尝试页面内 fetch 降级 "Error: HTTP 404（…同址）"
[error] 全子页抓取失败（含降级）{ error: "Error: Error: HTTP 404", hint: "页面不存在（链接可能已失效）" }
[info]  buondua 全子页抓取结果 { count: 0 }
```

注意失败 URL 是**基址**（`…/id-6ab304a17337d/`，不带 `1.html`）→ 404。降级通道也失败，因为**降级用的还是同一个 URL**。

## 二、根因

抓取流程第一步是「抓基址取标题」：

```ts
const base = site.baseUrlOf(url)
const firstHtml = await getHtml(base)      // ← 抓 base
```

而 8se.me 的基址（不带页码的目录路径）**本身不存在**，第 1 页真实地址是 `…/id-xxx/1.html`（定义已声明 `html-from-1`）。即：**定义里的分页规则没有作用到首屏这一步**。

## 三、修复（`src/background/buondua-service.ts`）

```ts
// 仅 {N}.html 形态改用第一页 URL；其余分页方式继续抓 base
const firstPageUrl = site.def.pagination.kind === 'html-from-1' ? site.pageUrl(base, 1) : base
const firstHtml = await getHtml(firstPageUrl)
```

**为什么限定 `html-from-1`**：其余分页方式（`query` / `path-from-2` / `path-slash-from-2` / `page-path-slash` / `single`）的第 1 页语义就是 base，若统一改成 `pageUrl(base,1)`，`query` 类站点会变成抓 `?page=1`（可能与 base 不同）→ 为避免任何既有站点行为变化，只对该形态生效。

循环内第 1 页仍复用 `firstHtml`，不增加请求。

- 影响面：仅 `html-from-1`（当前仅 8se.me）走新分支；其余 10 个站代码路径不变

## 六、另一个现象说明（非缺陷）

日志里 `解析完成（默认全选）{ count: 32 }` 是**主抓取页（第一个页签）**的结果：内容脚本扫描的是 `<img>`，而该站正文用 CSS 背景渲染、`<img>` 里只有 logo 与推荐图 → 32 张里混有站点图标/推荐位，**不是正文**。

**所以抓 8se.me 请用「多页图站」页签**（走站点定义 + 图床白名单，只取正文）。主抓取页支持该站的 CSS 背景方案属另一个改动（内容脚本扫描器），暂列遗留。
