# 2026-11-11-003 rrwsh 图床变更适配（wp.com → img.ssuu.uk）

> 版本：**v0.2.74** ｜ 类型：站点适配跟进（预防性）
> 触发：用户报告 `dsad.ssuu.uk` 的相册 URL「改结构了」，并提供了探测输出

## 一、先纠正我的一处误判

用户最初给的 URL 是：

```
https://dsad.ssuu.uk/content/28/client-error-get-https-translate-google-com-translate-a-single-client-...html/5
```

我抓取它只得到 **1991 字节 + `Loading...` + 0 个 img**，据此判断「站点改成了 SPA」——**这个判断是错的**。

那串 slug（`client-error-get-https-translate-google-com-...`）是 **Google 翻译服务出错时拼出来的坏链接**，
返回的当然只是空壳。

用户随后提供的正常 URL 探测显示：**页面结构完好，服务端渲染正常**。

## 二、实际变化：只有图床

用 `https://dsad.ssuu.uk/content/10/october-2026-fantia.html` 的探测输出对比：

| 项 | 原来 | 现在 |
|----|------|------|
| 正文容器 | `div.entry-content` | `div.is-layout-constrained.entry-content.wp-block-post-content`（**仍含 `entry-content`**） |
| 图片数 | — | 29 张，正常渲染 |
| **图床** | **`wp.com`** | **`img.ssuu.uk`** |
| img 属性 | — | `src` |
| 分页 | `/content/N/slug.html/N` | 同（用户给的 `/5` 即第 5 页） |

**结论：结构没变，只有图床域名换了。**

## 三、改动（`src/sites/defs/rrwsh.ts`）

```ts
imageHosts: ['wp.com', 'ssuu.uk'],
```

**说明**：新图床的图片都带 `.webp` 扩展名，引擎按扩展名即可识别，`imageHosts` 只对**无扩展名**的图片 URL 生效。所以这个改动是**预防性**的 ——
万一将来出现无扩展名的 URL 也不会被漏掉。

**其余字段全部保持原样**（容器、分页、baseUrl、标题清理、搜索都验证过仍然正确）。

## 五、用户实测清单

1. **刷新扩展**（确认 v0.2.74）
2. 打开 `https://dsad.ssuu.uk/content/10/october-2026-fantia.html` → 多页图站 → 抓取全部子页
3. 预期：抓到 29 张，文件名形如 `026-fantia-4khd.com-001.webp`
4. 有分页的相册（如你给的 `/5`）→ 应能翻完所有页

## 六、遇到「改结构」时的排查顺序（沉淀经验）

1. **先确认 URL 是好的** —— 从页面地址栏复制，不要用转发/翻译服务生成的链接
   （本次教训：翻译错误链接导致误判为 SPA）
2. 用「**探测结构**」看三样：`img` 数量、正文容器父级链、分页链接
3. `img` 数为 0 且内容只有 `Loading...` → 才是真 SPA（此时需要浏览器内提取通道）
4. 图床变了但图片有扩展名 → 引擎通常无需改动
