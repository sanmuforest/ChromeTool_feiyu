# 2026-10-11-002 下载/打包与网格去重保持一致

> 版本：**v0.2.27** ｜ 类型：行为一致性修复（用户已确认）
> 触发：日志显示 `打包下载完成 { ok: 180, total: 180 }` —— 90 张的相册却打包 180 项

## 问题

同一相册抓取两次（各 90 张）后：

| 环节 | 数量 | 说明 |
|------|------|------|
| 网格显示 | 90 张 | 走 `visibleImages()` → 经 `applyDedupe` 去重 |
| 下载 / 打包 | **180 项** | 走 `collectSelectedItems()` → **直接遍历未去重的 `images`** |

即：**开启去重时，网格里去掉的重复图，下载与打包仍会带上** —— 网格与产出不一致（用户看到 90 张，导出 180 个文件）。

## 根因

```ts
// 修复前
for (const img of images) {                    // ← 未去重
  if (selected.has(img.url)) items.push(...)
}
```

## 修复（`src/grabber/image-grab-view.ts`）

```ts
// 修复后：先按选中过滤，再应用去重
const selectedImages = images.filter((img) => selected.has(img.url))
const { kept } = applyDedupe(selectedImages)
const items = kept.map((img) => ({ url: downloadUrlOf(img) }))
```

设计取舍：

- **只应用 `applyDedupe`**，**不引入尺寸筛选 / 小图过滤** —— 避免出现「我没筛它、它却不下」的反直觉行为（用户已确认此方案）
- **先 filter 后 dedupe**：只对「已选中的图」去重，不会出现「选中项被去重掉」的边界问题
- **命名顺序不变**：`Array.filter` 与 `applyDedupe`（按首次出现分组）都保持原顺序 → 编号仍严格等于抓取顺序（遵守 2026-09-29-004 的冻结约定）

## 影响面（用户可见行为变更）

`collectSelectedItems` 是**全部 7 个抓取场景**下载与打包的唯一入口 → 所有场景在「开启去重」时下载数量会与网格一致（重复项不再下载）。

- 未开启去重时行为完全不变
- 关闭去重（界面上可切）即可回到"下载所有选中项"
