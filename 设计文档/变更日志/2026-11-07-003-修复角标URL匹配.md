# 2026-11-07-003 修复角标不显示（URL 键不一致）

> 版本：**v0.2.71** ｜ 类型：缺陷修复
> 触发：用户反馈「进度条正确显示，但是角标依然缺失」

## 一、现象

v0.2.70 修好进度路由后，进度条正常跳动，但缩略图上的下载状态角标**完全不出现**。

## 二、根因：两套 URL 键不是同一个字符串

角标状态推导：

```ts
const doneSet = new Set(job?.doneUrls ?? [])
const state = doneSet.has(url) ? 'ok' : ...     // url = img.url
```

而 background 写入 `doneUrls` 时用的是**下载项 URL**：

```ts
if (!job.doneUrls.includes(active.item.url)) job.doneUrls.push(active.item.url)
// active.item.url 来自 collectSelectedItems()：{ url: downloadUrlOf(img) }
```

`downloadUrlOf(img)` 返回 `img.downloadUrl || img.url` —— 在 imgbb 等站点二者可能不同
（显示 URL ≠ 下载 URL）。于是：

- `doneSet` 里存的是 `downloadUrlOf(img)`
- 查询用的是 `img.url`
- **永远不命中** → 状态恒为 `pending`
- 而 `pending` 在 CSS 里是 `display: none` → **角标永远隐藏**

这正好解释「进度条正常（它只看计数）+ 角标不出现（它靠 URL 匹配）」。

## 三、改动（`src/grabber/image-grab-view.ts`）

| # | 改动 | 说明 |
|---|------|------|
| 1 | 创建角标时记录 `dlBadge.dataset.dlUrl = downloadUrlOf(img)` | 把「下载时实际使用的 URL」存到角标上 |
| 2 | `updateDownloadBadges()` 用 `dlUrl` 比对，并同时兼容 `img.url` | 任一命中即算匹配 |
| 3 | 新增一次性诊断日志「下载角标刷新（诊断）」 | 输出 `badges / doneCount / failCount / sampleBadgeDlUrl / sampleDoneUrl`，可直接比对两个 URL 是否同一字符串 |

## 五、用户实测清单

1. **刷新扩展**（确认 v0.2.71）
2. 抓 imgbb 相册 → 下载选中
3. 预期：
   - 完成的图右下角出现绿色 **✓**
   - 失败的图红色 **!**（可点击单张重试）
4. 若角标**仍然**不出现，请贴日志里的这一行：
   `下载角标刷新（诊断） { badges, doneCount, failCount, sampleBadgeDlUrl, sampleDoneUrl }`
   - 若 `badges: 0` → 说明角标元素根本没建（网格渲染路径问题）
   - 若 `sampleBadgeDlUrl ≠ sampleDoneUrl` → 说明还有第三套 URL 形态
   - 若两个 URL 相同但角标仍不显示 → 转查 CSS 层叠（可能是被其他样式覆盖 `display`）
