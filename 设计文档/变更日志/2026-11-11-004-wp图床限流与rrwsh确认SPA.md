## 二、phimvuspot：`wp.com`（Photon）触发 429 —— 本次已修

```
GRAB_FETCH_IMAGE 抓取失败 { error: "Error: HTTP 429" }
url: https://i0.wp.com/im.thismore.fun/... / https://i1.wp.com/...
```

该站 375 张的相册，抓取时 `i0/i1.wp.com` 大量 429。

### 改动

**`src/lib/downloader.ts`** 图床策略表新增一条：

```ts
{
  re: /^(?:i\d+\.wp\.com|[^.]*\.wp\.com)$/i,
  policy: { concurrency: 4, timeoutMs: 40000, retryMax: 2, backoffBaseMs: 1200 },
}
```

| 参数 | 值 | 依据 |
|------|-----|------|
| 并发 | **4** | Photon 对并发敏感，比 imgbb 的 8 更保守 |
| 超时 | 40000 | 沿用默认，Photon 本身不算慢 |
| 重试 | 2 | 与 imgbb 一致 |
| 退避基数 | 1200ms | 比 imgbb 的 1000 稍长，给限流计数降温 |

**`src/grabber/image-grab-view.ts`** 打包并发判断扩展：

```ts
const wpLimit = policyForUrl('https://i0.wp.com/x').concurrency
const hasWp = items.some((i) => /^https?:\/\/i\d+\.wp\.com\//i.test(i.url))
// 两者都命中时取更小的那个
```

## 五、待决：rrwsh 的 SPA 通道

需要你确认是否要做。工作量估计：

| 部分 | 内容 |
|------|------|
| 新增消息 | `BD_FETCH_DOM`（请求源页提取当前 DOM 的图片 URL） |
| 导航 | `chrome.tabs.update` 到 `/2`、`/3`…，等 `status: 'complete'` + 额外延迟 |
| 提取 | content script 复用现有 `image-scanner` 逻辑 |
| 回退 | 导航失败/超时时回到原页并如实报错 |

风险：导航会**改动用户的标签页**（不能开新标签页的话）；若用户同时在看别的内容会被打断。
可以改成**临时新标签页**逐页抓，抓完关闭；但那会占用更多资源。
