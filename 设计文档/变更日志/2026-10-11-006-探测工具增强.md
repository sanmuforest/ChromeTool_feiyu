# 2026-10-11-006 探测工具增强（新站适配盲点修复）

> 版本：**v0.2.31** ｜ 类型：工具增强（用户批准解冻 `messages.ts` / `background.ts`）
> 触发：适配 `tw.8se.me` 时，现有「探测结构」输出**看不出正文容器**，用户选择「先增强探测工具」

## 一、暴露的三个盲点（8se.me 实测）

| # | 盲点 | 现象 |
|---|------|------|
| 1 | 图片样本被站点 logo 占满 | 输出「图片样本(32)」前 8 个全是 `tw.8se.me/images/sites/*.png`（导航图标），真正的图床图 `img.xchina.io/...` 一张没露 |
| 2 | 容器候选只统计「有 class 的父元素」 | 输出 `subs(16) menu(16) z-fixed-zones(12) right-5(9) …` **清一色是菜单与框架**；正文图父级若无 class 则完全不出现，无法据此写定义 |
| 3 | 分页识别只认 `?page=` / 路径尾 `/N` | 该站分页是 **`N.html`** → 输出「分页(0)：（无）」，实际有分页 |

> 该站服务端 403（Cloudflare 类反爬），无法用后台 fetch 探测，只能依赖浏览器内探测 → 工具的盲点直接卡住适配。

## 二、改动（三处）

| 文件 | 改动 |
|------|------|
| `src/lib/messages.ts` | `PageProbeResult` 新增三个**可选**字段：`imageGroups`（按 host 分组）、`pageLinks`（任意形态分页）、`lazyCount` |
| `src/background/background.ts` | `extractProbeData`（注入函数）新增：① 按图片 host 分组，每组给出数量、样本、**代表图向上 5 层的 `tag.class` 链**；② 任意形态分页链接（`\d+.html` / `?page=` / `?paged=` / `?p=` / `/page/N`，去重、上限 20）；③ `img[data-src]` 计数（判断 lazy load） |
| `src/grabber/view-buondua.ts` | 探测输出追加三段：`== 按图床分组（正文容器判据）==`、`== 疑似分页链接（任意形态）==`、`data-src（lazy）数量` |

**为何用 host 分组**：logo 与正文图几乎必然不同域（本例 `tw.8se.me` vs `img.xchina.io`），分组后正文图床自动浮出，且其父级 class 链直接给出容器写法。

**兼容性**：新字段全部可选，旧的 `imgSrcs` / `containerCandidates` / `pagination` 保留不动（不破坏既有输出习惯）。

## 四、用户实测清单

1. **重新加载插件**（chrome://extensions → 刷新，因为改了 background）
2. 打开 `https://tw.8se.me/photo/id-6ab304a17337d/2.html` 所在抓取页 → 多页图站 → 粘贴该 URL → 点「**探测结构**」
3. 预期新增三段输出，其中最关键的是：
   - `img.xchina.io ×N`（正文图床）

4. 把新输出整段贴我
