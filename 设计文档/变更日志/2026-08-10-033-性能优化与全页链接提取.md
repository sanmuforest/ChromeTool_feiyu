# 2026-08-10-033 性能优化 + 全页链接提取 + imgbb 180x180 修复（参考项目比对）

## 背景

用户反馈抓取展示"依然很卡"。比对参考项目 `e:\AI插件\浏览器插件\图片批量下载器`（DEVLOG 经验沉淀），定位差异并修复；同时按参考项目方案改造多链接提取；规避参考项目未修好的 imgbb 180x180 下载 bug。

## 一、性能优化（比对参考项目差异）

| 问题 | 参考项目做法 | 我们改动 |
|------|------------|---------|
| 网格大图卡顿 | thumb\|\|url + 小容器 + lazy + async，无 canvas 降采样 | **移除 canvas 降采样**（80 张大图 drawImage 是卡顿元凶）；网格直接 `thumbUrl \|\| url`（浏览器固定小容器自动降采样）；预览双击才加载原图 |
| 通用抓取测尺寸 | DOM 直读 naturalWidth/width 属性，零加载 | **image-scanner 改为 DOM 直读尺寸**（naturalWidth > width/height 属性）；仅缺失才懒加载测尺寸，超时 15s→5s、并发 8→4 |
| 缩略图 | 解析阶段即带 thumb | 保持（imgbb 服务器 thumb / buondua 原图页面缓存 / 通用 currentSrc） |

## 二、多链接提取（参考项目 collectLinksFromPage 方案）

- **新增 `parseAllPostLinks`**：扫描全页所有 `a[href]`，按 URL 规则过滤 buondua 帖子链接（hostname=buondua.com、路径 `/xxx-数字` 结尾、排除 tag/search/category/author/分页），标题优先取 a 的 title 属性
- **「批量抓取其他链接」改为全页扫描**（排除推荐区已收录），比原来只解析 popular-item 区块更完整
- 实测：推荐区 20 个 + 全页其他 20 个，标题/张数正确，无重复、无当前页/分页

## 三、imgbb 180x180 修复（参考项目未修好的坑，主动规避）

参考项目 DEVLOG 实测根因：**imgbb 对 `chrome.downloads` 直连 `i.ibb.co` 降级返回 180x180 缩略图**（扩展上下文 TLS 指纹差异），background fetch 能拿原图。

**我们的下载器此前正是 downloads.download 直连 i.ibb.co → 已中招。修复：**
- `downloader.ts`：下载项 URL 含 `i.ibb.co|ibb.co` 时，先 background fetch 抓原图字节（带 UA，40s 超时）→ base64 data URL → downloads.download（data URL 无服务器文件名，filename 必生效）；失败降级直连
- 重试/取消兼容（item.url 不变，重试重新抓字节）
