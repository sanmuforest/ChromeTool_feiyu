# 2026-10-15-004 8se.me 第一页地址容错（纠正上一轮的形态推断）

> 版本：**v0.2.38** ｜ 类型：Bug 修复 + 推断纠正
> 触发：用户指出「你推测错误 —— 首页没有 /3 序列页标，这个网页依然是多页的」

## 一、先承认：上一轮的推断是错的

v0.2.37 我把用户误粘的 `https://tw.8se.me/photo/id-6ab82e0dab417.html`（**不带斜杠**）当成了「单页相册形态」，并据此新增 `html-auto` 与拆分标题规则。

用户提供了该相册的**正确地址**：`https://tw.8se.me/photo/id-6ab82e0dab417/3.html` —— 它**依然是多页**，且「首页没有 `/3` 这类序列页标」，即：

- 第 1 页：`…/photo/id-6ab82e0dab417/`（目录本身，不带序号）
- 第 N 页：`…/photo/id-6ab82e0dab417/N.html`

而**前一轮**用 `1.html` 抓（`…/id-6ab304a17337d/1.html`）又确实成功过。两轮实测结论不一致 → 说明**第 1 页的地址形态在同一站内也不统一**（`1.html` 与目录本身可能都有效，或随相册而异）。

## 二、处理：不再猜，改成容错

```ts
let firstHtml: string
if (firstPageUrl !== base) {
  try {
    firstHtml = await getHtml(firstPageUrl)      // 先试 {base}1.html
  } catch (err) {
    logger.warn('buondua', '第一页地址抓取失败，回退基址重试', { site, firstPageUrl, base, error })
    firstHtml = await getHtml(base)              // 失败则退回目录本身
  }
} else {
  firstHtml = await getHtml(base)
}
```

- **两种形态都能工作**，不再依赖对站点形态的推断
- 回退时会打 `warn` 日志（`第一页地址抓取失败，回退基址重试`），下次实测即可看出该站实际属于哪种
- 仅对 `html-from-1` / `html-auto` 生效（其余分页方式本来就是抓 base，行为零变化）；失败回退不额外增加请求（只有失败时才多发一次）

## 三、保留的部分（无害）

- `html-auto` 分页方式：对正确形态（base 以 `/` 结尾）等价于 `html-from-1`；对以 `.html` 结尾的地址则直接抓该地址（比拼出必然 404 的 `…/xxx.html/1.html` 友好）
- `titleStrip` 拆两条（先去页码、再去站名）：对多页与无页码标题都适用
