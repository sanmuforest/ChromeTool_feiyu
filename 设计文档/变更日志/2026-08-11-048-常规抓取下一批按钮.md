# 2026-08-11-048 常规抓取「加载下一批」按钮修复（>200 张分批抓取）

## 问题

常规抓取（主抓取页签）页面图片超过 200 张时只抓第一批，表现为「抓取失败/不完整」。

## 根因

- 单批上限 `MAX_PER_PARSE = 200` 在 content 端（`src/content/image-scanner.ts`），分批机制本身正常（`seenUrls` 去重 + `GRAB_LOAD_MORE` 触发滚动 + 增量解析）
- **按钮从未被启用**：`image-grab-view.ts` 已渲染「加载下一批」按钮并提供 `setLoadMoreEnabled` API，但 `view-images.ts` 的 `onParseDone` 收到 `reachedLimit` 后只显示提示文字，从未调用启用方法 → 按钮永远 disabled → 用户无法加载下一批

## 本次改动

### 1. `src/grabber/image-grab-view.ts`（共享抓取视图，原 FROZEN，本次经用户确认解锁此功能）

- `setLoadMoreEnabled(enabled, loading = false)` 增加可选 `loading` 参数，区分两种状态：
  - `loading=true`：按钮禁用 + 显示「加载中…」（解析进行中）
  - `loading=false`：按钮按 enabled 显示「加载下一批」且 enabled 时可点击
- 其余逻辑零改动

### 2. `src/grabber/view-images.ts`（主抓取页签桥接层）

- `onReparse`：重新解析前按钮置「加载中…」
- `onParseBatch`：解析进行中按钮置「加载中…」
- `onParseDone`：`reachedLimit && !cancelled` → **启用按钮**（可点「加载下一批」）；否则禁用
- `onParseError`：禁用按钮

### 不改

- content 端（`image-scanner.ts`）：分批机制正常，无需改动
- 消息协议、background：`GRAB_LOAD_MORE` 路由已有
- imgbb / buondua 适配页签：传 `showLoadMore: false`，不渲染此按钮，不受影响

## 回归检查（红线 1 第 3 条）

| 相邻模块 | 检查结论 |
|---------|---------|
| imgbb 适配页（view-adapters） | 不受影响：`showLoadMore: false`，按钮不渲染；`setLoadMoreEnabled` 对 null 按钮安全返回 |
| buondua 适配页（view-buondua） | 同上 |
| content 解析器 | 未改动，`GRAB_LOAD_MORE` 语义不变 |
| 消息协议 | 未改动 |

## 验证方式

1. `npm run build` 通过（grabber.js 239.5kb）
2. 实测：打开 >200 张图片的网页 → 常规抓取 → 第一批 200 张 + 提示「已达单批上限」 → 「加载下一批」按钮亮起 → 点击 → 增量追加 → 直至全部抓完、按钮禁用
