# 2026-10-17-019 原图尺寸异步探测

> 版本：**v0.2.53** ｜ 类型：功能补全（尺寸显示）
> 触发：用户要求「我需要知道图片尺寸」；v0.2.51 网格改用预览图后，原图尺寸无法从预览得到

## 一、背景

- v0.2.51 起网格显示 `thumbUrl`（如 xchina 的 `_600x0.webp`），显示更快，但预览尺寸不等于原图尺寸
- v0.2.52 修复了「用预览尺寸回填原图尺寸」的错误 → 尺寸标签变成「尺寸未知」
- xchina 相册页 HTML 不提供原图 `width`/`height`（用户提供的标签是 `<link rel="prefetch">`，无尺寸字段），图床又对后台请求 403
- 因此只能由浏览器侧加载原图来读取真实像素

## 二、方案

只对**进入视口**的图片做异步探测：

1. `IntersectionObserver` 触发缩略图加载时，顺带调用 `enqueueSizeProbe(img, el)`
2. 用 `new Image()` 加载 `img.url`（原图），`referrerPolicy = 'no-referrer'`
3. `onload` 读取 `naturalWidth/naturalHeight` → 回填 `img.width/height`、`sizeStatus='ok'`，刷新尺寸角标与尺寸筛选
4. `onerror` 或超时（15s）→ 保持「尺寸未知」，该 URL 不再重试
5. 并发上限 **2**，避免重新引入 v0.2.51 之前的解码压力；失败不重试，避免 403 图床反复请求

## 三、实现位置

`src/grabber/image-grab-view.ts`：

- 新增 `probeQueue` / `probedUrls` / `probeActive` / `restoreTagMap` / `thumbImgMap`
- `enqueueSizeProbe()` + `runProbeQueue()`
- `thumbObserver` 回调中触发探测（仅视口内的图）
- 探测成功后通过 `restoreTagMap` 找到对应卡片的 `restoreSizeTag()` 更新角标

## 四、验证

- `npm run typecheck`：通过
- `npm run build`：通过，当前版本 **v0.2.53**

## 五、用户实测清单

1. `chrome://extensions` 刷新扩展
2. 抓一个 xchina 相册，滚动网格
3. 预期：每张图进入视口后，尺寸角标从「尺寸未知」陆续变成真实像素（如 `1200×1600`）
4. 若滚动后仍全部「尺寸未知」→ 说明原图在扩展页也被图床 403，这条路不通，需要回退为「显示预览尺寸并标注」或保持未知；贴日志确认

## 六、风险

- 每张可见图会额外加载一次原图（并发 2），比纯预览略增带宽/解码；不可见图不探测
- 原图加载失败（403/CORS）时探测无效，保持未知
- 探测会缓存失败 URL（`probedUrls`），同一相册不会反复请求
