# 2026-10-10-004 修复：多页抓取看不到图片尺寸（重试角标滞留 + 尺寸补齐）

> 版本：**v0.2.19** ｜ 类型：回归修复 + 小增强
> 触发：用户验证破图修复通过后反馈「多页抓取现在看不到图片尺寸了」

## 根因（两个叠加）

### 1. 回归（v0.2.17 引入）

v0.2.16/0.2.17 加入重试与兜底流程后，**改写了角标文案**（`重试中 N/2…`、`兜底加载中…`），但**没有绑定 `load` 事件**：

- 首次加载失败 → 角标变「重试中 1/2…」
- 重试**成功** → 没有任何代码把角标恢复 → **角标永久停在「重试中 1/2…」**，尺寸再也看不到

多页图站抓 kaizty 时限流较多、走重试的图多，所以这个现象在「多页抓取」场景尤其明显。

### 2. 既有事实：多页站本来就不测量尺寸

- 主抓取页由内容脚本扫描，会用 `new Image()` 实测尺寸 → `sizeStatus: 'ok'` → 显示 `1920×2880`
- 多页图站走后台 fetch 解析，`BuonduaImage` **只有 `url` 与 `filename`**（无宽高）
  → `toGrabbed()` 里 `sizeStatus` 恒为 `'unknown'` → 角标一直显示「尺寸未知」

因此用户"看不到尺寸"里，**一半是我的回归，一半是这条长期存在的路径差异**。

## 改动（`image-grab-view.ts`）

绑定 `load` 事件，一次解决两件事：

```ts
thumb.addEventListener('load', () => {
  // ① 补齐尺寸：后台未提供宽高时（多页站），直接读取实际加载到的像素尺寸（零额外请求）
  if ((!img.width || !img.height) && thumb.naturalWidth > 0 && thumb.naturalHeight > 0) {
    img.width = thumb.naturalWidth
    img.height = thumb.naturalHeight
    img.sizeStatus = 'ok'
    updateStats()
  }
  // ② 恢复角标：无论首次/错峰/自动重试/手动重试成功，角标都回到「尺寸」状态
  restoreSizeTag()
})
```

**收益**：多页图站现在也能显示真实尺寸（不再恒为「尺寸未知」），统计同步修正。

## 已知限制

- **小图过滤（`<100×100` 剔除）不追溯**：多页站的尺寸是在图片**加载后**才补齐的，而小图过滤/去重在渲染时已执行 → 补齐的尺寸不会让"已显示的小图"被自动剔除。需要重新渲染（切换筛选或重抓）才参与过滤。这是"零额外请求"方案的代价，暂不引入后台测量以免拖慢抓取
- 若某张图（含兜底 blob）始终无法加载，尺寸仍显示「尺寸未知」——因为没有可用的解码结果
