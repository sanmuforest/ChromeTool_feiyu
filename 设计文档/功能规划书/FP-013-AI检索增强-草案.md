> 目标：从「适配器模式」转向「AI 检索代理模式」——AI 自主完成策略生成、广域检索、质量验证、参考图比对，搜索空间不再被已知站点列表锁死，扩展能力从「写解析器」变为「AI 加搜索词」

## 〇、合规红线（最高优先，凌驾于功能）

1. **严格排除未成年人内容**：AI 策略提示词硬性约束 + 域名黑名单 + 页面标题/元数据特征过滤；命中立即停止该路并提示
2. 仅限**合法成人内容**（成年人、公开、非非法范畴）；插件个人使用，manifest 描述与 UI 不出现色情词汇（避免上架/分发限制）
3. 目标站点自身合规性由用户判断，插件仅做公开内容抓取

## 一、用户痛点申明（2026-08-16 原话归纳）

1. 现有聚合搜索流程能跑通但**不智能**，且**常遇 bug**（反爬/站点改版/通道脆弱，维护成本高）
2. 项目最终目的是**抓取高质量图片**，但当前搜索**手动**：手动添加已知目标网站、手动关键词提取、手动结果筛选、手动处理 bug；**缺乏扩展能力**——无法搜索已知范围外的图片，扩展站点需手写解析器
3. 插件开发虽用 AI 完成，但**检索流水线本身是传统工作流**，没有结合 AI 的广域资源检索能力

## 二、根因分析

现有架构为**适配器模式**（`GALLERY_SITES` 配置驱动，每站配 searchUrl + 专用解析器）：

- 搜索空间 = 已知站点列表，AI 未参与「去哪里找」→ 搜不到列表外的图
- 每站一个解析器，站点改版/反爬 = 解析器失效 = bug，维护量随站点数线性增长

结论：**AI 只用在开发时，没有用在运行时**。必须换架构，而非继续加适配器。

## 三、架构转变：AI 检索代理模式

```
传统：已知站点列表 → 每站专用解析器 → 直连抓取 → 人眼筛选
新：  AI 策略 → 搜索引擎广域入口 → 通用 SERP 解析 → 通用页面抽取 → AI 质量验证 → 抓取下载
```

### 四大支柱

| 支柱 | 设计 | 解决痛点 |
|------|------|---------|
| ① AI 策略生成 | 关键词 → 搜索变体(5~8) × 域名候选(AI 知识图站 + 搜索中自动发现) + 排除词；文本模型 1~3 次调用；内置**成人写真站生态提示词** | 关键词提取自动化；广域扩展 |
| ② 搜索引擎 = 索引层 | Bing/Google 搜「关键词 + 域名候选」（**成人题材必须关 SafeSearch**），SERP 即相册页 URL 列表；不直连各图站；反爬面从 N 站点收敛到 2 搜索引擎 | bug 收敛；搜索空间广域化 |
| ③ 通用页面抽取 | og:image / 大图启发式(最大 img、宽>800) / JSON-LD；**抽不出时交 AI 看 HTML 片段兜底** | 免适配扩展（新站 = AI 加搜索词） |
| ④ AI 质量验证 | 视觉 API（**须选无审核/宽松审核端点**）：清晰度/水印/主题匹配打分排序；参考图比对(可选) | 结果筛选自动化；高质量目标 |

### 通道分层（主/辅）

- **主链路（广域）**：Bing SERP（网页 + 图片）+ Google SERP（网页 + 图片 tbm）→ 通用抽取 → AI 验证
- **增强通道（可选勾选）**：现有 5 站适配器保留不动（gallery-sites.ts 原样，本就是成人写真站），作为已知高质量站点的快速直连
- ~~免费图库 API（Unsplash/Pexels）~~：**作废**——两家平台明令禁止成人内容，本题材返回空/违规

## 四、题材敏感性技术修正（v3 新增）

| 环节 | 问题 | 修正 |
|------|------|------|
| 图库 API | Pexels/Unsplash 禁成人内容 | **移除该源** |
| Bing 搜索 | SafeSearch 默认过滤成人结果 | 查询参数 `adlt=off`（关闭 SafeSearch） |
| Google 搜索 | SafeSearch 默认过滤 | 网页 `safe=off`；图片 `tbm=isch&safe=off` |

| 词扩展 LLM | 国内文本模型对成人搜索词生成受限/弱化 | 词扩展端点与视觉同配置（默认海外/宽松端点）；提示词内置成人写真站生态特征（WordPress 相册站、标题 NNNphotos、域名模式），并允许用户手动补充变体兜底 |
| 合规 | 未成年人内容红线 | 见「〇、合规红线」：策略硬约束 + 域名黑名单 + 特征过滤 |

## 五、技术设计要点

### 搜索渠道

| 渠道 | 方式 | 说明 |
|------|------|------|
| Bing 网页/图片搜索 | 后台 fetch 或 content 注入解析 | 反爬比 Google 宽松；**必须 `adlt=off`**；图片结果自带缩略图可当封面 |
| Google 网页搜索 | content script 注入解析（复用 FP-012 通道经验） | **`safe=off`**；sorry 页检测 + 手动验证重试 |
| Google 图片 tbm=isch | content script 注入解析 | **`safe=off`**；封面 + 原图链接；反爬同 Google |

### 域名候选生成（AI 策略核心）

```
输入关键词 → AI 输出：
  - 搜索变体列表（中英/同义/风格词，如 amateur/glamour/softcore 等题材词族）
  - 域名候选列表（成人写真相册站生态：WordPress 相册站、NNNphotos 标题特征、常见域名模式）
  - 排除词列表（含未成年相关词 → 硬性丢弃并告警）
→ 每个「变体 × 域名」生成一条 SERP 查询：关键词 + 域名 或 site: 限定
→ 首轮结果中发现的陌生域名自动记入候选（AI 判断是否写真相册站：URL 特征 + 标题 + og:image 存在性）
→ 下一轮用新域名再搜（广域扩张，受会话预算约束）
```

### 通用页面抽取（无解析器）

优先级：`og:image` / `twitter:image` → JSON-LD ImageObject → 大图启发式（文档中最大 `<img>`、自然宽>800、非图标/背景）→ **AI 兜底**：截取 HTML 片段（img/srcset/背景图特征）交文本模型提取 URL 模式，正则回填。

### 质量验证（视觉 API）

- 配置：OpenAI 兼容端点 + 模型 + safety settings（默认预设 **Gemini Flash 免费档**，SEXUALLY_EXPLICIT 等调至 BLOCK_NONE；自定义端点可填任何兼容服务）
- 输入：每相册封面 + 前 N 张（一次调用多图）
- 输出：主题匹配度 / 清晰度 / 水印 / 综合分 → 排序
- 无密钥自动降级 L0 纯规则（分辨率/锐度 Laplacian/水印启发式/pHash 去重）

### 成本控制（金字塔）

L0 规则先挡 90% 噪音 → 视觉只评幸存者；`ai_cache` 缓存打分；会话调用预算上限（默认 100 次，可配）超限转纯规则；SERP 请求间隔防反爬。

## 九、UI 设计（AI 检索场景，多页图站第 5 子标签）

- **输入区**：关键词、参考图（URL/文件）、目标数量、质量阈值、通道勾选（广域 Bing/Google/增强站点）

## 十一、风险与对策

| 风险 | 对策 |
|------|------|
| 搜索引擎反爬/封号 | 请求间隔；Bing 优先；Google sorry 检测（FP-012 经验）+ 手动验证重试；成人题材查询属搜索引擎允许范围（非非法内容） |

| FROZEN 红区误动 | 独立类型文件；消息登记流程；模块边界先行更新 |
| AI 域名候选质量差 | 域名黑名单 + 页面特征校验 + 用户可手动增删候选 |
| 未成年内容误入 | 合规红线：策略硬约束 + 域名黑名单 + 标题/元数据特征过滤 + 命中即停并告警 |
