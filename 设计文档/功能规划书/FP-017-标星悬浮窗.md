# FP-017 标星悬浮窗（imgbb 页面内评星）

> 立项：2026-09-29（用户指示）｜状态：已实施（编码 + 类型检查通过，待用户实测）
> 关联：FP-015 手动星级评定（复用同一套 `starRating` 数据与消息）

## 1. 需求（用户指示）

「可以在（相册）用户的相册页面加一个标星级的小悬浮窗」——即在 imgbb 页面上直接给当前页面对应的用户评星，不必先回到抓取页。

用户确认的四项决策：

1. 标星对象 = **相册所属用户**（复用 FP-015 的用户星级，不新建相册级数据）
2. 覆盖页面 = **`*.imgbb.com` 用户页 + `ibb.co/album/*` 相册详情页**
3. 注入方式 = **按需授权 + 动态注册**（不写 manifest 静态 `content_scripts`）
4. 库外用户 = **标星时自动入库**（入度 0，来源标记 `star`）

## 2. 方案

### 2.1 注入（权限最小化）

- manifest 的 `optional_host_permissions` 新增 `*://*.imgbb.com/*`、`*://ibb.co/*`（**可选**权限，默认不授予）
- 用户在「抓取页 → 站点适配 → ②区 → 标星悬浮窗 → 启用」点击时：先 `chrome.permissions.request`（手势内）→ 授权后发 `STAR_OVERLAY_SET { enabled: true }`
- background 用 `chrome.scripting.registerContentScripts`（id `star-overlay`，`js: ['js/star-overlay.js']`，`runAt: document_idle`，`persistAcrossSessions: true`）注册；关闭时 `unregisterContentScripts`
- SW 启动时校验：开关为开但权限失效 → 自动置为关闭并记日志
- 已有页面需刷新一次才会出现浮窗（动态注册不回溯注入已打开页面）

### 2.2 页面识别（决定给谁标星）

| 页面 | 用户名来源 |
|------|-----------|
| `https://{username}.imgbb.com/...`（用户主页 / 关注墙 / 粉丝墙） | 子域名直接取，零请求 |
| `https://ibb.co/album/{id}` | 复用已有消息 `IMG_RESOLVE_USER`（后台解析相册属主） |

识别不到用户名的页面（如 `ibb.co/<id>` 单图页、非 imgbb 域）不显示浮窗。

### 2.3 浮窗 UI

- Shadow DOM + `CSSStyleSheet`（CSSOM 不受页面 CSP 限制），样式与页面完全隔离
- 内容：`@用户名`、5 颗星（`☆`/`★`，点第 N 颗 = N 星，再点同一颗取消）、入度 / 相册数 / 「未入库（标星自动入库）」
- 交互：标题栏拖拽移动、`–` 折叠、`×` 关闭；位置与折叠状态记忆在 storage `star_overlay_pos`
- 写入：`IMG_DB_SET_STAR { username, stars, autoCreate: true }` → 返回 `starInfo` 即时刷新

### 2.4 消息协议

| type | 说明 |
|------|------|
| `IMG_DB_GET_STAR` | 单人星级与库内状态（只读单条，避免拉全库排行） |
| `IMG_DB_SET_STAR` | 已有（FP-015），新增 `autoCreate` 字段支持库外用户自动入库 |
| `STAR_OVERLAY_SET` | 启用/关闭悬浮窗（注册/注销 content script） |
| `STAR_OVERLAY_STATUS` | 查询 `{ enabled, registered }` |

### 2.5 数据层

- `producer-db.ts` 新增 `ensureEntry(db, username, source)`（库外建条目）与 `starInfo(db, username)`（单条查询）
- 库外用户由此入库：`inDegree: 0`、`sources: ['star']`、`albumsChecked` 未设置（会在④/⑤区显示为「未确认」，属预期）

## 3. 权限影响（红线 1）

| 项 | 变更 |
|----|------|
| manifest `permissions` | **不变**（仍是 storage / downloads / activeTab / scripting） |
| manifest `optional_host_permissions` | 新增两个 imgbb 域条目（可选，不授予即无效） |
| 运行时权限 | 仅当用户点「启用」并同意授权后才持有 imgbb 域权限；点「关闭」后自动注销注入 |
| 静态 content_scripts | **不新增**（模块边界禁止事项第 3 条已更新为"必须动态注册 + 用户授权"） |

## 4. 验证方式（用户实测）

1. `npm run build` → 重载扩展 → 抓取页右下角核对 **v0.2.3**
2. 站点适配 → ②区「标星悬浮窗」点 **启用** → Chrome 弹出 imgbb 域权限提示 → 允许
3. 打开 `https://{某用户}.imgbb.com/` → 页面右下角出现浮窗，显示 `@用户名` 与当前星级
4. 点第 3 颗星 → 变 `★★★☆☆`，状态显示「已标 3 星」；回到抓取页「读取」→ 入度 Top 中该用户星级同步、得分 Top 重排
5. 打开 `https://ibb.co/album/xxxx` → 浮窗显示**相册属主**用户名（后台解析）
6. 拖拽浮窗到别处、折叠 → 刷新页面 → 位置与折叠状态保持
7. 未入库用户在浮窗里标星 → 提示「未入库（标星自动入库）」→ 标星后抓取页可见该用户（入度 0）
8. 回抓取页点「关闭」→ 刷新 imgbb 页面不再出现浮窗
9. 日志（debug）应见：`[background/star] 标星悬浮窗已注册/已注销`、`[background/score] 手动星级已设置 { autoCreate: true }`

## 5. 已知限制

- 单图页 `ibb.co/<id>` 不显示浮窗（避免每页一次属主解析请求）
- 已打开的 imgbb 页面需刷新一次才出现浮窗
- 浮窗只做用户星级；相册级星级未实现（如需要另立 FP，涉及新数据结构）
- 库外自动入库的用户在标签云/检索中表现为「未确认相册」（需跑一次「确认评分」补相册数）
