# FP-020 交互修复：空白区滚轮 + 批量结果卡片关闭

> 立项日期：2026-10-07 ｜ 状态：**已交付** ｜ 版本 v0.2.7
> 需求方：用户（多页图站实测反馈）

## 1. 需求

1. **鼠标停在两侧空白区域滚动滚轮时，应当驱动整体最外层滚动条**（当前无反应）
2. **批量抓取结果卡片加一个关闭按钮**：每个相册结果卡片右上角 ×，点掉只移除该卡片

## 2. 根因（问题 1）

- 抓取页 `.app` 是 `max-width: 1200px; margin: 0 auto; height: 100vh`，屏幕两侧留白属于 `body`
- `.main` 与 `.panel` 都是 `overflow: hidden`，真正的滚动发生在**各面板内部容器**（图片网格区、链接列表、批量结果区等）
- 鼠标停在留白上时，浏览器向上找不到可滚动祖先 → 滚轮事件无处生效

## 3. 方案

### 3.1 空白区滚轮转发（`src/grabber/wheel-forward.ts`，新增）

- 监听全局 `wheel`：若事件目标**不在任何可滚动祖先内**，则把滚动量转发给「当前激活页签内可滚动余量最大的可见容器」
- 滚动量单位换算：`deltaMode=1`（行）×16、`deltaMode=2`（页）×容器高度、`deltaMode=0`（像素）原值
- 性能：候选容器查找结果缓存 300ms，避免高频遍历 DOM
- **守卫（不接管的情况）**：
  - 交互控件（`SELECT` / `INPUT` / `TEXTAREA`）内的滚轮 —— 保留下拉选项的原生滚轮选择
  - `.preview-layer`（大图预览浮层）内的滚轮 —— 保留预览缩放
  - 事件已被处理（`defaultPrevented`）或目标已在可滚动容器内 —— 交还浏览器默认行为

### 3.2 批量结果卡片关闭按钮（`view-buondua.ts` + `grabber.css`）

- 卡片头部 `.bd-batch-head` 追加 `×` 按钮（`.bd-batch-close`），悬停变红
- 点击后：清理该卡片的 grab view（`clear()` 释放图片引用）、删除三张索引表（视图 / 文件夹名 / 图片名前缀）中的对应项、移除 DOM 节点
- **只影响本卡片**：不影响其它卡片，也不取消后台抓取任务（后台按 index 推送，已移除的卡片不再有接收方，消息被忽略）
- 覆盖两个批量入口：推荐/其他链接、聚合搜索
