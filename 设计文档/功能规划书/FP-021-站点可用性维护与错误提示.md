# FP-021 站点可用性维护与错误提示可读化

> 立项日期：2026-10-07 ｜ 状态：**已交付** ｜ 版本 v0.2.8
> 触发：用户实测聚合搜索失败，日志定位出三个站点的真实失败原因（域名失效 / 域名被占用 / 反爬）

## 1. 背景与定位结论

用户提供的 v0.2.7 聚合搜索日志（query「丝袜」）+ 外部可达性验证：

| 站点 | 日志现象 | 根因（已验证） |
|------|---------|---------------|
| buondua | `count 40, pages 2` | 正常（证明站内搜索通道本身可用） |
| cangcuc | `TypeError: Failed to fetch` | **域名失效**：`getaddrinfo ENOTFOUND cangcuc.com`（DNS 已不存在），无新域名线索 |
| jrants | `HTTP 403` | **站点反爬**：搜索页与首页均拒绝后台直接访问（外部 fetch 亦失败） |
| rrwsh | `count 0, pages 1`（无报错） | **域名被他人站占用且模板改版**：`rrwsh.uuss.uk/search/...` 返回 200，但页面内文章链接全部指向 `iozl.uuss.uk`（站名「豆豆」，WordPress tob-10 主题、视频站），旧解析器依赖的 `li.wp-block-post` 结构已不存在 |

三个失败均为站点侧变化，非本轮重构回归。

## 2. 用户决策

1. **rrwsh / cangcuc**：从聚合搜索默认勾选移除（仍保留在站点列表中，需要时可手动勾选）
2. **jrants**：改走 Google 站内搜索（sitesearch）通道，与 hitxhot / kaizty 一致
3. **错误提示可读化**：界面不再直接抛 `TypeError: Failed to fetch` / `HTTP 403（url）`

## 3. 改动

| 文件 | 改动 |
|------|------|
| `src/sites/defs/rrwsh.ts` | `defaultChecked: false` + 记录域名被占用的实测结论 |
| `src/sites/defs/cangcuc.ts` | `defaultChecked: false` + 记录 DNS 失效结论 |
| `src/sites/defs/jrants.ts` | `channels: ['google']`、`defaultChecked: false`、`search` 改 `google-sitesearch`、`linkParser` 改 `google-serp` |
| `src/grabber/view-buondua.ts` | Google 组加入 `jrants`；默认勾选收敛为 `buondua`；站点列表分组同步调整 |
| `src/background/buondua-service.ts` | 新增 `humanizeFetchError()`，搜索失败时界面显示可读原因，日志同时保留原始错误与提示 |

**说明**：站点定义（`channels` / `defaultChecked`）与 UI 硬编码数组**同时**更新，避免将来把分组改由定义派生（FP-018 阶段 1B）时默认勾选被"复活"。

## 4. 错误提示映射

| 原始错误 | 界面提示 |
|---------|---------|
| `TypeError: Failed to fetch` / `NetworkError` / `ERR_*` | 站点不可达（域名可能已变更或网络受限） |
| `HTTP 403` | 被站点拒绝（反爬拦截，可稍后重试） |
| `HTTP 404` | 页面不存在（链接可能已失效） |
| `HTTP 5xx` | 站点服务器错误 |
| 超时 / `AbortError` | 请求超时 |

## 5. 已知限制

- **jrants 结果过滤较弱**：其相册位于根路径（如 `/20260101.html`），无固定路径前缀，Google 结果无法用 `searchAlbumPath` 过滤 → 结果中可能混入分类 / 标签页。需实测反馈后再决定是否新增 `searchAlbumPattern`（正则过滤）字段
- **rrwsh / cangcuc 未恢复**：前者等于换了一个视频站（适配意义有限），后者需用户提供新域名；两者正是 FP-018 阶段 1B「界面改域名 + 域名自愈」的目标场景
