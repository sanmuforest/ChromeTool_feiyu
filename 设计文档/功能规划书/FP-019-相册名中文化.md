# FP-019 相册名中文化

> 立项日期：2026-10-07 ｜ 状态：**已交付（范围 = 多页图站）** ｜ 版本 v0.2.6
> 需求方：用户（多页图站抓取后，文件夹名与图片名前缀为日文/英文/越南文，不便管理）

## 1. 需求

多页图站（buondua / rrwsh / hitxhot / kaizty / jrants / pixibb / cangcuc / phimvuspot / ilovexs）的相册标题多为原文（日文、英文、越南文），希望：

1. **文件夹名**用翻译后的中文
2. **图片文件名**也用中文

## 2. 已确认的方案（用户选择）

| 决策点 | 结论 |
|--------|------|
| 翻译能力来源 | Google 翻译免费端点（`translate.googleapis.com`，非官方接口，无需 key） |
| 命名规则 | 文件夹名 + 图片名前缀都用译文；**翻译失败自动回退原文**；提供开关（默认开） |
| 覆盖范围 | **本阶段仅多页图站相册**（主抓取页与 imgbb 暂不动，改动最小） |

## 3. 关键设计

### 3.1 同源命名：一个改动点同时生效

图片名前缀 = `getAlbumName()` 的返回值（由共享抓取视图拼接为 `001-{相册名}.jpg`），与文件夹名同源于「相册标题」。因此在标题进入命名链路前翻译一次，**文件夹名与图片名同时中文化**。

### 3.2 翻译层（`src/lib/translate.ts`）

- 端点：`GET https://translate.googleapis.com/translate_a/single?client=gtx&sl=auto&tl=zh-CN&dt=t&q=`
- 缓存：storage `translate_cache`（按原文缓存，上限 500 条，超出丢较早一半），同一相册不重复请求
- 开关：storage `translate_enabled`（默认开）
- **回退优先**：未授权 / 超时（8s）/ 非 200 / 响应结构异常 / 译文为空 → 一律返回原文，且不影响抓取主流程（异常只记 warn 日志）
- 已是中文（含 CJK 字符）的标题直接跳过，省请求
- 译文清洗：去包裹引号与多余空白、替换文件名非法字符 `\ / : * ? " < > |`、限长 120

### 3.3 接入点（仅 `src/grabber/view-buondua.ts`）

| 场景 | 位置 |
|------|------|
| 单相册「抓取全部子页」 | 拿到后台返回的页面标题后翻译，再套用原命名规则（`buildBuonduaFolderName` + `extractBuonduaAlbumShortName`） |
| 批量抓取（推荐 / 其他链接） | 「抓取选中」时逐个翻译选中项（显示 `翻译相册名 n/N…` 进度），再创建结果卡片 |
| 聚合搜索批量抓取 | 同上 |
| 开关 UI | 多页图站页签名右侧复选框「相册名译成中文」，状态持久化 |

**结构零变化**：命名规则本身（站点路由、短名清洗、分页/张数标记剥离）完全沿用，只是把输入标题换成译文。

## 4. 权限与隐私

- 请求依赖已授权的 `optional_host_permissions: <all_urls>`（多页图站抓取本身已要求该授权）；**未授权时自动跳过翻译并回退原文**，不新增任何权限
- 隐私提示：**相册标题会发送给 Google 翻译服务**；不希望的场景可关闭开关（关闭后不发任何请求）

## 5. 风险

| 风险 | 处理 |
|------|------|
| 非官方端点限流 / 接口变动 / 被墙 | 全部失败路径回退原文 + warn 日志；缓存减少请求量 |
| 译文过长影响文件名 | 清洗 + 限长 120 字符 |
| 站点标题含页数/标签标记 | 翻译后仍走原清理规则（`extractBuonduaAlbumShortName`） |

## 6. 不在本阶段范围

- 主抓取页（普通网页）与 imgbb 场景的中文化（后续如需，改为在 background 会话标题生成处接入）
- 翻译服务可选（百度 / 有道 / 自建）与人工词典
- 中英对照命名（`原文（译文）`）

## 7. 验收

1. 多页图站单相册抓取 → 文件夹名与图片名前缀为中文
2. 批量抓取 → 每个相册卡片标题、文件夹名、图片名前缀均为中文，且进度提示出现
3. 关闭开关 → 命名回到原文
4. 断网或未授权 → 命名回退原文，抓取仍正常完成
