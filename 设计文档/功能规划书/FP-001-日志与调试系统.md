# FP-001 日志与调试系统（项目地基）

- 状态：**DONE（2024-08-10）**
- 关联文档：`设计文档/模块边界.md`、`AGENTS.md`（AI 宪法）

## 背景与动机

前项目踩坑三连：无宪法导致模块冲突、AI 自主完善导致功能受损、自动测试卡死推进。
本项目立宪（三条红线），并以「用户手动实测 + 插件内日志定位」为唯一主测试手段。
本 Feature 是宪法红线 3 的落地载体：**日志系统 + popup 日志面板**。

## 需求

1. 全插件统一日志入口：等级（debug/info/warn/error）、模块标签、时间戳、附加数据
2. 日志持久化（环形缓冲 ≤500 条），popup 可查看
3. popup 日志面板：刷新 / 清空 / 复制 / 导出 / 等级切换 / 等级过滤
4. 面板显示插件版本号（防旧版本误判）
5. 权限最小化：仅 `storage`，不声明任何 content_scripts

## 架构决策（ADR-001）

| 决策点 | 选择 | 理由 |
|--------|------|------|
| 日志写入者 | 唯一写入者 = background，popup/content 走消息转发 | 避免多上下文并发写 storage 竞态覆盖 |
| 存储 | chrome.storage.local 环形缓冲 | SW 无状态，日志跨会话保留 |
| 构建 | esbuild 多入口 IIFE + 静态复制 | 全 IIFE 兼容 MV3（popup/background/content 均可） |
| 版本展示 | popup 读 manifest.version | 防「改了没生效/加载旧版」误判 |

## 验证方式

手动加载 `dist/`，打开 popup：能看到 background 初始化日志、popup 打开日志；
切换 debug 等级后刷新、清空、复制、导出均可用。用户贴日志给 pi 即可定位问题。
