# FP-002 网页图片抓取器（Image Grabber）

- 状态：**DONE（2026-08-10 用户验收通过，功能完结）**
- 关联：`设计文档/模块边界.md`、`AGENTS.md`（AI 宪法）
- 用户确认事项：无 popup 悬浮窗（全 tab 内运行）/ 文件夹名含网站信息+时间戳 / 可引入 JSZip / 失败重试1次+保留重下 / 图片下方显示尺寸

## 一、背景与动机

用户需要一款网页图片抓取插件。核心使用感：**在想要抓取的网页点击图标 → 紧靠该网页右边新建插件抓取页 tab → 在抓取页内完成解析、筛选、预览、下载全流程**。不同网页可激活多个互不干扰的抓取页。项目地基（FP-001 日志系统）已冻结，本次在其上构建第一个真实功能。

### 默认方案（顺带确认）

1. **解析范围**：img[src]、img[srcset]、懒加载属性、picture>source；**CSS 背景图暂不做**（代价高，收益低，后续按需加）
2. **尺寸获取**：解析时对每个图片 URL 真实加载一次（new Image）获取实际宽高，供筛选与展示。**会真实请求图片流量**，失败项标记「尺寸未知」
3. **图片下载**：原图 URL 直下，不做格式转换

## 三、核心交互流程

```
用户打开网页 A → 点击插件图标
  → background 在 A 的右侧创建抓取页 tab（grabber.html?srcTabId=A）
  → 抓取页自动向 A 注入 content script → 开始解析
  → content 分批扫描图片 + 获取尺寸 → 实时上报 → 抓取页展示（进度条推进）
  → 用户在抓取页：尺寸筛选 / 划过预览选择 / 全选
  → 点击下载：队列下载到「标题+域名+时间戳」文件夹（进度条+取消）
  → 或点击打包下载：JSZip 打包选中图片 → 下载 zip
  → 打开下载文件夹：跳转浏览器下载目录定位文件
```

中断语义（R10）：解析取消/失败 → content 停止扫描但**提交已收集批次**，抓取页展示已有结果；下载取消 → 已完成的保留，队列剩余标记取消。

## 五、技术方案

### 权限（最小化）

| 权限 | 用途 |
|------|------|
| `storage`（已有） | 日志、会话映射 |
| `downloads` | 下载到子文件夹、打开下载文件夹、取消、进度监听 |
| `activeTab` | 用户点击图标后动态注入 content script，**不申请 `<all_urls>`** |

### 注入方式

- action 点击（无 popup）→ `chrome.action.onClicked` → `chrome.scripting.executeScript` 动态注入 `js/content.js`
- 内容脚本不在 manifest 静态声明（权限最小化）

### 消息协议（新增，扩展 `src/lib/messages.ts`）

| type | 方向 | 说明 |
|------|------|------|
| `GRAB_CREATE_SESSION` | grabber→background | 注册会话（srcTabId→grabTabId） |
| `GRAB_PARSE_START` | grabber→background→content | 开始解析 |
| `GRAB_PARSE_BATCH` | content→background→grabber | 解析批次（图片列表+进度） |
| `GRAB_PARSE_DONE` / `GRAB_PARSE_CANCEL` | content | 解析结束/取消 |
| `GRAB_PARSE_CANCEL_REQ` | grabber→background→content | 请求取消解析 |
| `GRAB_DOWNLOAD_START` | grabber→background | 开始下载队列（含文件夹名） |
| `GRAB_DOWNLOAD_CANCEL` | grabber→background | 取消下载队列 |
| `GRAB_DOWNLOAD_OPEN_FOLDER` | grabber→background | 打开下载文件夹 |
| `LOG_*`（已有） | 复用 | 日志链路不变 |

路由规则：content 的批次消息经 background 按 srcTabId 路由到对应 grabber tab。

### 存储 schema（新增键）

| 键 | 格式 | owner | 说明 |
|----|------|-------|------|
| `grab_sessions` | `Record<srcTabId, {grabTabId, title, host, folderName, status}>` | grabber 模块 | 会话映射（background 内存为主，storage 仅兜底） |

解析结果（图片列表）存 **grabber 页内存**（量大，不进 storage；页面关闭即弃，重新解析）。

### 下载实现

- 队列管理：background 内串行/并发(≤3)下载，`chrome.downloads.download({ url, filename: 文件夹/序号-原名 })`
- 进度：`chrome.downloads.onChanged` 统计 + 队列计数，上报 grabber 页
- 失败：自动重试 1 次，仍失败保留列表（标记「失败」，可手动重下）
- 打包：JSZip 收集选中图片 blob → 生成 zip → downloads.download

#### 技术决策 ADR-002：为什么不直接保存已加载的图片（用户疑问）

- 解析时 `new Image()` 加载图片仅为**获取尺寸**（并顺带进浏览器缓存），不保存数据
- **不能**用 fetch 先拿 blob 再保存：① content script 的 fetch 受 CORS 限制（网页图片几乎全跨域，拿不到数据）；② no-cors 返回 opaque 响应无数据；③ storage 容量 ~10MB 装不下；④ IndexedDB 仍绕不过 CORS
- `chrome.downloads.download({ url })` 不受 CORS 限制，是跨域图片下载的唯一可靠通道
- 缓存收益：解析时已加载的图大概率命中浏览器磁盘缓存，`downloads.download` 秒下，体验接近「保存已拿到的图」

### 构建链

- esbuild 新增入口：`js/grabber.js`（grabber.ts）、`js/content.js`（content.ts，IIFE，经 getURL 注入）
- popup.html/css/ts **废弃删除**，日志面板逻辑抽为 `src/lib/log-panel.ts` 供 grabber 日志页签复用
- 新增依赖：`jszip`
