# 插件产品设计方法论

通用产品设计 skill，适用于本项目（浏览器插件）的所有设计工作。

## 核心价值循环（插件示例）

```
用户痛点 → 插件功能 → 页面/后台交互 → 解决痛点 → 用户留存/口碑
                ↑                                    ↓
                └──────── 反馈迭代（数据与评论驱动）──────┘
```

## 价值评估框架

- **痛点是否真实**：用户遇到什么麻烦？现在怎么绕过去？
- **解决是否轻量**：安装即用，还是需要配置和学习？
- **侵入是否可控**：是否尊重用户浏览体验，权限是否最小化？
- **数据是否闭环**：插件如何证明自己有用（统计、反馈）？

## 设计文档模板

新功能设计文档（放 `设计文档/`）应包含：

```markdown
# 功能名
## 一句话定位
## 用户故事与场景（谁在用、什么时候用）
## 功能清单（入口 / 交互 / 输出）
## 权限与数据（manifest 权限、存储结构）
## 边界情况（无网络/页面不支持/权限被拒）
## 与其他模块的关系
## 实现要点（给开发）
```

## MVP 原则

- **最小闭环**：一个核心场景完整跑通（注入→取数→展示→设置）优先于 10 个半成品功能
- 验证核心价值后再加功能（设置项 → 主题 → 导出 → 同步 → 社交）

## 评审标准

- 核心价值是否闭环？每个功能是否服务核心场景？
- 配置是否数据驱动（存储 schema 可扩展）？
- 是否违背"最小权限 + 不打扰"的插件底线？
