# ⚖️ 设计评审与架构决策（pi 版）

**一句话：** 评审设计文档，确认后再进入开发。

## 激活方式

```
帮我评审 设计文档/ 下的设计：权限是否最小、数据流是否清晰、有没有 MV3 坑
```

## 涉及资源

- **Agent**: `extension-specialist`（架构与合规把关）
- **Skill**: `extension-review`（评审清单）
- **Skill**: `extension-security`（权限与合规）

## 产出

- 评审结论（阻断项 / 建议项）
- 架构决策记录（ADR：数据流、权限、存储方案）
- 修改后的设计文档定稿

## 协作协议

设计阶段结束前必须有明确结论；阻断项清零后才允许进入编码阶段。
